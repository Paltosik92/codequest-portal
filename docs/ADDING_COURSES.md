# Добавление направления

Создавать новую страницу `.astro` не нужно. Главная и динамические маршруты читают один каталог.

## 1. Добавьте метаданные программы

В `src/data/source-inventory.json` добавьте ключ со стабильным латинским идентификатором. Поле `source` — путь относительно общей папки учебных материалов. Публикуются только названия, без содержимого файлов.

```json
{
  "new-course": {
    "source": "Папка_исходного_курса",
    "lessons": []
  }
}
```

Пример схематический: добавьте объект к существующим, сохранив остальные записи. Если программа ещё не определена, оставьте массив пустым. Не заполняйте его выдуманными занятиями.

Для известных реальных файлов запись имеет вид:

```json
{ "number": 1, "title": "Точное название из методички", "file": "Исходное имя.md" }
```

## 2. Добавьте объект в definitions

В `src/data/courses.ts` добавьте объект с обязательными полями `Omit<Course, 'materialsPath' | 'plannedLessons'>`:

```typescript
{
  id: 'new-course',
  title: 'Новое направление',
  academicTitle: 'Название дисциплины',
  category: 'Категория',
  description: 'Коротко о результате.',
  intro: 'Описание по реальным материалам.',
  image: null,
  cover: 'desktop',
  accent: '#7cdbb7',
  technologies: ['C#'],
  order: 6,
  status: 'draft',
  project: 'Название проекта',
  goals: ['Ожидаемый учебный результат'],
}
```

`materialsPath` и `plannedLessons` подставляются из метаданных по `id`. При отсутствии записи каталог завершится с понятной ошибкой. Пока `status: 'draft'`, карточка и страница не генерируются. Для открытия направления поменяйте статус на `published`.

Используйте один из существующих типов обложек (`arena`, `mobile`, `guild`, `desktop`, `web`) либо своё проверенное изображение. Для изображения положите файл в `public/covers/` и задайте `image: 'covers/new-course.webp'`. Не добавляйте BASE_PATH в конфигурацию: шаблон сделает это сам. Не копируйте всю папку `img` ради одной обложки.

Для скриншотов интерфейса или постеров, которые нужно показать целиком, добавьте `imageFit: 'contain'`, как у Desktop Forge. По умолчанию используется `cover`: изображение заполняет область обложки с возможной обрезкой краёв. Настройка применяется одновременно к карточке и странице курса.

Идентификатор должен быть уникальным, содержать строчные латинские буквы, цифры и дефисы. `order` управляет порядком карточек. Контраст текста задаётся общей темой; не используйте цвет обложки в качестве цвета основного текста.

## 3. Добавьте модули, если они реально есть

```typescript
modules: [{ title: 'Название блока из утверждённого плана', from: 1, to: 5 }];
```

Без `modules` отображается единая программа. Диапазоны должны покрывать номера курса без пересечений. Добавляя занятия за пределами диапазонов, обновляйте модули.

## 4. Подключите выбранные работы

Пока допустимо опубликовать только программу. Для настоящих методичек см. [CONTENT_IMPORT.md](CONTENT_IMPORT.md). Создайте Markdown с `status: published`, правильными `courseId`, `number`, `order` и уникальным `slug`. Страница и ссылка в программе появятся при сборке автоматически.

## 5. Проверьте

```powershell
npm run check
npm run build
npm run verify:links
```

Откройте направление на desktop и mobile, проверьте обе темы. Повторите сборку с `$env:BASE_PATH='/test-portal'`, затем удалите переменную `Remove-Item Env:BASE_PATH` и соберите обычную версию. Браузерная проверка описана в README.

Если нужен снимок исходных файлов нового курса, расширьте список `sources` в `scripts/source-inventory.mjs`. Этот служебный сценарий не является автоматическим импортёром и не нужен для добавления курса вручную. Не запускайте пересоздание первоначального снимка перед проверкой сохранности оригиналов.
