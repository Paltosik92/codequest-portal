# Устройство CodeQuest

## Принцип работы

Все страницы создаются Astro на этапе сборки. На сервере не исполняются код приложения, запросы к БД или обработчики API. Клиентский TypeScript отвечает только за тему, фильтр направлений, копирование кода, подсветку пункта оглавления и просмотр изображения.

Содержимое доступно без JavaScript: программы, Markdown, ссылки и листинги остаются обычным HTML. Кнопки, которым нужен JavaScript, добавляются или открываются после инициализации. Светлая тема сохраняется в `localStorage`; при недоступности хранилища работает в текущей вкладке. Начальная тема всегда тёмная, если читатель ранее не выбрал светлую.

## Данные курсов

Оформление задаётся общими `global.css`, `prose.css` и `pixel.css`. Пиксельная тема использует одни компоненты для всех курсов и обеих цветовых тем. Текст методичек и код сохраняют системные шрифты увеличенного размера. `PixelWorld.astro` — статичная авторская SVG-сцена на целочисленной сетке. Локальный заголовочный шрифт собирается без зависимостей сценарием `scripts/build-pixel-font.mjs` из собственной сетки 5×7; готовый TTF хранится в `src/assets/fonts/`. Vite добавляет хэш и базовый путь к CSS-адресу и preload шрифта.

`Course` определён в `src/data/courses.ts`: идентификатор, название и академическое название, категория, описания, `image`, тип CSS-обложки, цвет, технологии, порядок, `status`, `materialsPath`, цели, результат, необязательная заметка об источнике, модули и названия занятий.

Необязательный массив `downloads` задаёт название, описание, путь и при необходимости `buttonLabel` для скачиваемых ресурсов. Общий шаблон отображает ссылки на странице курса. У Neon Arena подключён ZIP исходных спрайтов и звуков, у Mobile Lab — Markdown-инструкция настройки Android SDK, у MediaHub — три архива изображений, данных и шаблонов PixelPort. Они учитываются в манифестах и проверке SHA-256. Дополнительные студенческие Markdown-документы перечисляются в `attachments` явного списка импорта; сборка не читает оригиналы. ZIP собираются отдельно сценарием PowerShell по `resourceBundles` с проверкой SHA-256 каждого вложения.

`image: null` включает CSS-обложку; у всех пяти стартовых курсов уже выбраны локальные изображения. Необязательное `imageFit: 'contain'` показывает изображение целиком: у Desktop Forge это окно каталога из работы №9. По умолчанию остаётся `cover`. Обложка одна и та же в каталоге и на странице курса. Цвет применяется к акцентам карточки; интерфейс и контрастные цвета текста остаются частью общей темы. Модули отображаются только там, где они обнаружены в плане: сейчас это пять блоков PixelPort. Для остальных направлений показывается плоская программа без выдуманных семестров.

`source-inventory.json` содержит путь исходной папки, номер, заголовок и имя файла. Он не нужен для чтения оригиналов при сборке: собирать сайт можно без доступа к учебному архиву. `materialsPath` — справочная связь для будущего импортёра, не публичная ссылка и не команда копирования.

## Коллекция Markdown

Используется Content Layer API: `defineCollection`, `glob`, схема `z` и `render()` из Astro. Конфигурация находится в `src/content.config.ts`. Сборка читает только `src/content/lessons/**/*.md`. Ни одна внешняя папка автоматически не подключена.

Записи с `status: draft` исключены из маршрутов и навигации. Для реальной работы обязательны курс и положительный номер. Ссылка на неопубликованный/неизвестный курс, повтор slug или повтор номера внутри курса останавливают сборку. Нейтральная демонстрация помечена `demo: true`, `status: draft` и сохранена только как исходный шаблон; публичная страница и ссылки на неё убраны.

Карточки курса сопоставляют коллекцию с программой по `courseId` и `number`. Пока запись не опубликована, строка программы показывает «Материал ещё не подключён» без ссылки, ведущей в пустоту. При добавлении опубликованной записи соответствующая строка становится ссылкой. Новые номера вне первоначального снимка также включаются в список. Для курса с модулями расширьте диапазоны модулей при расширении программы.

## Маршруты и BASE_PATH

| Сущность    | Маршрут относительно базы |
| ----------- | ------------------------- |
| Главная     | `/`                       |
| Направление | `/courses/{id}/`          |
| Работа      | `/practice/{slug}/`       |
| Поиск       | `/search/`                |
| Прогресс    | `/progress/`              |
| Индекс поиска | `/search-index.json`    |
| Офлайн-библиотека | `/offline/`          |
| Сведения об офлайн-копиях | `/offline-index.json` |
| Состав одной копии | `/offline-packages/{slug}.json` |

Slug может включать сегмент курса, например `neon-arena/first-scene`. Путь не вычисляется из русского имени исходного файла: стабильный slug сохраняется даже после переименования методички.

В шаблонах все адреса строятся через `src/lib/paths.ts`. Astro добавляет базу для скомпилированных CSS/JS. Для Markdown плагин `remark-base-links.mjs` добавляет `BASE_PATH` к URL, начинающимся с `/`, включая reference-ссылки и `src` поддержанных одиночных HTML-изображений; `#якоря` остаются локальными. Импортёр заранее нормализует эти `img` и сохраняет размеры/alt. Прочий HTML с URL требует отдельной поддержки и останавливает импорт. Кодовые блоки с примерами HTML не обрабатываются как разметка страницы.

## Длинные методички

У колонки текста ограничена ширина, оглавление закреплено на desktop и становится обычным раскрываемым блоком на mobile. Таблицы и листинги прокручиваются внутри, не расширяя страницу. Код не переносится принудительно. Подсветку Shiki генерирует при сборке для двух тем.

Кнопка копирования использует текст `code`, сохраняя пробелы и переносы. При недоступности Clipboard API код выделяется для ручного копирования. Иллюстрации загружаются лениво, увеличиваются по Enter/клику; Escape закрывает окно и возвращает фокус. Галочки Markdown статичны и не изображают сохранение прогресса.

`code-windows.css` оформляет листинги как пиксельные окна. Bash и другие оболочки получают чёрный фон с зелёным акцентом в обеих темах сайта; для подсветки внутри них используется тёмная палитра Shiki. Остальные языки и обычный текст следуют выбранной теме. `lesson.ts` добавляет название языка, тип фрагмента и декоративный значок в отдельную шапку; содержимое `<code>` не изменяется, `$` из шапки не попадает в буфер обмена. Поддельные имена файлов и рабочие пути не добавляются.

Соседние работы вычисляются среди опубликованных записей одного курса, сортируются по `order`. Демо отделено от реальных работ. Если соседней страницы нет, отображается текстовое неактивное состояние.

## Поиск и личный прогресс

`src/lib/learning-catalog.ts` формирует метаданные только опубликованных студенческих работ. Каталог встраивается в общий макет как JSON с экранированием `<`; новые дисциплины и работы подключаются автоматически. Номера и количество берутся из коллекции.

Статический endpoint `src/pages/search-index.json.ts` при сборке разбирает Markdown через unified/remark и сохраняет текст, включая листинги. HTML-комментарии, черновики, README и техническая документация в поиск не попадают. `/search/` загружает индекс только при первом запросе. Поиск не различает регистр и `е`/`ё`, требует присутствия всех введённых слов, учитывает выбранный курс и ставит совпадения в заголовках выше. Выдача загружается порциями по 20; запрос и фильтр сохраняются в URL. Отрывки и заголовки вставляются через `textContent`, без выполнения разметки из кода.

`src/scripts/learning.ts` и `learning-store.ts` хранят локальное состояние в `localStorage` под ключом `codequest-learning-v1`: явная отметка выполнения, время изменения, раздел и позиция чтения каждой работы. Скролл сохраняется с ограничением частоты и при уходе со страницы. Только ссылка «Продолжить» с `?resume=1` восстанавливает позицию; обычные переходы и ссылки на заголовки сохраняют привычное поведение. Изменения синхронизируются между вкладками; при возврате кнопкой браузера интерфейс обновляется.

Это личные отметки, а не подтверждение сдачи преподавателю. Очистка данных браузера удаляет прогресс; между устройствами автоматической синхронизации нет. `/progress/` позволяет скачать JSON и объединить его с данными другого браузера по времени изменения записи. Импорт проверяет версию, типы, границы чисел и известные slug; неизвестные работы пропускаются, повреждённые данные не применяются. Максимальный файл — 1 МБ. При запрете localStorage доступна работа в памяти и экспорт прямо на текущей странице.

### Настройки чтения и закладки

`ReadingTools.astro` добавляет в общий шаблон методички две раскрывающиеся панели: настройки и закладки текущей работы. `reading-tools.ts` управляет интерфейсом через общий store, а `reading.css` применяет размер текста 20/22/24/26 px, обычную/узкую/широкую колонку и обычный/плотный/свободный межстрочный интервал. Значения по умолчанию сохраняют прежнее оформление, включая мобильный интервал; сброс настроек не затрагивает выполнение и закладки. Настройки действуют только на чтение методичек, исходный текст и копирование кода не изменяются.

У заголовков h2/h3 с идентификатором появляются доступные с клавиатуры кнопки ☆/★ с `aria-pressed`. Закладка хранит slug работы, якорь, заголовок, время изменения и признак удаления. Ссылки формируются по текущему каталогу с учётом BASE_PATH; якорь кодируется как URL, заголовок вставляется через `textContent`. В методичке показываются её закладки, на `/progress/` — общий список с курсом и номером работы. Удаление доступно из обоих списков и повторным нажатием ★. После удаления записи из списка фокус остаётся в его панели.

Формат экспорта теперь `version: 2`: добавлены `bookmarks` и `reading`. Исторический ключ `codequest-learning-v1` сохранён намеренно, чтобы существующее хранилище автоматически читалось и мигрировало при записи. Импорт версии 1 сохраняет прежние отметки и позицию; при объединении с версией 2 не стирает закладки и настройки. Изменения закладок объединяются по времени, включая записи об удалении: старая резервная копия не восстанавливает более недавно удалённую закладку. Настройки имеют отдельное время изменения. Рост закладок ограничен размером экспортируемого файла с запасом для новых записей прогресса. Новые версии формата потребуют явной миграции.

`npm run test:reading` проверяет миграцию, настройки, закладки, экспорт/импорт обеих версий, две вкладки, мобильные экраны и доступность. Сценарий использует тот же механизм проверки реальной статической сборки и поддерживает `BASE_PATH`/`OUTPUT_DIR`.

`npm run test:learning` проверяет эти сценарии на готовом `dist/` в Chrome, включая экспорт настоящего файла, импорт, две вкладки, запрет хранилища, мобильную вёрстку и axe. Поддерживаются `BASE_PATH` и `OUTPUT_DIR` для проверки сборки в подпапке. HTTP-ответы в этом сценарии берутся из реальных файлов сборки через `localArtifactRoutes`.

## Карта курса

`CourseMap.astro` получает те же занятия и настоящие модули, что и обычный список. Для каждой работы создаётся узел с номером, полным названием и ссылкой; неопубликованные работы не получают ссылок. `course-map.ts` раскладывает маршрут змейкой в 1/2/3 колонки по доступной ширине и рисует пунктирные соединения SVG. DOM и порядок клавиатурной навигации сохраняют последовательность занятий. Из `learning.ts` передаётся существующий прогресс: завершённые работы отмечаются, текущей становится последняя посещённая незавершённая либо первая незавершённая. Ссылка на ранее посещённую текущую работу поддерживает восстановление чтения.

Без JavaScript остаётся обычный список. С JavaScript по умолчанию показана карта, есть явные кнопки переключения с `aria-pressed`; выбор запоминается отдельно для BASE_PATH и применяется ко всем курсам. Схема прогресса версии 2 не менялась. Значки «Офлайн» читают фактические готовые копии из Cache Storage, а не имитируют сохранение.

## Офлайн-копии

Интеграция `scripts/offline-packages.mjs` запускается после штатного копирования public (на Windows — после `windowsPublicAssets`). Она читает публичный каталог из сгенерированной главной и HTML каждой опубликованной работы. Пакет включает HTML работы, HTML её курса, `/offline/`, favicon, локальные сборочные CSS/JS/шрифты из `_astro/` и встроенные изображения этих страниц. Markdown-архив, ZIP-загрузки и внешние ресурсы автоматически не добавляются. Реальные файлы не дублируются в dist: пакет — JSON со списком URL, размерами и SHA-256. После изменения курса или материалов состав и версия пересчитываются обычной сборкой. Сейчас генерируются 93 пакета; демонстрация и черновики исключены каталогом.

`offline.ts` показывает размер до начала загрузки. Service Worker устанавливается только после явного нажатия сохранения, обычное чтение не запускает установку. `offline-storage.ts` по очереди получает ресурсы, проверяет длину и SHA-256, записывает их в отдельный Cache Storage и лишь в конце добавляет маркер готовности. При отмене, сетевой ошибке, несовпадении хэша или нехватке места незавершённый кеш удаляется; прежняя готовая копия остаётся. Устаревшие незавершённые кеши старше часа очищаются при чтении списка. Копии независимы: удаление одной не удаляет общие файлы другой. При наличии Web Locks изменения одной работы блокируются между вкладками; BroadcastChannel обновляет список во вкладках. Сохранённые файлы не включаются в экспорт JSON прогресса.

`scripts/offline-worker.js` копируется в `sw.js` относительно базы сайта. Его scope и префикс Cache Storage привязаны к BASE_PATH. Worker не предзагружает архив и не кеширует посещения автоматически. Сначала запрашивается свежая сеть; при недоступности используются только завершённые пакеты. Если запрошенная работа не сохранена, показывается сохранённая офлайн-библиотека. В корне домена незнакомые маршруты других приложений не подменяются библиотекой. При обновлении сайта старые копии сохраняются до явного успешного обновления пользователем; фоновое обновление не удаляет их. Прогресс, закладки и настройки остаются в прежнем localStorage независимо от удаления файлов.

Офлайн-функция доступна в production/preview по HTTPS либо localhost. Dev-сервер не формирует пакеты. Наличие Cache Storage, Service Worker и безопасного контекста проверяется; отказ браузера показывается сообщением. Браузер управляет квотой и может очистить хранилище; копии не являются резервной копией исходных материалов. Справочные API: [Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers), [Cache](https://developer.mozilla.org/en-US/docs/Web/API/Cache), [Storage](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API).

`npm run test:offline` проверяет все пакеты по реальным файлам и SHA-256, затем использует настоящий Service Worker Chrome. HTTP-ответы отдаются из dist, после сохранения сеть отключается и HTTP-кеш очищается. Проверяются иллюстрации, перезагрузка, копирование кода, карта, fallback, обновление/отмена/ошибка и независимое удаление копий. Поддерживаются BASE_PATH и OUTPUT_DIR. Снимки и машинные отчёты исключены из Git.

## Проверки

`astro check` проверяет Astro/TypeScript, `astro build` создаёт статический результат. `verify-links.mjs` проходит HTML, внутренние ресурсы, якоря и CSS URL. `browser-qa.mjs` проверяет интерактивность, адаптивность, обе темы и доступность с axe. Внешние ссылки автоматически не запрашиваются.

`source-inventory.mjs` при первоначальном запуске сделал SHA-256 снимок всех файлов в пяти исходных направлениях. `verify:sources` сравнивает его с текущим состоянием. Снимок локальный и исключён из Git; он не нужен на GitHub Actions и не переносит файлы на портал.

## Выборочный импорт

`scripts/import-course.mjs` читает явный список из `content-map/{courseId}.json`. В него включены только студенческие методички. Markdown AST определяет диапазоны ссылок, комментариев и заголовков; точечные правки сохраняют исходное форматирование и содержимое листингов. Файлы изображений копируются без преобразования, только по действительным ссылкам и явно выбранной обложке.

Манифест хранит хэши источников и копий. Повторный импорт останавливается при ручном изменении выходного файла. `verify:source` проверяет файлы манифеста; `test:guild` — все 24 страницы в браузере. Сборка сайта не запускает импорт и не зависит от наличия внешних исходных папок.

На Windows включён `preserveSymlinks` Vite для корректной загрузки пакетов. Копирование `public/` выполняется интеграцией `windows-public-assets.mjs` без операции восстановления timestamps, которая в ограниченных средах Windows может получать EPERM на async realpath каталогов. Источники не изменяются, символические ссылки в `public/` отклоняются, пересечения с генерируемыми файлами останавливают сборку. На Linux/GitHub Actions используется штатное копирование Astro.
