# Подключение Markdown

В портал подключены все пять стартовых направлений: 24 студенческие работы «Гильдии героев», 13 работ Neon Arena, 14 работ Mobile Lab, 30 работ PixelPort (MediaHub) и 12 работ Desktop Forge (Labs_Avalonia). Всего 93 реальные работы. Решения преподавателя и служебные документы не включаются в публичный контент.

## Реализованный импорт «Гильдии героев»

- `content-map/guild-of-heroes.json` — явный список разрешённых `.md`, стабильные адреса `guild-of-heroes/lab-01` … `lab-24`, метаданные и выбранный постер.
- `scripts/import-course.mjs` — разбор через Markdown AST с GFM, точечные правки исходных диапазонов; кодовые блоки не пересобираются и сравниваются до/после.
- `content-map/guild-of-heroes.manifest.json` — пути, SHA-256 исходников и копий, ресурсы, статистика и исправленные ссылки.
- `src/content/lessons/guild-of-heroes/` — подключённые работы.
- `public/materials/guild-of-heroes/img/` — только изображения, на которые ссылаются работы, и постер `start-poster-01-team_v3.webp`.

```powershell
npm run import:guild -- --dry-run
npm run import:guild -- --write
npm run check
npm run build
npm run verify:links
```

Без `--write` импортёр только проверяет план и сообщает результат. Он не изменяет исходные методички. Повторный запуск останавливается, если опубликованная копия была изменена вручную после последнего импорта; сначала перенесите нужные изменения в источник либо сохраните и согласуйте локальную правку.

Опубликованные Markdown-копии записываются с окончаниями строк LF до расчёта SHA-256. `.gitattributes` сохраняет LF для методичек и JSON-манифестов при checkout на Windows и Linux, чтобы `npm run verify:source` получал одинаковые контрольные суммы локально и в GitHub Actions. Хэши исходных методичек по-прежнему считаются по исходным байтам.

Удаляется первая H1, которую заменяет заголовок шаблона. Последующие H1 становятся H2, их подразделы смещаются на один уровень; код с Markdown-заголовками внутри листингов не затрагивается. Удаляются HTML-комментарии, включая промпты COMIC. Встроенные учебные самопроверки в `<details>` сохраняются: они являются частью студенческой методички, в отличие от отдельных эталонов решений преподавателя.

Относительные изображения, reference-ссылки и переходы между выбранными `.md` переписываются на адреса портала без жёсткого BASE_PATH. В работе №23 для `img/lab23/04-dam-threshold-v2` найден единственный существующий файл `.webp`, расширение добавлено только в копии. Иные неразрешимые ссылки останавливают импорт. Неподдержанный HTML с URL, скриптами или обработчиками событий также останавливает импорт; молчаливого переноса таких блоков нет.

Перенесено 287 файлов изображений с обложкой, сохранены 867 листингов. Копии содержат около 83 МБ иллюстраций; полное дерево исходного `img/` и неиспользуемые варианты изображений не копировались. Источники проверяются на выход за границы курса и символьные ссылки/junction. Манифест позволяет проверять сохранность и повторять импорт без потери ручных изменений.

Для обычной сборки сайта исходные учебные папки не требуются: загрузчик коллекции читает только материалы, уже перенесённые внутрь портала.

## Импорт Neon Arena

В студенческой выдаче сохранены 3254 блока кода и 19 таблиц, перенесены 203 используемые иллюстрации. Удалены 116 служебных комментариев, включая GENERATED_IMAGE с промптами. В заголовках работ №2 и №4 типы `<PlayerProjectile>` и `<T>` экранированы, чтобы браузер показывал их как текст C#, а не воспринимал как HTML. Это не меняет содержимое листингов.

C#-код студенческих разделов и учебные задания не переписывались. В работах №4, 6, 9–13 исключён точный раздел «Что нужно подготовить преподавателю до занятия» вместе с его подразделами и 25 служебными листингами. Разделы сдачи студентом сохранены. Правило `omitSections` применяется при каждом импорте; исходные методички не изменяются.

### Игровые ресурсы

Для студентов подготовлен архив из **33 ресурсов**: по одной выбранной версии каждого спрайта и звукового файла. Изображения преобразованы в настоящий PNG с именами из методичек. Для анимаций выбраны исправленные листы с кадрами 96×96: player_idle/move из v3, player_death и анимации врагов из v2; фон арены из v3. Исходные WebP и старые варианты остаются в учебной папке.

Явное соответствие источника, имени внутри ZIP, номера работы и размеров хранится в `content-map/neon-arena.resources.json`. В работах №1 и №5 компонент `LessonResources` показывает таблицу «файл архива → папка проекта» и размеры. Архив не содержит готового проекта или решений.

Для пересборки нужен локальный ImageMagick (он не требуется ни студентам для распаковки, ни GitHub Actions):

```powershell
# Если magick не добавлен в PATH, укажи путь к установленному исполняемому файлу:
# $env:MAGICK_PATH = 'C:/Program Files/ImageMagick-7.1.2-Q16-HDRI/magick.exe'
npm run package:neon
npm run import:neon -- --write
npm run verify:source
npm run build
npm run verify:publication
```

Упаковщик проверяет сигнатуру PNG, размеры, сетку кадров, содержимое ZIP и CRC. Он не меняет размеры изображений и не редактирует исходники; в репозиторий входит готовый ZIP. Для замены выбранной версии сначала проверь изображение и размеры, затем обнови явное соответствие.

## Импорт MediaHub / PixelPort

Источник — `Осуществление_интеграции_программных_модулей_2027`. Явный список — `content-map/mediahub.json`; манифест — `content-map/mediahub.manifest.json`. Команды: `npm run import:mediahub -- --dry-run` и `npm run import:mediahub -- --write`. Все 30 работ доступны по адресам `/practice/mediahub/lab-01/` … `/practice/mediahub/lab-30/`. Номера `№01` в исходных H1 корректно сопоставляются с числом `1` в конфигурации. Разделение на пять блоков взято из плана, а не придумано при импорте.

Сохранены все 510 блоков кода и 69 таблиц, перенесены 89 изображений с обложкой (83 378 066 байт) и четыре дополнительных документа. Обложка — `img/hero.png`. Изображения методичек находятся в `assets/screenshots/`, `assets/tickets/` и `assets/diagrams/`; сохраняются PNG, JPG, SVG и GIF без конвертации. Импортёр обрабатывает одиночные HTML-теги `<img>` с URL, сохраняя `alt` и размеры; плагин Markdown добавляет базовый путь и к этим изображениям. Портреты Ани и Гоши остаются небольшими декоративными изображениями, а мобильный макет можно увеличить. HTML-таблица со сравнением TypeScript и JSON в работе №13 сохраняется вместе с вложенными листингами. Листинги HTML из учебных примеров не переписываются.

Поле `attachments` содержит четыре явно выбранных студенческих файла: памятку общего компьютера, настройку Node.js, шаблон функции и карточку демо-дня. Они копируются без изменений в `public/materials/mediahub/` с исходными путями; ссылки из работ на памятку и настройку ведут к этим файлам. Шаблон функции предназначен для заполнения студентом: комментарии-подсказки и место под собственный макет в нём сохраняются. Это отдельные скачиваемые документы, не дополнительные практические работы.

### Ресурсы для проекта PixelPort

В `resourceBundles` перечислен каждый разрешённый файл. Архивы разделены на три части:

| Архив                       | Состав                                                                                  | Файлов |
| --------------------------- | --------------------------------------------------------------------------------------- | -----: |
| `pixelport-images.zip`      | `img/`: обложки, логотипы, баннеры, аватары, состояния; без `img/screens/`              |     26 |

Оба архива изображений распаковываются в одну папку проекта: структура `img/` объединяется. Материалы из третьего архива используются по указаниям конкретной работы. В архивы не входят проекты-решения, промпты генерации, планы, технические манифесты и обзорные коллажи.

Для обновления архивов в PowerShell из папки портала:

```powershell
./scripts/package-course-resources.ps1
npm run import:mediahub -- --write
npm run verify:source
```

Сценарий упаковки читает `resourceBundles` из `content-map/mediahub.json`, сохраняет исходные имена и байты, затем открывает каждый ZIP и сравнивает SHA-256 всех вложенных файлов с источниками. Рекурсивного включения неописанных файлов нет. Он нужен только при обновлении ресурсов; для сборки сайта PowerShell не требуется. Можно передать другой явный список параметром `-Map`. Контрольные суммы готовых ZIP записываются импортёром и проверяются `verify:source`.

Исходные Markdown и изображения остаются неизменными.

## Уже подготовленный контракт

Разместите отобранную копию студенческой работы в `src/content/lessons/{course-id}/`. Пример служебной шапки — не учебное содержание:

```yaml
---
title: 'Точное название из исходника'
description: 'Короткое описание результата реальной работы.'
slug: neon-arena/first-scene
courseId: neon-arena
number: 1
order: 10
status: draft
demo: false
---
```

Не добавляйте ещё один H1 в тело: крупный заголовок создаёт шаблон из `title`. Основные разделы начинаются с H2, подразделы — с H3. Порядок `order` управляет навигацией соседних опубликованных работ, `number` связывает запись со строкой программы. Публикация требует `status: published`. `module` можно сохранить как строковую метку; группировка программы задаётся в конфигурации курса.

## Целевая организация ресурсов

```text
src/content/lessons/neon-arena/first-scene.md
public/materials/neon-arena/img/lab1/example.webp
```

Для первого практического импорта достаточно явно заменить ссылку:

```markdown
![Точное описание схемы](/materials/neon-arena/img/lab1/example.webp)
```

Плагин добавит BASE_PATH на этапе сборки. Не вписывайте `/codequest-portal` прямо в текст. Ссылка на работу должна вести на стабильный адрес портала, например `/practice/neon-arena/first-scene/`, а не на физический `.md`. Локальные ссылки `#раздел` остаются прежними, если заголовки сохранены.

Исходные изображения можно оставить без конвертации: PNG, JPG/JPEG, WebP и SVG поддерживаются браузером. Сохраняйте размер, пропорции и подписи. Конвертация в WebP — отдельная задача, с визуальной проверкой схем и читаемости текста. Учебные ассеты, которые студент должен скачать в проект, следует отделять от иллюстраций самой методички.

## Архитектура будущего импортёра

Рекомендуемый вход — **явный список разрешённых студенческих файлов**, а не glob на весь учебный архив. Например `content-map.json` со связью исходного имени, courseId, номера и постоянного slug. Путь `materialsPath` из каталога поможет найти папку, но сам по себе не разрешает массовую публикацию.

Будущий импорт должен проходить следующие этапы:

1. Прочитать allowlist и проверить, что каждый путь расположен внутри выбранного исходного курса. Отклонить `..`, символьные ссылки за пределы источника и конфликты slug.
2. Проверить назначение каждого файла. Решения, эталоны, ответы, отчёты преподавателя, паспорт персонажей, промпты генерации и внутренние заметки исключаются. Проверка по названию — дополнительный фильтр, основное решение принимает автор по allowlist.
3. Выполнить dry run: показать выбранные `.md`, изображения, ресурсы и будущие адреса. Ничего не записывать в источники.
4. Разобрать Markdown через AST, сохранив таблицы, блоки кода, задания, языки листингов и ссылки. Регулярных выражений для полноценной обработки недостаточно.
5. Нормализовать первую H1 и добавить frontmatter, не меняя заголовки разделов без необходимости. Технические комментарии для преподавателя и блоки промптов исключить из публикуемой копии после просмотра.
6. Разобрать image/link/definition nodes. Для `img/labN/...` разрешить путь относительно исходной методички; для ссылок с пробелами учитывать Markdown `<...>`/URL encoding. Копировать только реально используемые ресурсы, сохраняя дерево внутри `public/materials/{courseId}/`.
7. Разобрать HTML-блоки отдельным HTML AST: `src`, `href`, `srcset`, `<figure>`, `<picture>`. Существующий remark-плагин работает с Markdown nodes и не переписывает raw HTML.
8. Для каждого `.md`-перехода найти запись в карте. Заменить на маршрут портала и сохранить fragment. Если целевая работа не выбрана, показать это в отчёте и оставить исходную запись черновиком до исправления; не публиковать битую ссылку.
9. URL вида `https://`, `mailto:` и внутристранничные якоря обработать отдельно. Не скачивать внешние картинки автоматически и не переносить файл за пределами allowlist без проверки назначения.
10. Записать только подготовленные копии в портал. Оригиналы читать без правки, перемещения и удаления. Сформировать manifest с хэшами исходника и производных файлов для повторного импорта.
11. Прогнать сборку, проверку ссылок с обеими базами, браузерную QA и выборочную проверку длинных C#-листингов/иллюстраций.

При одинаковом относительном пути изображений в разных курсах namespace `{courseId}` предотвращает конфликт. Повторяющиеся ресурсы внутри курса можно дедуплицировать по хэшу, если сохранена карта переписанных ссылок. При конфликте разных байтов по одному пути импорт должен остановиться, а не молча перезаписать файл.

## Безопасность учебного содержимого

В коллекцию попадает доверенный, просмотренный автором Markdown. Не подключайте произвольные загруженные пользователями файлы. HTML в Markdown разрешает богатую разметку, поэтому при дальнейшем внешнем импорте требуется очистка скриптов, обработчиков событий и небезопасных URL.

Решения преподавателя следует хранить вне публичного репозитория. Статический сайт не может скрыть файл авторизацией: любой файл в `public/` доступен по прямому адресу после публикации, даже без ссылки в интерфейсе.

## Минимальная проверка одной подключаемой работы

- Совпадают номер, название, порядок и курс.
- Текст принадлежит студентам, не содержит эталона решения.
- Заголовки строят понятное оглавление, код сохраняет отступы.
- Каждое изображение существует; нет абсолютных путей `C:\...` или `F:\...`.
- Все `.md`-переходы заменены на маршруты; ссылки с `#fragment` проверены.
- Нет prompts/скрытых преподавательских комментариев в конечном HTML.
- `npm run check`, `npm run build`, `npm run verify:links` проходят для `/` и `/test-portal`.
- Работа читается на телефоне, обе темы сохраняют контраст.

Подключайте материалы по одному курсу или небольшими просмотренными партиями. Сначала можно оставить `draft`, проверить содержимое локально, затем осознанно переключить на `published`.

## Правила студенческой публикации после аудита

- `omitSections` удаляет только раздел с точным совпадением заголовка и его потомков до следующего заголовка того же или старшего уровня. Список удалений записывается в манифест.
- `studentReplacements` задаёт номер работы и точную пару `from/to`. Импорт останавливается, если найдено не ровно одно совпадение. В MediaHub №6 редакторская отсылка заменена командой `magick input.png -resize "543x>" -quality 82 output.webp` и сохранён предложенный в самой работе веб-инструмент.
- `--prune` удаляет только прежние ресурсы данного курса, отсутствующие в новом манифесте, если их хэш не изменился. Исходные учебные папки не затрагиваются.
- Демонстрационный шаблон и четыре изображения находятся в `test/fixtures/`, вне Content Collection и `public/`. Для новой реальной работы используй схему коллекции и выставляй `status: draft` до проверки; демонстрацию не публикуй.
- `npm run verify:publication` проверяет точный состав `public/` по манифестам, отсутствие служебных разделов и демо-файлов в сборке, а также канонический ZIP Neon Arena. Новые публичные ресурсы должны входить в явный манифест импорта. При добавлении доменного `CNAME` отдельно дополни разрешённый список в этой проверке.
