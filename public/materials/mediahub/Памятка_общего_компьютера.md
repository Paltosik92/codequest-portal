# Памятка: работа за общим компьютером

За твоим компьютером занимаются студенты ещё двух групп. Пять правил, чтобы твой проект оставался твоим, а чужой — чужим.

## 1. Своя папка

Работай в папке с кодом группы и фамилией, например `pixelport-is31-ivanov`. Если находишь в рабочей папке чужой проект, не трогай его и не удаляй, просто создай свой рядом.

## 2. Свой Git и свой GitHub

Перед первым коммитом на паре проверь, от чьего имени ты коммитишь и куда отправляешь:

```bash
git config user.name
git config user.email
git remote -v
```

Если имя чужое, задай своё **только для своего проекта** (без `--global`):

```bash
git config user.name "Иван Иванов"
git config user.email "ivanov@example.com"
```

Если при `git push` браузер или Git предлагает войти в чужой аккаунт GitHub, позови преподавателя. Имя автора коммита и аккаунт, через который идёт отправка, — разные вещи. Смена `user.name` не меняет аккаунт.

## 3. Уходя — выйди

В конце пары выйди из GitHub в браузере, если входил. Закрой VS Code и браузер. Чужие вкладки и чужие проекты не закрывай.

## 4. Данные браузера общие

Всё, что сайт сохраняет в браузере (с №11 — корзина и «Желаемое»), видят все, кто откроет тот же адрес в том же профиле браузера. Поэтому в коде курса ключи хранения содержат твой код студента. Это разделение учебных данных, а не защита.

## 5. Пароли не попадают в Git

С блока 3 у тебя появится пароль от своей учебной базы данных. Он хранится только в локальном файле настроек, который указан в `.gitignore`. Если пароль случайно попал в коммит, скажи преподавателю: пароль просто заменят, ничего страшного.
