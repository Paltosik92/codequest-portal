## Цель работы

![Елена предлагает научить героев действовать самим](/materials/guild-of-heroes/img/lab2/00_lab2_start.webp)

В предыдущей практической работе мы создали первый класс `Hero` и научились создавать несколько независимых объектов.

Сейчас герой умеет **хранить данные**, но почти всё управление этими данными выполняется снаружи.

В этой работе необходимо:

- понять разницу между данными объекта и его поведением;
- создать методы экземпляра;
- передавать значения в методы через параметры;
- изменять состояние объекта из его собственных методов;
- использовать методы с возвращаемым значением;
- разобраться с `void` и `return`;
- увидеть, что один и тот же метод работает с состоянием именно того объекта, у которого он был вызван;
- уменьшить количество прямой работы с полями из `Program.cs`.

**Результат занятия:** программа поручает герою получить урон, восстановить здоровье и накопить опыт; герой сам выполняет эти действия по правилам. Он также отвечает, жив ли он, и возвращает информацию о себе.

### 2. Зачем переносить правила в объект

Следующие фрагменты объясняют проблему, **добавлять их в `Program.cs` не нужно**. В рабочем файле пока остаются три строки создания героев.

Представим, что Ярослав получил 25 единиц урона.

Сейчас мы можем написать в `Program.cs`:

```csharp
yaroslav.Health -= 25;
```

Если затем нужно нанести урон Анастасии:

```csharp
anastasia.Health -= 30;
```

А если здоровье героя стало меньше нуля?

Например:

```csharp
yaroslav.Health = 10;
yaroslav.Health -= 50;
```

Получится:

```text
Health = -40
```

Для героя такое состояние выглядит странно.

Можно исправлять это в `Program.cs`:

```csharp
yaroslav.Health -= 50;

if (yaroslav.Health < 0) {
    yaroslav.Health = 0;
}
```

Но затем тот же код понадобится для другого героя:

```csharp
anastasia.Health -= 50;

if (anastasia.Health < 0) {
    anastasia.Health = 0;
}
```

![Одинаковые проверки для каждого героя перегружают Program.cs](/materials/guild-of-heroes/img/lab2/meme-01-stop-doing-everything-yourself.webp)

Для каждого героя `Program.cs` повторяет уменьшение здоровья и проверку границы. Эти правила относятся к поведению самого героя — перенесём их в `Hero`.

**Состояние** — данные объекта в текущий момент. **Поведение** — действия, которые объект умеет выполнять; в C# их описывают методами.

![Четыре поля состояния и пять действий Hero; объясняет Елена](/materials/guild-of-heroes/img/lab2/02-state-and-behavior.webp)

Слева показаны четыре поля уже созданного героя, справа — возможности, которые добавим сегодня. Например, вместо ручного вычитания программа будет вызывать `yaroslav.TakeDamage(25);`.

```text
Program.cs меняет поле и повторяет проверки
                    ↓
Hero получает собственный метод с этими правилами
                    ↓
Program.cs поручает действие конкретному объекту
```

![Повторение проверок в Program.cs и один метод с правилами внутри Hero](/materials/guild-of-heroes/img/lab2/01-stop-micromanaging-hero-v2.webp)

### 3. Первый метод, параметр и получатель вызова

**Метод** — именованный блок кода, который выполняется при вызове. Создадим **метод экземпляра**: он объявлен внутри класса без `static` и работает с конкретным объектом.

Откройте `Hero.cs`. После конструктора, но **до последней фигурной скобки класса `Hero`**, добавьте:

```csharp
public void TakeDamage(int damage) {
    Health -= damage;
}
```

![Герой получает метод TakeDamage с параметром damage](/materials/guild-of-heroes/img/lab2/meme-02-hero-learned-a-method.webp)

Поля и конструктор оставьте прежними. Метод не должен оказаться внутри конструктора или после закрывающей скобки класса.

![Части объявления метода: доступ, тип результата, имя, параметр и тело](/materials/guild-of-heroes/img/lab2/04-method-anatomy.webp)

- `public` — метод доступен из других частей программы.
- `void` — метод не возвращает значение.
- `TakeDamage` — имя метода.
- `int damage` — параметр: получает переданное при вызове целое число.
- `{ ... }` — тело метода, выполняемое при вызове.

**Параметр** `damage` объявлен в методе. **Аргумент** `25` — конкретное значение, переданное при вызове `yaroslav.TakeDamage(25);`.

```text
yaroslav.TakeDamage(25);
    │                │
    │                └─ 25 попадает в параметр damage
    └─ метод работает со здоровьем объекта yaroslav

Health -= damage;    →    100 - 25 = 75
```

Теперь откройте `Program.cs`. Сразу после трёх строк создания героев, перед собственным блоком, если он есть, добавьте:

```csharp
Console.WriteLine($"До вызовов: {yaroslav.Health}, {anastasia.Health}, {artem.Health}");

yaroslav.TakeDamage(25);
anastasia.TakeDamage(30);

Console.WriteLine($"После вызовов: {yaroslav.Health}, {anastasia.Health}, {artem.Health}");
```

В терминале проекта выполните `dotnet run`. В блоке с героями ожидается:

```text
До вызовов: 100, 90, 120
После вызовов: 75, 60, 120
```

![Получатель вызова и независимое состояние героев](/materials/guild-of-heroes/img/lab2/05-who-called-it-gets-it.webp)

**Действие выполняет объект слева от точки.** Вызов `yaroslav.TakeDamage(25);` меняет Ярослава, а `anastasia.TakeDamage(30);` — Анастасию. Метод написан в `Hero` один раз, но обращается к полям своего получателя. Артёму метод не вызывали, поэтому его здоровье осталось `120`.

На рисунке показаны именно эти два последовательных вызова. Дополнительные вызовы по картинке вводить не нужно.

### 4. Проверяем действие и останавливаем недопустимый вызов

Первая версия вычитает любое число. При здоровье `120` урон `200` даст `-80`, а отрицательный урон, наоборот, увеличит здоровье. Исправим правила в одном месте, чтобы каждый герой пользовался ими одинаково.

![До защитной проверки отрицательный урон увеличивает здоровье](/materials/guild-of-heroes/img/lab2/meme-03-negative-damage-heals.webp)

В `Hero.cs` **замените существующий `TakeDamage`** следующим методом. Не создавайте второй метод с такой же сигнатурой:

```csharp
public void TakeDamage(int damage) {
    if (damage <= 0) {
        return;
    }

    Health -= damage;

    if (Health < 0) {
        Health = 0;
    }
}
```

Здесь две разные проверки:

1. `damage <= 0` означает недопустимое действие. `return;` сразу завершает вызов, не изменяя здоровье.
2. При положительном уроне действие выполняется. Если результат меньше нуля, метод устанавливает `0`.

![Ранний return завершает текущий вызов до вычитания урона](/materials/guild-of-heroes/img/lab2/07-return-means-exit.webp)

![Ранний return отклоняет отрицательный урон](/materials/guild-of-heroes/img/lab2/meme-04-return-says-no.webp)

На рисунке для ясности показан только защитный выход перед вычитанием. В вашем методе сохраните и последнюю проверку `Health < 0` из листинга выше.

```text
TakeDamage(-20) → damage <= 0 → return; → здоровье остаётся прежним
TakeDamage(200) → урон положительный → вычитание → проверка нижней границы
```

В `Program.cs` после вывода «После вызовов…» добавьте:

```csharp
yaroslav.TakeDamage(-20);
Console.WriteLine($"После неверного урона: {yaroslav.Health}");

artem.TakeDamage(200);
Console.WriteLine($"После сильного урона, Артём: {artem.Health}");
```

Запустите `dotnet run`. Новые строки вывода:

```text
После неверного урона: 75
После сильного урона, Артём: 0
```

![Большой урон останавливает здоровье Артёма на нуле](/materials/guild-of-heroes/img/lab2/meme-05-artem-tested-production.webp)

Отказ не изменил здоровье Ярослава. Большой положительный урон обработан, и здоровье Артёма остановилось на нуле. Это две проверки поведения метода; оставьте их в сценарии.

![Урон не опускает здоровье ниже нуля](/materials/guild-of-heroes/img/lab2/06-damage-cannot-go-below-zero-v2.webp)

### 5. Лечение и получение опыта

Герой должен уметь не только получать урон, но и восстанавливать здоровье. В `Hero.cs` после `TakeDamage`, внутри класса, добавьте:

```csharp
public void Heal(int amount) {
    if (amount <= 0) {
        return;
    }

    Health += amount;
}
```

Параметр `amount` задаёт количество лечения. Неположительное значение отклоняется уже знакомым `return;`. Положительное прибавляется к здоровью **того героя, у которого вызвали метод**.

После `Heal`, внутри класса, добавьте получение опыта:

```csharp
public void GainExperience(int amount) {
    if (amount <= 0) {
        return;
    }

    Experience += amount;
}
```

Разница в изменяемом поле: лечение увеличивает `Health`, получение опыта — `Experience`. Вместо ручного `yaroslav.Experience += 40;` программа поручает действие герою.

В `Program.cs` после проверки сильного урона добавьте:

```csharp
yaroslav.Heal(10);
yaroslav.GainExperience(40);
yaroslav.GainExperience(25);

Console.WriteLine($"После лечения, Ярослав: {yaroslav.Health}");
Console.WriteLine($"Опыт Ярослава: {yaroslav.Experience}");
```

Выполните `dotnet run`. Новые строки:

```text
После лечения, Ярослав: 85
Опыт Ярослава: 65
```

![Опыт накапливается: 0 → 40 → 65](/materials/guild-of-heroes/img/lab2/09-experience-adds-up.webp)

![Мем 6](/materials/guild-of-heroes/img/lab2/meme-06-xp-farming.webp)

Здоровье Ярослава: `100 → TakeDamage(25) → 75 → Heal(10) → 85`. Отрицательный урон его не изменил.

Опыт: `0 → +40 → 40 → +25 → 65`. Вызовы с картинки уже записаны — повторять их не нужно. `GainExperience` накапливает опыт, а уровень пока остаётся `1`. `Heal` прибавляет положительное число; верхнюю границу здоровья в этой работе не вводим.

### 6. Метод возвращает bool

`TakeDamage`, `Heal` и `GainExperience` изменяют состояние. А как спросить, жив ли герой, ничего не изменяя?

Правило `Health > 0` относится к герою. В `Hero.cs` после `GainExperience`, внутри класса, добавьте:

```csharp
public bool IsAlive() {
    return Health > 0;
}
```

`bool` — тип с двумя значениями: `true` (истина) и `false` (ложь). В отличие от `void`, метод с типом `bool` должен вернуть такое значение.

`return Health > 0;` сначала вычисляет выражение по текущему здоровью, затем возвращает ответ в место вызова и завершает метод. В нём нет печати в консоль.

```text
yaroslav.IsAlive() → Health равно 85 → return true;  → переменная yaroslavAlive
artem.IsAlive()    → Health равно 0  → return false; → Console.WriteLine
```

В `Program.cs` после вывода опыта добавьте блок целиком:

```csharp
bool yaroslavAlive = yaroslav.IsAlive();
Console.WriteLine($"Ярослав жив: {yaroslavAlive}");
Console.WriteLine($"Артём жив: {artem.IsAlive()}");

if (yaroslavAlive) {
    Console.WriteLine("Ярослав может продолжать приключение.");
} else {
    Console.WriteLine("Ярослав больше не может сражаться.");
}
```

Выполните `dotnet run`. Новые строки:

```text
Ярослав жив: True
Артём жив: False
Ярослав может продолжать приключение.
```

В первом случае ответ сохранён в переменную и использован дважды: при печати и в `if`. Во втором ответ сразу передан в `Console.WriteLine`. В исходном коде значения записываются как `true` и `false`, а при таком выводе C# показывает `True` и `False`. Сами вызовы `IsAlive()` здоровье не изменяют.

![IsAlive возвращает bool: ответ Ярослава сохранён в переменную, ответ Артёма сразу передан в Console.WriteLine](/materials/guild-of-heroes/img/lab2/10-methods-can-answer-questions-v2.webp)

### 7. Метод возвращает строку, программа печатает её

В первой работе для вывода героя повторялись четыре обращения к полям:

```csharp
Console.WriteLine($"Имя: {yaroslav.Name}");
Console.WriteLine($"Здоровье: {yaroslav.Health}");
Console.WriteLine($"Уровень: {yaroslav.Level}");
Console.WriteLine($"Опыт: {yaroslav.Experience}");
```

Это пример прежнего вывода; добавлять его не нужно. Создадим метод, который формирует информацию о текущем объекте.

В `Hero.cs` после `IsAlive`, внутри класса, добавьте:

```csharp
public string GetInfo() {
    return $">>> {Name} <<<\n" +
           $"Здоровье: {Health}\n" +
           $"Уровень: {Level}\n" +
           $"Опыт: {Experience}";
}
```

`string` указывает тип результата. `return` передаёт готовую строку вызывающему коду, `+` соединяет части строки, а `\n` задаёт переносы строк внутри текста.

В `Program.cs` после условия с `yaroslavAlive` добавьте:

```csharp
string info = yaroslav.GetInfo();
Console.WriteLine("Строка получена. Сейчас выведем её:");
Console.WriteLine(info);

Console.WriteLine();
Console.WriteLine(anastasia.GetInfo());
Console.WriteLine();
Console.WriteLine(artem.GetInfo());
```

Выполните `dotnet run`. После предыдущего вывода появится:

```text
Строка получена. Сейчас выведем её:
>>> Ярослав <<<
Здоровье: 85
Уровень: 1
Опыт: 65

>>> Анастасия <<<
Здоровье: 60
Уровень: 1
Опыт: 0

>>> Артём <<<
Здоровье: 0
Уровень: 1
Опыт: 0
```

![Мем 7](/materials/guild-of-heroes/img/lab2/meme-07-is-alive-check.webp)

**Обратите внимание на порядок:** сначала программа получает строку в `info`, затем печатает сообщение «Строка получена…», и только после него — сведения о Ярославе. Сам `GetInfo()` ничего не напечатал.

```text
yaroslav.GetInfo() ── return строка ──> переменная info ── Console.WriteLine(info) ──> экран
                   возврат                            печать
```

![Мем 8](/materials/guild-of-heroes/img/lab2/meme-08-getinfo-does-not-print.webp)

В `Program.cs` временно поставьте `//` перед **только одной строкой** `Console.WriteLine(info);` и запустите `dotnet run`. Карточка Ярослава исчезнет, хотя строка по-прежнему создаётся и сохраняется. После наблюдения удалите эти `//`, восстановив вывод. Остальной код не меняйте.

| Объявление              | Что делает в нашем Hero | Что получает вызывающий код |
| ----------------------- | ----------------------- | --------------------------- |
| `void Heal(int amount)` | Изменяет здоровье       | Возвращаемого значения нет  |
| `bool IsAlive()`        | Проверяет здоровье      | `true` или `false`          |
| `string GetInfo()`      | Формирует описание      | Строку                      |

`void` означает отсутствие возвращаемого значения, но само по себе не запрещает методу печатать. В нашем `Hero` печать оставлена в `Program.cs`: он решает, когда показать полученную информацию. Отдельный метод для печати добавлять не требуется.

### 8. Найдите и исправьте две ошибки

Выполните две короткие диагностики. Фрагменты **намеренно неверные**, их не нужно оставлять в рабочей программе.

Для каждого: **найдите ошибку, объясните причину, исправьте минимально необходимое место**.

#### Ошибка 1. Не передали величину урона

Метод объявлен как `public void TakeDamage(int damage)`. Вызов:

```csharp
yaroslav.TakeDamage();
```

Исправьте вызов так, чтобы герой получил `20` урона. Сам метод и конструктор менять нельзя.

#### Ошибка 2. Ждут автоматической печати

### 10. Итоговые Hero.cs и сценарий Program.cs

Откройте `Hero.cs` и сравните его с итоговым вариантом. Не копируйте файл целиком, если ваш код уже работает. Поля, конструктор и пять методов должны находиться внутри одной пары скобок класса. Ни один метод не должен быть продублирован.

```csharp
public class Hero {
    public string Name;
    public int Health;
    public int Level;
    public int Experience;

    public Hero(string name, int health) {
        Name = name;
        Health = health;
        Level = 1;
        Experience = 0;
    }

    public void TakeDamage(int damage) {
        if (damage <= 0) {
            return;
        }

        Health -= damage;

        if (Health < 0) {
            Health = 0;
        }
    }

    public void Heal(int amount) {
        if (amount <= 0) {
            return;
        }

        Health += amount;
    }

    public void GainExperience(int amount) {
        if (amount <= 0) {
            return;
        }

        Experience += amount;
    }

    public bool IsAlive() {
        return Health > 0;
    }

    public string GetInfo() {
        return $">>> {Name} <<<\n" +
               $"Здоровье: {Health}\n" +
               $"Уровень: {Level}\n" +
               $"Опыт: {Experience}";
    }
}
```

Теперь сверьте **блок с героями** в `Program.cs`. Это проверочная версия уже собранного сценария, а не команда добавить все вызовы ещё раз. Самостоятельный блок собственного класса, если он расположен здесь же, сохраните ниже.

Console.WriteLine($"До вызовов: {yaroslav.Health}, {anastasia.Health}, {artem.Health}");

anastasia.TakeDamage(30);
