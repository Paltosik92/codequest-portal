## Цель работы

После первых двух работ Ярослав, Анастасия и Артём решили оформить свою компанию как настоящую **Гильдию героев**. У героев уже есть данные и методы. Осталось убедиться, что эти данные заслуживают доверия.

В этой работе вы:

- обнаружите, как открытое поле позволяет обойти проверки методов;
- разберётесь с `public`, `private`, `get`, `set` и `private set`;
- замените открытые поля свойствами;
- проверите начальные значения в конструкторе;
- ограничите здоровье снизу и сверху;
- научите класс очищать имя от лишних пробелов;
- сохраните изменение состояния через `TakeDamage()`, `Heal()` и `GainExperience()`;
- примените инкапсуляцию в собственном проекте.

Продолжаем существующий проект `GuildOfHeroes_ФИО` из ПР №1–2. Новый проект и новый репозиторий создавать не нужно.

**Главная мысль:** методов недостаточно, если внешний код всё ещё может напрямую испортить состояние. Объект должен контролировать и доступ к данным, и правила их изменения.

### 2. Поле и автоматическое свойство

— Заменим поле свойством, — предложила Анастасия.

— И всё само станет правильным? — уточнил Артём. — Мне нравится такой объём работы.

Проверим, достаточно ли одной замены синтаксиса.

В `Hero.cs` найдите:

```csharp
public int Health;
```

Замените **только эту строку**:

```csharp
public int Health { get; set; }
```

Не оставляйте одновременно поле и свойство с одинаковым именем.

**Поле** — переменная, в которой объект хранит данные. **Свойство** — член класса, через который можно организовать чтение и запись данных.

У свойства две части:

| Часть | Когда используется         | Пример обращения                       |
| ----- | -------------------------- | -------------------------------------- |
| `get` | Когда значение читают      | `Console.WriteLine(alexander.Health);` |
| `set` | Когда значение присваивают | `alexander.Health = 150;`              |

Запись `{ get; set; }` называется **автоматическим свойством**. Компилятор создаёт скрытое поле для хранения значения. Нам не приходится объявлять это поле вручную.

![Открытое поле и автоматическое свойство допускают внешнюю запись](/materials/guild-of-heroes/img/lab3/schema-01-field-vs-property.webp)

В `Program.cs` оставлен временный блок этапа 1. Не добавляйте ещё один. Запустите `dotnet run` после замены поля свойством: строки по-прежнему показывают `5000` и `-100`.

Обычный открытый `set` всё ещё принимает любое число. **Свойство само по себе не придумывает правила проверки.** Пока изменился способ объявления, а возможность внешней записи осталась.

![Свойство с public set всё ещё позволяет записать 5000 и −100](/materials/guild-of-heroes/img/lab3/meme-02-property-fixed-nothing.webp)

Теперь удалите **весь временный блок этапа 1**, включая его комментарии. После нового запуска у Александра снова должно быть `150`.

### 3. Кто может записывать значение и почему этого мало

Елена сформулировала правило:

— Посмотреть здоровье может любой участок программы. А менять его нужно через действия героя.

`public` означает, что член класса доступен внешнему коду. `private` ограничивает доступ кодом внутри класса, в котором объявлен этот член.

Если сделать всё свойство закрытым:

```csharp
private int Health { get; set; }
```

то из `Program.cs` нельзя будет даже прочитать здоровье. Этот вариант **не вставляйте**.

В `Hero.cs` замените:

```csharp
public int Health { get; set; }
```

на:

```csharp
public int Health { get; private set; }
```

Теперь чтение открыто, а запись доступна только коду внутри `Hero`.

![Чтение открыто, запись разрешена только внутри Hero](/materials/guild-of-heroes/img/lab3/schema-02-private-set-anatomy.webp)

| Где находится код               | Чтение `Health` | Присваивание `Health` |
| ------------------------------- | --------------- | --------------------- |
| В `Program.cs`                  | Разрешено       | Запрещено             |
| В конструкторе и методах `Hero` | Разрешено       | Разрешено             |

Поэтому существующая строка `Health = health;` в конструкторе продолжает работать. Строки изменения здоровья в методах тоже находятся внутри `Hero`.

**Инкапсуляция** — организация класса, при которой внутренние данные и правила работы с ними собраны вместе, а внешний код получает предусмотренные способы взаимодействия. В нашем проекте `Hero` должен отвечать за допустимое состояние героя.

**Учебный эксперимент — ожидаемая ошибка компиляции.** В конец блока с героями в `Program.cs` временно добавьте:

```csharp
alexander.Health = -100;
```

Выполните `dotnet run`. Программа **не запустится**: компилятор сообщит о недоступной записи `Hero.Health` (обычно `CS0272`). Даже допустимое число нельзя присвоить этим способом: запрет относится к доступу, а не к диапазону числа. Удалите строку.

![Закрытый setter не позволяет Александру напрямую записать здоровье из Program.cs](/materials/guild-of-heroes/img/lab3/meme-03-private-set-security-v2.webp)

Александр посмотрел на конструктор:

— Снаружи присваивать нельзя. Но начальное число я всё ещё передаю сам.

На этот раз он прав. Вместо удалённой строки временно добавьте:

```csharp
Hero healthProbe = new Hero("Проверка конструктора", -100);
Console.WriteLine($"После создания: {healthProbe.Health}");
alexander.Heal(5000);
Console.WriteLine($"После большого лечения: {alexander.Health}");
```

После `dotnet run` появится:

```text
После создания: -100
После большого лечения: 5150
```

**`private set` определяет, кто может записывать значение. Он не проверяет, какое число записывает разрешённый код.** Конструктор и `Heal` находятся внутри `Hero`, поэтому запись им доступна. Проверки допустимых чисел нужно написать именно там.

Удалите эти четыре строки, включая создание `healthProbe`. Снова запустите проект: четыре героя имеют исходное здоровье.

![Закрытая запись снаружи не заменяет проверки чисел в конструкторе и методах](/materials/guild-of-heroes/img/lab3/04-controlled-access-v2.webp)

### 4. Личный предел и проверка конструктора

— Значит, нужно знать, сколько здоровья вообще можно восстановить, — сказала Анастасия.

Артём поднял руку:

— Только не делайте всем сто. У меня со знакомства сто двадцать.

Введём небольшое правило нашей учебной модели:

1. У героя есть текущее здоровье `Health` и личный предел `MaxHealth`.
2. Положительное начальное здоровье до `200` включительно становится его личным пределом.
3. Если передано больше `200`, и начальное здоровье, и предел уменьшаются до `200`.
4. Если передано `0` или отрицательное число, текущее здоровье будет `0`, а предел для последующего восстановления — `100`.
5. После создания выполняется правило `0 <= Health <= MaxHealth`. Методы должны его сохранять.

![Артём сохраняет личный предел 120, а проверочное здоровье 5000 ограничивается 200](/materials/guild-of-heroes/img/lab3/meme-04-artem-max-health.webp)

На рисунке `5000 → 200` относится к отдельной проверке конструктора. Основной Александр по-прежнему создаётся со здоровьем и пределом `150`.

`200` — выбранный для этого учебного проекта общий потолок, а `100` — запасной предел для некорректного или нулевого начального значения. Это правила модели, а не ограничения языка C#.

![Начальный health определяет Health и личный MaxHealth](/materials/guild-of-heroes/img/lab3/schema-03-health-range.webp)

Так сохраняются все корректные вызовы из ПР №1–2: Ярослав начинает со `100`, Анастасия — с `90`, Артём — со `120`. Александру достанется предел `150`.

Здоровье `0` по-прежнему означает, что `IsAlive()` возвращает `false`. Лечение из этого состояния оставляем разрешённым, как в ПР №2: отдельные правила смерти и воскрешения не моделируем.

Откройте `Hero.cs`. Сразу после свойства `Health` добавьте:

```csharp
public int MaxHealth { get; private set; }
```

Внешнему коду нужен доступ к чтению предела, но менять его произвольно нельзя.

Найдите **существующий конструктор** `public Hero(string name, int health)` и замените его целиком:

```csharp
public Hero(string name, int health) {
    Name = name;

    MaxHealth = health;

    if (MaxHealth <= 0) {
        MaxHealth = 100;
    }

    if (MaxHealth > 200) {
        MaxHealth = 200;
    }

    Health = health;

    if (Health < 0) {
        Health = 0;
    }

    if (Health > MaxHealth) {
        Health = MaxHealth;
    }

    Level = 1;
    Experience = 0;
}
```

Сначала определяем допустимый предел. Затем приводим текущее здоровье к диапазону от `0` до этого предела. Порядок важен: нельзя сравнивать здоровье с ещё не подготовленным `MaxHealth`.

![Конструктор создаёт Hero в допустимом состоянии](/materials/guild-of-heroes/img/lab3/schema-04-constructor-flow.webp)

Конструктор по-прежнему принимает два аргумента. Все уже написанные правильные вызовы `new Hero("Имя", число)` работают.

Проверки создания и методов соберём **одним блоком на этапе 5**. Пока в `Program.cs` не добавляйте новые проверочные объекты.

### 5. Урон и лечение сохраняют границы здоровья

В `Hero.cs` найдите существующий метод `Heal(int amount)`. Замените его:

```csharp
public void Heal(int amount) {
    if (amount <= 0) {
        return;
    }

    int missingHealth = MaxHealth - Health;

    if (amount >= missingHealth) {
        Health = MaxHealth;
        return;
    }

    Health += amount;
}
```

Разберём по шагам:

1. Нулевое и отрицательное лечение игнорируем.
2. `missingHealth` хранит, сколько здоровья не хватает до личного предела.
3. Если лечения достаточно для полного восстановления, устанавливаем предел и заканчиваем метод.
4. Если лечения меньше, прибавляем его обычным способом.

Например, при `Health = 120` и `MaxHealth = 150` не хватает `30`. Лечение на `10` даст `130`, а на `5000` остановится на `150`.

![Алгоритм Heal сохраняет личный предел здоровья](/materials/guild-of-heroes/img/lab3/schema-05-heal-flow.webp)

Если здоровье уже полное, `missingHealth` равно `0`: положительное лечение оставит `Health` равным `MaxHealth`. Сначала сравниваем с недостающим здоровьем, чтобы не складывать заведомо слишком большие числа. Подробная арифметика — в дополнительной части А.

Метод `TakeDamage(int damage)` из №2 уже сохраняет нижнюю границу. **Оставьте его прежним**; сверьте, не добавляя второй метод:

```csharp
public void TakeDamage(int damage) {
    if (damage <= 0) {
        return;
    }

    Health -= damage;

    if (Health < 0) {
        Health = 0;
    }
}
```

**Учебный эксперимент.** В конец блока с героями в `Program.cs` добавьте один общий блок:

```csharp
// Начало проверки здоровья
Hero lowProbe = new Hero("Проверка нижней границы", -100);
Hero highProbe = new Hero("Проверка верхней границы", 5000);
Console.WriteLine($"Нижняя граница: {lowProbe.Health}/{lowProbe.MaxHealth}");
Console.WriteLine($"Верхняя граница: {highProbe.Health}/{highProbe.MaxHealth}");
Console.WriteLine($"Александр до действий: {alexander.Health}/{alexander.MaxHealth}");

alexander.TakeDamage(30);
alexander.Heal(10);
Console.WriteLine($"Обычные действия: {alexander.Health}");
alexander.Heal(5000);
Console.WriteLine($"Большое лечение: {alexander.Health}");
alexander.Heal(-20);
Console.WriteLine($"Отказ в лечении: {alexander.Health}");
alexander.TakeDamage(5000);
Console.WriteLine($"Большой урон: {alexander.Health}; жив: {alexander.IsAlive()}");
alexander.Heal(20);
Console.WriteLine($"Восстановление: {alexander.Health}");
Console.WriteLine($"Артём без изменений: {artem.Health}/{artem.MaxHealth}");
// Конец проверки здоровья
```

Выполните `dotnet run`. После карточек ожидается:

```text

Верхняя граница: 200/200
Александр до действий: 150/150
Обычные действия: 130
Большое лечение: 150
Отказ в лечении: 150
```

![Лечение на 5000 восстанавливает Александра до 150/150 и не повышает его предел](/materials/guild-of-heroes/img/lab3/meme-05-alexander-heal-5000.webp)

На рисунке — отдельный эпизод большого лечения до `150/150`, а не итог всего проверочного блока с последующим уроном и восстановлением.

Здесь видны обе стороны защиты: конструктор создаёт допустимое состояние, а разрешённые действия сохраняют его. Чтение свойств доступно; прямое присваивание снаружи было запрещено на этапе 3. Отрицательное лечение не меняет здоровье. Вызовы Александра не меняют Артёма.

Такое правило, которое объект сохраняет всё время своей работы, называют **инвариантом**. Его обеспечили проверки в конструкторе и методах вместе с ограничением записи.

Квадратные скобки в выводе помогают увидеть пробелы. Эти объекты проверяют ввод, а не добавляют в историю второго Александра.

![Пробелы вокруг имени Александра видны в скобках; очищать имя будет сам Hero](/materials/guild-of-heroes/img/lab3/meme-06-alexander-name-spaces-v2.webp)

Пока оставьте этот блок с двумя объектами и двумя строками вывода: после изменения `Name` запустим тот же пример и сравним результат. Создавать второй блок с такими же переменными не нужно.

Договоримся о правилах: пробелы по краям имени удаляем; пустое или состоящее только из пробельных символов имя заменяем на `"Безымянный герой"`. Это запасная подпись для некорректных данных, а не новый персонаж.

У автоматического свойства мы не писали тело `get` и `set`. Для очистки имени понадобится выполнить несколько команд при записи.

В `Hero.cs` найдите поле:

```csharp
public string Name;
```

Замените **эту строку** следующим блоком:

```csharp
private string _name = "Безымянный герой";

public string Name {
    get {
        return _name;
    }

    private set {
        if (string.IsNullOrWhiteSpace(value)) {
            _name = "Безымянный герой";
            return;
        }

        _name = value.Trim();
    }
}
```

Блок находится внутри `Hero`, перед числовыми свойствами. Поле и свойство здесь имеют **разные имена**.

| Часть         | Назначение                                              |
| ------------- | ------------------------------------------------------- |
| `_name`       | Закрытое поле, которое действительно хранит строку      |
| `Name`        | Свойство, через которое класс организует доступ к имени |
| `get`         | Возвращает содержимое `_name`                           |
| `private set` | Проверяет и сохраняет новое имя; доступен внутри `Hero` |
| `value`       | Значение, которое сейчас присваивают свойству           |

![Поле \_name хранит имя, свойство Name управляет доступом](/materials/guild-of-heroes/img/lab3/schema-07-name-property-anatomy.webp)

Подчёркивание в `_name` — принятый способ отличать закрытое поле от свойства. Это часть имени, а не отдельная команда C#.

Начальное значение `_name` гарантирует, что поле с самого начала содержит строку. Окончательное имя конструктор назначит через свойство.

В конструкторе **сохраните** строку:

```csharp
Name = name;
```

Она запускает `set`. Не заменяйте её на `_name = name;`: тогда проверки будут обойдены внутри самого класса.

На схеме проверки выполняет **наш код внутри setter свойства Name**. Слова `private set` сами по себе лишь ограничивают доступ; проверку имени они не добавляют.

### 7. Откуда берётся value и как проходит имя

При создании:

```csharp
Hero alexander = new Hero("   Александр   ", 150);
```

данные проходят такую цепочку:

```text
аргумент "   Александр   "
        ↓
параметр name в конструкторе
        ↓
Name = name
        ↓
value внутри set
        ↓
проверка и Trim()
        ↓
_name хранит "Александр"
```

![Присваивание через Name запускает проверку и Trim](/materials/guild-of-heroes/img/lab3/schema-08-name-data-flow.webp)

Это объясняющий пример; повторное объявление `alexander` в `Program.cs` добавлять не нужно.

`string.IsNullOrWhiteSpace(value)` возвращает `true`, если значение отсутствует, строка пуста или состоит только из пробельных символов. Под отсутствием значения здесь понимается `null`; создавать такие значения для этой работы не требуется.

`value.Trim()` возвращает строку без пробелов по краям. Пробелы между словами сохраняются. Полученный результат нужно записать в `_name`.

При чтении `alexander.Name` выполняется `get`, который возвращает уже проверенную строку.

**Важно:** `get` должен возвращать `_name`, а не `Name`. Иначе чтение свойства снова вызовет чтение того же свойства — без остановки.

![Возврат Name из getter вызывает его снова; return \_name читает сохранённое имя](/materials/guild-of-heroes/img/lab3/meme-07-getter-infinite-mirror.webp)

**Сравним с результатом до изменения.** В `Program.cs` уже оставлен блок с `spacedProbe` и `emptyProbe` из этапа 6. Не вставляйте его ещё раз. Выполните `dotnet run`:

```text
Имя с пробелами: [Александр]
Пустая запись: [Безымянный герой]
```

Раньше в квадратных скобках оставались лишние пробелы. Теперь `Name = name;` запускает setter, тот проверяет вход и сохраняет нормализованную строку в `_name`. Getter возвращает уже сохранённое имя.

`value` доступно внутри setter автоматически: это значение правой части присваивания. Его не нужно объявлять отдельной переменной или передавать дополнительным аргументом конструктора. При `Name = name;` содержимое параметра `name` становится `value`.

**`get` (getter)** выполняется при чтении `spacedProbe.Name`. **`set` (setter)** выполняется при присваивании внутри класса. Снаружи читать `Name` можно, а переименовать героя прямой записью нельзя: setter закрыт. `Name` — свойство, а не метод, поэтому для чтения скобки `()` не нужны.

Удалите весь экспериментальный блок с `spacedProbe`, `emptyProbe` и выводом их имён. Основной Александр остаётся один. Дополнительную проверку с `""` можно выполнить позже по части Б.

**Второй шаг закончен:** в объекте хранится проверенная строка, а конструктор проходит через одно место проверки имени. Закрытое поле `_name` хранит данные; свойство `Name` организует доступ к ним.

### 11. Итоговый Hero и сценарий регистрации

Откройте `Hero.cs` и сравните с итоговым вариантом. Не заменяйте свой рабочий код механически: найдите отличия и проверьте их смысл. Не оставляйте поля рядом с одноимёнными свойствами. Все члены находятся внутри класса; ни один метод не дублируется.

![Карта данных, свойств и методов актуального Hero](/materials/guild-of-heroes/img/lab3/schema-10-hero-class-map.webp)

На карте приведены **названия методов**, а не готовые строки вызова: у `TakeDamage`, `Heal` и `GainExperience` параметры для краткости опущены. В реальном коде каждый принимает **один int**, как показано в листинге ниже. Вызовы этих методов без аргумента недопустимы.

```csharp
public class Hero {
    private string _name = "Безымянный герой";

    public string Name {
        get {
            return _name;
        }

        private set {
            if (string.IsNullOrWhiteSpace(value)) {
                _name = "Безымянный герой";
                return;
            }

            _name = value.Trim();
        }
    }

    public int Health { get; private set; }
    public int MaxHealth { get; private set; }
    public int Level { get; private set; }
    public int Experience { get; private set; }

    public Hero(string name, int health) {
        Name = name;

        MaxHealth = health;

        if (MaxHealth <= 0) {
            MaxHealth = 100;
        }

        if (MaxHealth > 200) {
            MaxHealth = 200;
        }

        Health = health;

        if (Health < 0) {
            Health = 0;
        }

        if (Health > MaxHealth) {
            Health = MaxHealth;
        }

        Level = 1;
        Experience = 0;
    }

    public void TakeDamage(int damage) {
        if (damage <= 0) {
            return;
        }

        Health -= damage;

        if (Health < 0) {
            Health = 0;
        }
    }

    public void Heal(int amount) {
        if (amount <= 0) {
            return;
        }

        int missingHealth = MaxHealth - Health;

        if (amount >= missingHealth) {
            Health = MaxHealth;
            return;
        }

        Health += amount;
    }

    public void GainExperience(int amount) {
        if (amount <= 0) {
            return;
        }

        if (amount > 2147483647 - Experience) {
            return;
        }

        Experience += amount;
    }

    public bool IsAlive() {
        return Health > 0;
    }

    public string GetInfo() {
        return $">>> {Name} <<<\n" +
               $"Здоровье: {Health}\n" +
               $"Уровень: {Level}\n" +
               $"Опыт: {Experience}";
    }
}
```

`IsAlive()` и `GetInfo()` остались такими же, как в №2. `GetInfo()` возвращает строку с прежним форматом, а вывод выполняется в `Program.cs`. Предел при необходимости читается отдельно через `MaxHealth`.

## Дополнительная часть

### А. Арифметика безопасного изменения чисел

#### Почему Heal сравнивает перед сложением

У `int` есть конечный диапазон. Если сначала вычислить `Health + amount`, очень большая сумма может выйти за него. Поэтому `missingHealth = MaxHealth - Health` вычисляет только недостающую величину. При `amount >= missingHealth` метод сразу устанавливает `MaxHealth` и завершает вызов. При меньшей положительной прибавке результат остаётся ниже предела. Метод работает и при полном здоровье: недостающая величина равна `0`.

#### Почему GainExperience сравнивает с остатком диапазона

В нашем классе опыт неотрицателен. Выражение `2147483647 - Experience` показывает, сколько ещё можно прибавить без выхода за границы `int`. Если `amount` больше, весь вызов отклоняется. Проверка должна стоять **перед** `Experience += amount;`.

![До сложения проверяем оставшееся место в диапазоне int](/materials/guild-of-heroes/img/lab3/schema-09-experience-overflow.webp)

Точная граница типа не является порогом нового уровня. Даже опыт `120` в текущей версии оставляет уровень `1`.

| Конструкция                               | Где хранятся данные                    | Что контролируем                           |
| ----------------------------------------- | -------------------------------------- | ------------------------------------------ |
| `public int Health;`                      | Непосредственно в открытом поле        | Внешняя запись ничем не ограничена         |
