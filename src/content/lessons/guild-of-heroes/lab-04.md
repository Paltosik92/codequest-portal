## Цель и результат

После этой работы вы:

- соберёте героев в коллекцию `List<Hero>`;
- научитесь добавлять элементы, узнавать их количество и получать элемент по номеру;
- замените повторяющийся вывод одним циклом `foreach`;
- проверите, что список хранит **ссылки** на прежних героев, а не их копии;
- создадите класс `Guild` — название и состав вместе;
- увидите, от чего `private set` у списка защищает, а от чего — нет;
- научитесь предсказывать вывод программы со ссылками до запуска;
- перенесёте коллекцию в свой личный проект.

**Результат:** одна гильдия, пять героев, один цикл переклички. Новый участник добавляется одной строкой.

### 2. Почему отдельных переменных уже мало

Сейчас вывод выглядит так:

```csharp
Console.WriteLine(yaroslav.GetInfo());
Console.WriteLine(anastasia.GetInfo());
Console.WriteLine(artem.GetInfo());
Console.WriteLine(alexander.GetInfo());
```

Для Бориса нужен список **всех**. С пятым участником придётся дописать пятую строку. Ещё — в подсчёт, в поиск, в любой другой общий отчёт. Забыли одну строку — герой есть, а в отчёте его нет.

Нам нужна **коллекция** — объект, который объединяет элементы и позволяет:

1. узнать, сколько их;
2. получить один элемент;
3. выполнить одно действие с каждым.

Первая коллекция курса — `List<Hero>`, список героев.

### 3. Создаём список и добавляем героев

Откройте `Program.cs`. Создания четырёх героев и строки `alexander.TakeDamage(10);` и `alexander.Heal(10);` **оставьте**. Весь старый вывод — от `">>> Участники готовы <<<"` до строки о пределе здоровья Александра — **удалите**.

Ниже добавьте:

```csharp
List<Hero> heroes = new List<Hero>();
Console.WriteLine($"В списке: {heroes.Count}");
```

| Фрагмент | Смысл |
| --- | --- |
| `List<Hero>` | Тип: список, элементы которого — объекты `Hero` |
| `heroes` | Имя переменной; множественное число подсказывает, что это не один герой |
| `new List<Hero>()` | Создание нового **пустого** списка |
| `heroes.Count` | Свойство: сколько элементов сейчас в списке |

`dotnet run` покажет `В списке: 0`. Это правильно: герои существуют, но список о них ещё ничего не знает.

Теперь **между** созданием списка и выводом `Count` добавьте:

```csharp
heroes.Add(yaroslav);
heroes.Add(anastasia);
heroes.Add(artem);
heroes.Add(alexander);
```

`Add` — метод списка: кладёт переданный элемент в конец. Новых героев здесь нет: в скобках — уже созданные объекты.

Запустите: `В списке: 4`.

> **Запомните:** создать героя, создать список и добавить героя в список — три разных действия.

### 4. Номер элемента — индекс

Елена попросила назвать первого и последнего в списке.

— Первому номер один, — уверенно сказал Александр.

— Не в списке, — ответила Анастасия. — Здесь счёт с нуля.

**Индекс** — позиция элемента. У `List` первый индекс — `0`:

```text
Индекс:    0          1          2        3
Элемент:   Ярослав    Анастасия  Артём    Александр
           Count = 4, последний индекс = Count - 1 = 3
```

Элемент получают квадратными скобками: `heroes[0]` — это один `Hero`, у него можно прочитать `Name`.

После строки с `Count` добавьте:

```csharp
if (heroes.Count > 0) {
    Console.WriteLine($"Первый: {heroes[0].Name}");
    Console.WriteLine($"Последний: {heroes[heroes.Count - 1].Name}");
}
```

Ожидается:

```text
В списке: 4
Первый: Ярослав
Последний: Александр
```

Проверка `Count > 0` нужна: у пустого списка нет даже элемента `[0]`.

![Count равно 4, но индекса 4 нет](/materials/guild-of-heroes/img/lab04/schema-02-index-boundary.webp)

![Артём ищет ящик с индексом 4: у четырёх ящиков есть только индексы 0–3](/materials/guild-of-heroes/img/lab04/meme-01-count-not-index.webp)

### 5. Один foreach вместо четырёх строк

Выводить всех по индексам — снова повторение. Нужна команда «для каждого героя в списке — вывести карточку». Это цикл `foreach`.

После блока `if` добавьте:

```csharp
Console.WriteLine();
foreach (Hero hero in heroes) {
    Console.WriteLine(hero.GetInfo());
    Console.WriteLine();
}
```

| Часть | Смысл |
| --- | --- |
| `foreach` | Выполнить тело для каждого элемента |
| `Hero hero` | Тип и имя переменной текущего элемента |
| `in heroes` | Откуда брать элементы |

На каждом проходе `hero` указывает на очередного героя: Ярослав, Анастасия, Артём, Александр. Тело написано один раз, выполняется четыре.

Не путайте: `heroes` — весь список, `hero` — один текущий элемент. Цикл **не создаёт** героев: внутри нет `new Hero`.

![Третий проход foreach: hero получает ссылку на Артёма из элемента с индексом 2](/materials/guild-of-heroes/img/lab04/schema-04-foreach-current.webp)

Запустите: после первого и последнего — четыре карточки.

### 6. Список хранит ссылки, а не копии

— Если Ярослав есть и в переменной, и в списке, — спросил Артём, — их теперь два?

Проверим. Это проба, поэтому работаем с **учебными** объектами и не трогаем основной сценарий.

Замените тело `Probe.Run` целиком:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Hero probeHero = new Hero("Учебная проба", 100);
    List<Hero> probeList = new List<Hero>();
    probeList.Add(probeHero);

    probeHero.TakeDamage(20);

    Console.WriteLine($"Через переменную: {probeHero.Health}");
    Console.WriteLine($"Через список: {probeList[0].Health}");
    Console.WriteLine($"Элементов: {probeList.Count}");
}
```

В `Program.cs` уберите `//` перед `Probe.Run();`.

**До запуска предскажите:** какое здоровье будет видно через список?

`dotnet run`. В начале вывода:

```text
>>> Проба <<<
Через переменную: 80
Через список: 80
Элементов: 1
```

Урон получил **один** объект. `Add` положил в список не копию героя, а **ссылку** — способ добраться до того же объекта. Поэтому изменение видно с обеих сторон.

```text
probeHero ────┐
              ├──► Hero «Учебная проба»: Health 100 → 80
probeList[0] ─┘
```

![Переменная и элемент списка ведут к одному объекту](/materials/guild-of-heroes/img/lab04/schema-01-list-references.webp)

Защита `Hero` из №3 продолжает работать: через список менять здоровье можно только методами героя.

Верните `//` перед `Probe.Run();` и очистите тело `Run` до одной строки вывода «Проба».

### 8. Класс Guild: название и состав вместе

Елена подписала бланк Бориса и остановилась.

— Список есть. А чей он? У гильдии есть название. Пусть в программе тоже будет понятно, чьи это участники.

Гильдия — отдельная сущность: у неё есть **название** и **состав**. Создайте в корне проекта файл `Guild.cs`:

```csharp
public class Guild {
    public string Name { get; private set; }
    public List<Hero> Heroes { get; private set; } = new List<Hero>();

    public Guild(string name) {
        Name = name;
    }
}
```

| Член | Назначение |
| --- | --- |
| `Name` | Название гильдии |
| `Heroes` | Список участников этой гильдии |
| `= new List<Hero>()` | Начальное значение: у каждой новой гильдии свой пустой список |
| `Guild(string name)` | Конструктор получает название |

`Guild` не заменяет `Hero` и не является «большим героем». Гильдия **хранит ссылки** на героев.

![Guild хранит название и список ссылок на героев](/materials/guild-of-heroes/img/lab04/schema-03-guild-owns-list.webp)

#### 8.1. Переносим состав в гильдию

В `Program.cs` замените строку

```csharp
List<Hero> heroes = new List<Hero>();
```

на

```csharp
Guild guild = new Guild("Гильдия героев");
```

Затем **все** обращения к `heroes` замените на `guild.Heroes`:

| Было | Стало |
| --- | --- |
| `heroes.Add(yaroslav);` и остальные `Add` | `guild.Heroes.Add(yaroslav);` … |
| `heroes.Count` (три места, включая скобки индекса) | `guild.Heroes.Count` |
| `heroes[0]`, `heroes[heroes.Count - 1]` | `guild.Heroes[0]`, `guild.Heroes[guild.Heroes.Count - 1]` |
| `foreach (Hero hero in heroes)` | `foreach (Hero hero in guild.Heroes)` |

Строку `Console.WriteLine($"В списке: ...")` замените на две:

```csharp
Console.WriteLine($">>> {guild.Name}: перекличка <<<");
Console.WriteLine($"Участников: {guild.Heroes.Count}");
```

Сначала сделайте все замены, потом запускайте. Регистр важен: `Heroes` — свойство гильдии, `heroes` — старая переменная, её больше нет.

Цепочку `guild.Heroes[0].Name` читаем слева направо: гильдия → её список → первый элемент → его имя.

### 9. Что private set защищает, а что нет

Пока Елена дописывала бланк, Александр взял ручку.

— Запишу себя ещё раз. Два дежурства — две порции обеда.

Проверим, может ли программа ему помешать. Снова работаем в `Probe.cs` с учебной гильдией. Замените тело `Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Guild probeGuild = new Guild("Учебная гильдия");
    Hero probeWarrior = new Hero("Учебный воин", 150);

    probeGuild.Heroes.Add(probeWarrior);
    probeGuild.Heroes.Add(probeWarrior);
    Console.WriteLine($"Записей: {probeGuild.Heroes.Count}");

    probeWarrior.TakeDamage(30);
    foreach (Hero hero in probeGuild.Heroes) {
        Console.WriteLine($"{hero.Name}: {hero.Health}");
    }
}
```

Включите пробу и запустите:

```text
>>> Проба <<<
Записей: 2
Учебный воин: 120
Учебный воин: 120
```

Две записи, но **один** объект: урон виден в обеих строках. `List` повторы не запрещает.

Теперь сразу после второго `Add` временно добавьте строку:

```csharp
probeGuild.Heroes = new List<Hero>();
```

Запуск **не состоится**: ошибка компиляции `CS0272` — запись в `Heroes` недоступна. Удалите эту строку.

Почему так?

```text
probeGuild.Heroes = другой список    → нужен set    → он private → запрещено
probeGuild.Heroes.Add(probeWarrior)  → нужен только get → список получен → Add изменил его содержимое
```

| Что | Защищено сейчас? |
| --- | --- |
| Заменить весь список другим | Да, `private set` |
| Добавить в список кого угодно, хоть дважды | **Нет** |

Правило «одна запись на человека» пока не принадлежит гильдии — его соблюдает только тот, кто помнит. Решать это будем в №5.

![Александр вписывает себя второй раз](/materials/guild-of-heroes/img/lab04/02-double-entry.webp)

Выключите пробу и очистите `Run`.
