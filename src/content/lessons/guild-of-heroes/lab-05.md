## Закрытый состав, поиск и null

> До совета Нижнего Брода — **19 дней**.

К воротам водосборника подошли рано. Над каменной стеной висели семь колоколов, а внизу, у калитки, стоял невысокий седой человек в коричневом фартуке. Из кармана торчал деревянный штемпель, на пальцах — синие пятна чернил.

— Борис, — кивнул он. — Список принесли?

Елена протянула вчерашний лист. Борис пробежал его глазами и нахмурился.

— Александр. И ещё раз Александр. Он что, пойдёт дважды?

— Это была шутка, — сказал Александр. — Про обед.

— На плотине шуток в списках не бывает. Сегодня он записан дважды, завтра кто-то впишет того, кого здесь нет. — Борис постучал пальцем по листу. — Список, в который можно вписать кого угодно, — не список.

Он достал из кармана помятую карточку.

— И вот ещё. С утра у ворот крутился парень, сказал, что из гильдии. Записался так.

На карточке было нацарапано: « аРтЁм ».

— Я с пробелами тоже я, — обиделся Артём.

— Это ты так говоришь, — ответил Борис. — А мне надо найти тебя в списке.

Елена кивнула на синюю отметку на вчерашнем бланке.

— Это ваша печать?

Борис посмотрел в сторону.

— Привычка. Потом объясню.

## Обязательная часть

### 1. Воспроизводим проблему

В №4 мы увидели: `private set` не мешает вызвать `Add`. Посмотрим, что ещё может сделать с составом любой участок программы.

Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Guild probeGuild = new Guild("Учебная гильдия");
    probeGuild.Heroes.Add(new Hero("Учебный воин", 150));
    probeGuild.Heroes.Add(new Hero("Учебный маг", 90));
    Console.WriteLine($"До: {probeGuild.Heroes.Count}");

    probeGuild.Heroes.Clear();
    Console.WriteLine($"После Clear: {probeGuild.Heroes.Count}");
}
```

`Clear()` — метод списка: удаляет все элементы. Включите пробу (`Probe.Run();` без `//`) и запустите:

```text
>>> Проба <<<
До: 2
После Clear: 0
```

Одна строка снаружи — и гильдия пуста. Гильдия хранит состав, но **не управляет** им: кто получил список, тот и решает.

Выключите пробу и очистите `Run`.

### 2. Кто отвечает за правило

— Я могу проверять повторы перед каждым `Add`, — предложил Ярослав.

— А тот, кто напишет код после тебя? — спросила Елена.

Если проверка живёт в `Program`, она работает только там, где о ней вспомнили. Любой другой участок программы получит список и добавит что угодно.

Поэтому правило будет принадлежать **самой гильдии**. Внешний код **просит**, гильдия **решает**.

| Объект | За что отвечает |
| --- | --- |
| `Hero` | Имя, здоровье, опыт одного героя |
| `Guild` | Состав: приём, поиск, удаление, подсчёт |
| `Program` | Порядок действий и вывод результата |

Договоримся о правиле на эту работу:

> В гильдии не может быть двух героев с одинаковым именем. Имена сравниваем без пробелов по краям и без учёта регистра.

| Уже в гильдии | Пытаются добавить | Решение |
| --- | --- | --- |
| Александр | того же `alexander` | отказ |
| Александр | другой объект с именем « аЛеКсАнДр » | отказ |
| Артём | героя «Артем» (через «е») | принять: в нашем сравнении это другое имя |

В жизни тёзки бывают разными людьми. Сегодня имя — простой ключ. Позже в курсе мы увидим, когда этого мало.

### 3. Закрываем список

Откройте `Guild.cs` и **замените всё содержимое**:

```csharp
public class Guild {
    private List<Hero> _heroes = new List<Hero>();

    public string Name { get; private set; }

    public int MemberCount {
        get { return _heroes.Count; }
    }

    public Guild(string name) {
        Name = name;
    }

    public bool AddHero(Hero hero) {
        _heroes.Add(hero);
        return true;
    }

    public List<Hero> GetMembers() {
        List<Hero> result = new List<Hero>();
        foreach (Hero hero in _heroes) {
            result.Add(hero);
        }
        return result;
    }
}
```

Это **промежуточная** версия. `AddHero` пока принимает всех — проверку добавим на этапе 6.

Разберём новое.

**`private List<Hero> _heroes`** — закрытое поле. Обращаться к нему может только код внутри `Guild`. Подчёркивание в имени — соглашение для закрытых полей, как `_name` в `Hero`. Публичного свойства `Heroes` больше нет.

**`MemberCount`** — **вычисляемое свойство**. Своего значения оно не хранит: при каждом чтении выполняется `get`, который берёт текущий `_heroes.Count`. Добавили или удалили героя — следующее чтение покажет новое число. Второй счётчик, который надо не забыть обновить, не нужен.

**`AddHero`** возвращает `bool`: `true` — принят, `false` — отказ. Как `IsAlive()` из №2, только теперь ответ сообщает, удалась ли операция.

**`GetMembers`** выдаёт **новый** список, в который переложены ссылки на тех же героев. Внутренний `_heroes` наружу не попадает. Почему это важно — проверим на этапе 8.

![Program просит Guild, а прямой путь к \_heroes закрыт](/materials/guild-of-heroes/img/lab05/schema-01-closed-roster.webp)

### 4. Переносим Program на новые методы

Пока `Program` обращается к `guild.Heroes`, которого больше нет, — редактор подчеркнёт ошибки. Это ожидаемо. Сделайте все замены, затем запускайте.

1. Пять строк `guild.Heroes.Add(...)` замените на `guild.AddHero(...)` с теми же аргументами.
2. Сразу после последнего `AddHero` получите копию состава:

```csharp
List<Hero> members = guild.GetMembers();
```

3. Остальные обращения замените по таблице:

| Было | Стало |
| --- | --- |
| `guild.Heroes.Count` в строке «Участников» | `guild.MemberCount` |
| `guild.Heroes.Count` в проверке и индексах | `members.Count` |
| `guild.Heroes[0]`, `guild.Heroes[...]` | `members[0]`, `members[members.Count - 1]` |
| все `foreach (... in guild.Heroes)` | `foreach (... in members)` |
| `guild.Heroes[0]` в поиске самого здорового | `members[0]` |

Индексы берём у `members`, поэтому и границу проверяем по `members.Count`.

Запустите. Вывод должен **совпасть** с итогом №4: пять карточек, «2» и «Александр (150)». Мы поменяли способ доступа, но не данные.

### 5. Поиск, который может не найти

Борис показал карточку « аРтЁм ».

— Найдите его в списке.

Нужен метод, который вернёт **существующего** героя. Но героя может и не оказаться. Что тогда вернуть?

#### 5.1. null и Hero?

```text
Hero   → ссылка на героя
Hero?  → ссылка на героя ИЛИ её отсутствие
null   → «ссылки нет», никого не нашли
```

`null` — не пустое имя, не строка `"null"` и не герой со здоровьем 0. Это отсутствие ссылки на объект. Знак `?` после типа говорит компилятору: здесь может прийти `null`, проверяйте.

![Пустой стул: не найден — не новый герой](/materials/guild-of-heroes/img/lab05/meme-01-null-chair.webp)

#### 5.2. Сначала точный поиск

Добавьте в `Guild`, после `AddHero`:

```csharp
public Hero? FindHeroByName(string name) {
    foreach (Hero hero in _heroes) {
        if (hero.Name == name) {
            return hero;
        }
    }
    return null;
}
```

Как он работает для запроса «Сергей»:

| Карточка | Совпало? | Что дальше |
| --- | --- | --- |
| Ярослав | нет | следующая |
| Анастасия | нет | следующая |
| Артём | нет | следующая |
| Александр | нет | следующая |
| Сергей | да | `return hero` — метод закончен |

`return hero` стоит **внутри** `if`: первое совпадение — сразу ответ. `return null` стоит **после** цикла: только просмотрев всех, мы знаем, что никого нет.

#### 5.3. Пользуемся ответом безопасно

```csharp
Hero? found = guild.FindHeroByName("Сергей");
if (found != null) {
    Console.WriteLine(found.Name);
} else {
    Console.WriteLine("Не найден.");
}
```

Это пример для разбора, пока не вставляйте. Главное: **сначала проверка на `null`, потом обращение к `Name`**. Если обратиться к свойству у `null`, программа завершится с ошибкой `NullReferenceException`. Компилятор подсказывает это предупреждением, если вы забыли проверку.

![Проверка результата Hero?: свойства читаем только в ветке found != null](/materials/guild-of-heroes/img/lab05/schema-04-safe-result.webp)

#### 5.4. « аРтЁм » — это Артём

Анастасия положила рядом две карточки: « аРтЁм » и «Артём».

— Пробелы по краям и большие буквы. Человек один.

Точный поиск этого не поймёт: `" аРтЁм " == "Артём"` — `false`. Запрос нужно подготовить, а сравнивать — без учёта регистра.

**Замените** `FindHeroByName` целиком:

```csharp
public Hero? FindHeroByName(string name) {
    if (string.IsNullOrWhiteSpace(name)) {
        return null;
    }

    string searchName = name.Trim();

    foreach (Hero hero in _heroes) {
        if (string.Equals(hero.Name, searchName, StringComparison.OrdinalIgnoreCase)) {
            return hero;
        }
    }

    return null;
}
```

| Часть | Смысл |
| --- | --- |
| `IsNullOrWhiteSpace(name)` | Пустой запрос — сразу «никого» |
| `name.Trim()` | Убрать пробелы по краям **запроса**; имена героев уже очищены их конструктором |
| `string.Equals(a, b, ...)` | Сравнить две строки |
| `StringComparison.OrdinalIgnoreCase` | Режим: без учёта регистра |

Мы не меняем имя героя и не создаём нового — только ищем и возвращаем ссылку на того, кто уже в составе.

В `Program.cs` после цикла карточек добавьте:

```csharp
Hero? found = guild.FindHeroByName(" аРтЁм ");
if (found != null) {
    Console.WriteLine($"Найден по запросу « аРтЁм »: {found.Name}");
} else {
    Console.WriteLine("По запросу « аРтЁм » никого нет.");
}
```

Запустите: `Найден по запросу « аРтЁм »: Артём`.

![Анастасия сравнивает карточку « аРтЁм » с карточкой Артёма](/materials/guild-of-heroes/img/lab05/02-two-cards.webp)

![Пустой запрос отклоняется сразу; непустой проходит карточки до совпадения или до конца списка](/materials/guild-of-heroes/img/lab05/schema-02-search-or-null.webp)

### 6. Гильдия сама отклоняет повтор

Теперь у гильдии есть поиск — его можно использовать в приёме. **Замените** `AddHero`:

```csharp
public bool AddHero(Hero hero) {
    if (FindHeroByName(hero.Name) != null) {
        return false;
    }

    _heroes.Add(hero);
    return true;
}
```

Порядок важен: **сначала проверка, потом изменение**. При отказе метод выходит до `_heroes.Add` — состав не тронут.

Обратите внимание: `AddHero` не сравнивает строки сам. Он вызывает `FindHeroByName`, где правило имени уже написано. Если правило изменится, менять его придётся в одном месте.

В `Program.cs` после блока поиска добавьте:

```csharp
Console.WriteLine($"Повтор Александра принят: {guild.AddHero(alexander)}");
```

Вызов метода внутри `{ }` выполняется, а его ответ попадает в строку. Ожидается `False`. Александр записан один раз.

### 7. Удаление найденного

— Если кто-то не пойдёт, — сказал Борис, — вычёркивайте одной операцией. Не руками в трёх местах.

Добавьте в `Guild`:

```csharp
public bool RemoveHero(string name) {
    Hero? hero = FindHeroByName(name);
    if (hero == null) {
        return false;
    }
    return _heroes.Remove(hero);
}
```

`Remove` у списка удаляет переданный элемент и возвращает `bool`: был ли он там. Мы передаём ту самую ссылку, которую нашёл поиск, — не новый объект с таким же именем.

Удаление убирает героя **из состава**, но не уничтожает объект: переменная, которая на него ссылалась, по-прежнему работает.

В `Program.cs` после проверки повтора:

```csharp
Console.WriteLine($"Удалён отсутствующий: {guild.RemoveHero("Борис")}");
Console.WriteLine($"Участников после проверок: {guild.MemberCount}");
```

— Меня вычёркивать не надо, — сказал Борис. — Я не в гильдии.

Ожидается `False` и `5`.

### 8. Почему наружу — копия

Ещё раз вспомним этап 1: получив сам список, внешний код вызвал `Clear()` и стёр состав. Что будет теперь?

Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Guild probeGuild = new Guild("Учебная гильдия");
    probeGuild.AddHero(new Hero("Учебный воин", 150));
    probeGuild.AddHero(new Hero("Учебный маг", 90));

    List<Hero> copy = probeGuild.GetMembers();
    copy.Clear();
    Console.WriteLine($"В копии: {copy.Count}");
    Console.WriteLine($"В гильдии: {probeGuild.MemberCount}");

    List<Hero> again = probeGuild.GetMembers();
    again[0].TakeDamage(50);
    Hero? warrior = probeGuild.FindHeroByName("Учебный воин");
    if (warrior != null) {
        Console.WriteLine($"Здоровье воина в гильдии: {warrior.Health}");
    }
}
```

Запустите:

```text
>>> Проба <<<
В копии: 0
В гильдии: 2
Здоровье воина в гильдии: 100
```

Два вывода из одной пробы:

| Действие | Что изменилось |
| --- | --- |
| `copy.Clear()` | Только копия. Внутренний `_heroes` цел |
| `again[0].TakeDamage(50)` | Сам герой. В копии лежала ссылка на тот же объект |

`GetMembers` защищает **состав**, но не делает героев неприкасаемыми. Героя по-прежнему защищает `Hero`: его здоровье меняется только через его методы.

![Два списка — одни и те же герои](/materials/guild-of-heroes/img/lab05/schema-03-copy-not-clone.webp)

Выключите пробу и очистите `Run`.

### 9. Трассировка: предскажите вывод

**Не запускайте сразу.** Фрагмент — на учебных объектах:

```csharp
Guild traceGuild = new Guild("Трассировка");
Hero first = new Hero("Первый", 100);
Hero second = new Hero("Второй", 80);

Console.WriteLine(traceGuild.AddHero(first));
Console.WriteLine(traceGuild.AddHero(new Hero(" пЕРВЫЙ ", 50)));
Console.WriteLine(traceGuild.AddHero(second));

List<Hero> snapshot = traceGuild.GetMembers();
Console.WriteLine(traceGuild.RemoveHero("первый"));

Console.WriteLine(traceGuild.MemberCount);
Console.WriteLine(snapshot.Count);

Hero? found = traceGuild.FindHeroByName("Первый");
Console.WriteLine(found == null);
```

1. Запишите в README предполагаемый вывод — **все семь строк**.
2. Ответьте: сколько объектов `Hero` создано в этом фрагменте? Сколько из них в итоге в гильдии?
3. Почему `snapshot.Count` не совпадает с `MemberCount`?
4. Вставьте фрагмент в `Probe.Run`, запустите, сравните. Где ошиблись — объясните.

<details>
<summary>Самопроверка — после запуска</summary>

```text
True
False
True
True
1
2
True
```

Объектов три: `new Hero` встречается три раза. Второй был создан, но гильдия его не приняла — отказ не уничтожает объект, он просто не попал в состав. В гильдии остался один — «Второй». `snapshot` — копия, снятая **до** удаления, поэтому в ней по-прежнему двое.

```csharp
public class Guild {
    private List<Hero> _heroes = new List<Hero>();

    public string Name { get; private set; }

    public int MemberCount {
        get { return _heroes.Count; }
    }

    public Guild(string name) {
        Name = name;
    }

    public bool AddHero(Hero hero) {
        if (FindHeroByName(hero.Name) != null) {
            return false;
        }

        _heroes.Add(hero);
        return true;
    }

    public Hero? FindHeroByName(string name) {
        if (string.IsNullOrWhiteSpace(name)) {
            return null;
        }

        string searchName = name.Trim();

        foreach (Hero hero in _heroes) {
            if (string.Equals(hero.Name, searchName, StringComparison.OrdinalIgnoreCase)) {
                return hero;
            }
        }

        return null;
    }

    public bool RemoveHero(string name) {
        Hero? hero = FindHeroByName(name);
        if (hero == null) {
            return false;
        }
        return _heroes.Remove(hero);
    }

    public List<Hero> GetMembers() {
        List<Hero> result = new List<Hero>();
        foreach (Hero hero in _heroes) {
            result.Add(hero);
        }
        return result;
    }

    public int CountHealthy(int minimum) {
        int count = 0;
        foreach (Hero hero in _heroes) {
            if (hero.Health >= minimum) {
                count += 1;
            }
        }
        return count;
    }

    public Hero? FindStrongest() {
        if (_heroes.Count == 0) {
            return null;
        }

        Hero strongest = _heroes[0];
        foreach (Hero hero in _heroes) {
            if (hero.Health > strongest.Health) {
                strongest = hero;
            }
        }
        return strongest;
    }
}
```
