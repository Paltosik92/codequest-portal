## Обязательная часть

### 1. Программа, которая не слушает

Сейчас `Program.cs` — сценарий. Он делает одно и то же при каждом запуске. Чтобы назначить №105 Сергею, нужно дописать строку в код и запустить снова. Человеку у окна так не объяснишь.

Попробуем просто спросить номер. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Console.Write("Номер поручения: ");
    string? text = Console.ReadLine();
    int questId = int.Parse(text);
    Console.WriteLine($"Принят номер {questId}");
}
```

Ещё до запуска компилятор выдаст **предупреждение** у `int.Parse(text)`: «возможно, передаётся `null`». Запомните его — вернёмся в шаге 4.

Включите пробу и запустите дважды:

- введите `105` — «Принят номер 105»;
- введите `сто пять` — программа **падает** с ошибкой `FormatException`.

`int.Parse` умеет только одно: превратить правильную запись числа в число. На всё остальное он отвечает аварийной остановкой. Человек у окна может ввести что угодно — и окно не должно от этого ломаться.

![int.Parse читает «сто пять» и падает в обморок](/materials/guild-of-heroes/img/lab09/meme-01-parse-faint.webp)

Выключите пробу и очистите `Run`.

### 2. TryParse и out

Для ввода есть безопасный родственник — `int.TryParse`. Он **пытается** разобрать строку и отвечает `true` или `false`, а само число возвращает через параметр с ключевым словом **`out`**.

```csharp
bool ok = int.TryParse("105", out int number);
```

- `ok` — получилось ли;
- `number` — число, если получилось, и `0`, если нет.

**`out`** означает: метод **обязан** записать значение в эту переменную, и после вызова им можно пользоваться. Запись `out int number` сразу объявляет переменную прямо в вызове. Приставка `Try` — та же договорённость, что у наших `TryAssign` и `TryComplete`: попытка с ответом «да/нет» вместо падения.

Проверим на разных вводах. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    string[] inputs = { "105", " 105 ", "сто пять", "", "-3", "99999999999" };
    foreach (string input in inputs) {
        bool ok = int.TryParse(input, out int number);
        Console.WriteLine($"«{input}» → {ok}, {number}");
    }
}
```

**До запуска** запишите ожидание для каждой строки. Затем запустите:

```text
>>> Проба <<<
«105» → True, 105
« 105 » → True, 105
«сто пять» → False, 0
«» → False, 0
«-3» → True, -3
«99999999999» → False, 0
```

Три вывода:

- пробелы по краям `TryParse` прощает;
- число, которое не помещается в `int`, — тоже отказ, без падения;
- `-3` — **правильная запись числа**, но не номер поручения. Проверку «номер больше нуля» придётся сделать самим.

Выключите пробу и очистите `Run`.

### 3. Класс окна приёма

Окно приёма — отдельный объект. Ему нужны гильдия и доска, чтобы спрашивать у них данные и передавать им команды. Создайте `GuildConsole.cs`:

```csharp
public class GuildConsole {
    private readonly Guild _guild;
    private readonly QuestBoard _board;
    private bool _isRunning;

    public GuildConsole(Guild guild, QuestBoard board) {
        _guild = guild;
        _board = board;
        _isRunning = false;
    }
}
```

Знакомый образец из №6: окно **получает** готовые гильдию и доску через конструктор и хранит ссылки в `private readonly` полях. Окно не создаёт свой мир — оно работает с тем, который ему дали.

`_isRunning` — не `readonly`: оно будет меняться. Это признак «окно открыто». Пока он `true`, окно принимает людей.

### 4. Цикл, меню и конец ввода

Добавьте в `GuildConsole` метод запуска и четыре помощника:

```csharp
public void Run() {
    Console.WriteLine($">>> {_guild.Name}: окно приёма открыто <<<");
    _isRunning = true;

    while (_isRunning) {
        ShowMenu();
        string? choice = ReadInput("Пункт: ");
        if (choice == null) {
            Console.WriteLine();
            _isRunning = false;
        } else {
            HandleChoice(choice);
        }
    }

    Console.WriteLine("Окно приёма закрыто.");
}

private void ShowMenu() {
    Console.WriteLine();
    Console.WriteLine(">>> Окно приёма <<<");
    Console.WriteLine("1 Состав · 2 Поручения · 3 Назначить · 4 Завершить · 0 Выход");
}

private void HandleChoice(string choice) {
    switch (choice.Trim()) {
        case "1":
            ShowMembers();
            break;
        case "2":
            ShowQuests();
            break;
        case "3":
            AssignQuest();
            break;
        case "4":
            CompleteQuest();
            break;
        case "0":
            _isRunning = false;
            break;
        default:
            Console.WriteLine("Нет такого пункта.");
            break;
    }
}

private string? ReadInput(string prompt) {
    Console.Write(prompt);
    return Console.ReadLine();
}
```

Компилятор пока подчеркнёт четыре метода, которых ещё нет, — напишем их в шагах 5 и 6.

Разберём по частям.

**Цикл `while (_isRunning)`** крутится, пока окно открыто. Закрыть его можно двумя способами: пункт `0` или конец ввода. Оба просто ставят `_isRunning = false` — и цикл заканчивается на следующей проверке условия.

**`switch` по строке** выбирает действие. Каждая ветка заканчивается `break`. Внимание: этот `break` выходит **из `switch`**, а не из цикла. Поэтому для выхода мы меняем `_isRunning`, а не пишем `break`.

**`default`** ловит всё остальное: `7`, `да`, пустую строку.

**`string?` и `null`.** `Console.ReadLine()` возвращает `string?`. `null` приходит, когда ввод **закончился**: пользователь нажал `Ctrl+Z` и `Enter` в терминале Windows или данные пришли из файла и кончились. Читать дальше нечего — честнее закрыть окно, чем крутить меню бесконечно. Это и было предупреждение из шага 1: `int.Parse(null)` — ещё одна причина упасть.

`ReadInput` прячет пару «напечатать подсказку — прочитать строку» в одно место. Методы-помощники `private`: снаружи окну нужен только `Run`.

![Цикл окна: меню → ввод → null? → switch → снова меню](/materials/guild-of-heroes/img/lab09/schema-01-console-loop.webp)

### 5. Пункты «Состав» и «Поручения»

Добавьте в `GuildConsole`:

```csharp
private void ShowMembers() {
    foreach (Hero hero in _guild.GetMembers()) {
        Console.WriteLine($"{hero.Name}: здоровье {hero.Health}, уровень {hero.Level}, опыт {hero.Experience}");

private void ShowQuests() {
    List<Quest> quests = _board.GetQuests();
    if (quests.Count == 0) {
```

### 6. Пункты «Назначить» и «Завершить»

Для назначения окну нужно спросить у человека номер и имя. Номер — строка, которую надо превратить в число и проверить, что оно больше нуля. Это нужно в нескольких пунктах, поэтому вынесем в отдельный помощник:

```csharp
private static bool TryParseQuestId(string text, out int questId) {
    if (!int.TryParse(text, out questId)) {
        return false;
    }
    return questId > 0;
}
```

Метод сам устроен как `TryParse`: ответ `bool` и число через `out`. Здесь `out questId` передаётся дальше, в `int.TryParse`, — он и запишет значение.

**`static`** — метод принадлежит классу, а не конкретному окну: он не читает и не меняет ни одного поля (`_guild`, `_board`, `_isRunning`). Ему нужно только то, что пришло в параметрах. Подробно о `static` — в №10.

Теперь сами пункты:

```csharp
private void AssignQuest() {
    string? idText = ReadInput("Номер поручения: ");
    if (idText == null) {
        _isRunning = false;
        return;
    }
    if (!TryParseQuestId(idText, out int questId)) {
        Console.WriteLine("Номер — это число, например 105.");
        return;
    }

    string? heroName = ReadInput("Имя исполнителя: ");
    if (heroName == null) {
        _isRunning = false;
        return;
    }

    if (_board.TryAssign(questId, heroName)) {
        Console.WriteLine("Назначено.");
    } else {
        Console.WriteLine("Отказ: проверьте номер, имя, состояние поручения и занятость героя.");
    }
}

private void CompleteQuest() {
    string? idText = ReadInput("Номер поручения: ");
    if (idText == null) {
        _isRunning = false;
        return;
    }
    if (!TryParseQuestId(idText, out int questId)) {
        Console.WriteLine("Номер — это число, например 105.");
        return;
    }

    if (_board.TryComplete(questId)) {
        Console.WriteLine("Завершено.");
    } else {
        Console.WriteLine("Отказ: поручение не найдено или не назначено.");
    }
}
```

Каждый ввод проверяется сразу: конец ввода — закрыть окно; не число — объяснить и вернуться в меню. Имя окно **не** обрабатывает: пробелы и регистр уже умеет `Guild.FindHeroByName`, а занятость и состояние — доска.

### 8. Граница: окно спрашивает, модель решает

Посмотрите, чего **нет** в `GuildConsole`:

- нет проверки здоровья, занятости и состояния поручения;
- нет поиска героя по имени;
- нет начисления опыта.

Окно проверяет только **форму** ввода: пришло ли что-то вообще и похоже ли это на номер. А **правила** — может ли этот герой взять это дело — живут в `Quest` и `QuestBoard`, как и раньше.

Почему это важно? Представьте, что в `AssignQuest` кто-то добавил:

```csharp
if (heroName.Trim() == "Сергей" && questId == 105) {
    Console.WriteLine("Сергей занят.");
    return;
}
```

Теперь правило «занят» записано в двух местах: на доске (`IsAssigned`) и в окне. Завтра доска его изменит, а окно — нет. И в окне, и в будущих отчётах, и в сохранении (это всё ещё впереди) правило должно быть **одним**. Окно — граница: снаружи человек и строки, внутри — объекты и их правила.

![Граница: окно проверяет форму ввода, модель проверяет правила](/materials/guild-of-heroes/img/lab09/schema-02-boundary.webp)

Ответы окна пока общие: «Отказ: проверьте номер, имя…». Почему именно отказ — доска не сообщает, она отвечает только `false`. Как модель может объяснить причину — тема №16.

### 9. Трассировка: предскажите вывод

Это не окно, а маленькая модель его цикла: вместо ввода — массив готовых команд.

**Не запускайте сразу.**

```csharp
string[] commands = { "2", "x", "1", "0", "1" };
int index = 0;
bool running = true;
int total = 0;

while (running && index < commands.Length) {
    string command = commands[index];
    index++;

    switch (command) {
        case "1":
            total += 10;
            break;
        case "2":
            total += 5;
            break;
        case "0":
            running = false;
            break;
        default:
            Console.WriteLine($"Нет пункта {command}");
            break;
    }
}

Console.WriteLine($"total = {total}, index = {index}");
```

2. Сколько раз выполнилось тело цикла? Почему последняя команда `"1"` не прибавила 10?
3. Что изменится, если в ветке `"0"` вместо `running = false;` оставить только `break;`?
4. Вставьте фрагмент в `Probe.Run`, запустите, сравните.

<details>
<summary>Открыть после самостоятельного шага</summary>

```csharp
public class GuildConsole {
    private readonly Guild _guild;
    private readonly QuestBoard _board;
    private bool _isRunning;

    public GuildConsole(Guild guild, QuestBoard board) {
        _guild = guild;
        _board = board;
        _isRunning = false;
    }

    public void Run() {
        Console.WriteLine($">>> {_guild.Name}: окно приёма открыто <<<");
        _isRunning = true;

        while (_isRunning) {
            ShowMenu();
            string? choice = ReadInput("Пункт: ");
            if (choice == null) {
                Console.WriteLine();
                _isRunning = false;
            } else {
                HandleChoice(choice);
            }
        }

        Console.WriteLine("Окно приёма закрыто.");
    }

    private void ShowMenu() {
        Console.WriteLine();
        Console.WriteLine(">>> Окно приёма <<<");
        Console.WriteLine("1 Состав · 2 Поручения · 3 Назначить · 4 Завершить · 5 Журнал №201 · 6 Отменить · 0 Выход");
    }

    private void HandleChoice(string choice) {
        switch (choice.Trim()) {
            case "1":
                ShowMembers();
                break;
            case "2":
                ShowQuests();
                break;
            case "3":
                AssignQuest();
                break;
            case "4":
                CompleteQuest();
                break;
            case "5":
                ShowObservations();
                break;
            case "6":
                CancelQuest();
                break;
            case "0":
                _isRunning = false;
                break;
            default:
                Console.WriteLine("Нет такого пункта.");
                break;
        }
    }

    private string? ReadInput(string prompt) {
        Console.Write(prompt);
        return Console.ReadLine();
    }

    private static bool TryParseQuestId(string text, out int questId) {
        if (!int.TryParse(text, out questId)) {
            return false;
        }
        return questId > 0;
    }

    private void ShowMembers() {
        foreach (Hero hero in _guild.GetMembers()) {
            Console.WriteLine($"{hero.Name}: здоровье {hero.Health}, уровень {hero.Level}, опыт {hero.Experience}");
        }
    }

    private void ShowQuests() {
        List<Quest> quests = _board.GetQuests();
        if (quests.Count == 0) {
            Console.WriteLine("Поручений нет.");
            return;
        }

        foreach (Quest quest in quests) {
            Console.WriteLine(quest.GetInfo());
        }
    }

    private void AssignQuest() {
        string? idText = ReadInput("Номер поручения: ");
        if (idText == null) {
            _isRunning = false;
            return;
        }
        if (!TryParseQuestId(idText, out int questId)) {
            Console.WriteLine("Номер — это число, например 105.");
            return;
        }

        string? heroName = ReadInput("Имя исполнителя: ");
        if (heroName == null) {
            _isRunning = false;
            return;
        }

        if (_board.TryAssign(questId, heroName)) {
            Console.WriteLine("Назначено.");
        } else {
            Console.WriteLine("Отказ: проверьте номер, имя, состояние поручения и занятость героя.");
        }
    }

    private void CompleteQuest() {
        string? idText = ReadInput("Номер поручения: ");
        if (idText == null) {
            _isRunning = false;
            return;
        }
        if (!TryParseQuestId(idText, out int questId)) {
            Console.WriteLine("Номер — это число, например 105.");
            return;
        }

        if (_board.TryComplete(questId)) {
            Console.WriteLine("Завершено.");
        } else {
            Console.WriteLine("Отказ: поручение не найдено или не назначено.");
        }
    }

    private void ShowObservations() {
        Expedition? expedition = _board.FindExpedition(201);
        if (expedition == null) {
            Console.WriteLine("Экспедиция №201 не найдена.");
            return;
        }

        Console.WriteLine($"Экспедиция №{expedition.Id} «{expedition.Name}», записей: {expedition.CountObservations()}");
        foreach (string record in expedition.GetObservations()) {
            Console.WriteLine($"- {record}");
        }
    }

    private void CancelQuest() {
        string? idText = ReadInput("Номер поручения: ");
        if (idText == null) {
            _isRunning = false;
            return;
        }
        if (!TryParseQuestId(idText, out int questId)) {
            Console.WriteLine("Номер — это число, например 105.");
            return;
        }

        if (_board.TryCancel(questId)) {
            Console.WriteLine("Отменено.");
        } else {
            Console.WriteLine("Отказ: поручение не найдено, уже выполнено или отменено.");
        }
    }
}
```

### Приложение Б. Если что-то не так

| Признак | Что проверить |
| --- | --- |
| Программа падает на «сто пять» | Где-то остался `int.Parse` вместо `TryParseQuestId` |
| Предупреждение о `null` у `ReadLine` | Результат хранится в `string`, а не в `string?`, или нет проверки на `null` |
| Пункт `0` возвращает в меню | В ветке `"0"` нет `_isRunning = false` |
| Запуск через `printf` зависает или печатает меню без конца | В `Run` нет обработки `choice == null` |
| После назначения список показывает «открыто» | Мир или доска создаются внутри цикла или внутри метода окна |
| `-3` принимается как номер | В `TryParseQuestId` нет проверки `questId > 0` |
| Имя « сергей » не находится | Окно передаёт в доску не то, что ввёл человек, или поиск в `Guild` изменён |
| Пункт 5: «не найдена» | Экспедиция не зарегистрирована через `board.AddExpedition` в истории |
| Ошибка компиляции у `TryParseQuestId` | Метод `static` пытается читать `_board` или `_guild` |
