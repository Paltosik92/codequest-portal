## Цель и результат

После этой работы вы:

- объявите константу `const` — правило «сколько опыта на уровень», одинаковое для всех героев;
- научите героя пересчитывать уровень при получении опыта;
- различите, что принадлежит **объекту** (опыт Сергея), а что — **классу** (порог уровня для всех);
- создадите **статический класс** `WorldSetup` с методом `Create`, который готовит мир;
- соберёте мир в объект `GuildWorld` со свойствами только для чтения;
- сократите `Program.cs` до трёх строк основного сценария.

**Результат:** Сергей с 50 опыта — на втором уровне; подготовка мира живёт в `WorldSetup.Create()`, а `Program` только создаёт мир и открывает окно.

## Обязательная часть

### 1. Уровень не растёт

Проверим на учебном герое. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Hero trainee = new Hero("Учебный герой", 100);
    trainee.GainExperience(120);
    Console.WriteLine($"Опыт: {trainee.Experience}, уровень: {trainee.Level}");
}
```

Включите пробу и запустите:

```text
>>> Проба <<<
Опыт: 120, уровень: 1
```

`Level` получил значение `1` в конструкторе в №3 — и с тех пор его никто не менял. Свойство есть, правила нет.

Где это правило должно жить? Не в окне и не в `Program`: уровень — состояние героя, а «сколько опыта на уровень» — правило для **всех** героев. Значит, в классе `Hero`.

Выключите пробу и очистите `Run`.

### 2. Константа и пересчёт уровня

Откройте `Hero.cs`. Первой строкой внутри класса, до `_name`, добавьте:

```csharp
public const int ExperiencePerLevel = 50;
```

**`const`** — константа: значение задаётся один раз прямо в объявлении, известно уже при компиляции и **никогда** не меняется. Попытка написать `ExperiencePerLevel = 40;` где угодно — ошибка компиляции.

Константа принадлежит **классу**, а не отдельному герою: порог один на всех. Поэтому снаружи к ней обращаются через имя класса — `Hero.ExperiencePerLevel`, как к `int.MaxValue` в №6. Внутри `Hero` можно писать просто `ExperiencePerLevel`.

Зачем константа, если можно написать `50`? Число «50» без имени ничего не говорит. А `ExperiencePerLevel` объясняет себя — и если Елена изменит устав, править придётся одну строку.

Теперь дополните `GainExperience`:

```csharp
public void GainExperience(int amount) {
    if (!CanGainExperience(amount)) {
        return;
    }

    Experience += amount;
    Level = 1 + Experience / ExperiencePerLevel;
}
```

Деление `int` на `int` — целочисленное: остаток отбрасывается.

| Опыт | `Experience / 50` | `Level` |
| --- | --- | --- |
| 0 | 0 | 1 |
| 15 | 0 | 1 |
| 49 | 0 | 1 |
| 50 | 1 | 2 |
| 120 | 2 | 3 |

`1 +` нужна потому, что уровни начинаются с первого, а не с нулевого.

Уровень пересчитывается **в одном месте** — там, где меняется опыт. Других способов изменить опыт у героя нет (`private set`), поэтому уровень не может «отстать».

![Границы уровней по 50 опыта и пересчёт Level сразу после успешного изменения Experience](/materials/guild-of-heroes/img/lab10/schema-05-level-boundaries.webp)

Запустите программу и выберите `1`:

### 3. Что принадлежит объекту, а что — классу

У каждого героя свой опыт: у Сергея 50, у Ярослава 15. А порог уровня — один на всех. Проверим. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Hero first = new Hero("Первый", 100);
    Hero second = new Hero("Второй", 100);
    first.GainExperience(120);

    Console.WriteLine($"{first.Name}: опыт {first.Experience}, уровень {first.Level}");
    Console.WriteLine($"{second.Name}: опыт {second.Experience}, уровень {second.Level}");
    Console.WriteLine($"Порог уровня: {Hero.ExperiencePerLevel}");
}
```

Запустите:

```text
>>> Проба <<<
Первый: опыт 120, уровень 3
Второй: опыт 0, уровень 1
Порог уровня: 50
```

Теперь допишите в пробу строку и посмотрите на ошибку компиляции:

```csharp
Console.WriteLine(first.ExperiencePerLevel);
```

Компилятор скажет: к этому члену нельзя обращаться через экземпляр — используйте имя типа. Константа не «лежит» в объекте `first`. Она принадлежит классу. Удалите строку.

| Чьё | Пример | Как обращаться |
| --- | --- | --- |
| Объекта (экземпляра) | `Experience`, `Level`, `Name`, `GainExperience` | `sergey.Experience`, `first.GainExperience(120)` |
| Класса | `ExperiencePerLevel`, `int.MaxValue`, `int.TryParse` | `Hero.ExperiencePerLevel`, `int.TryParse(...)` |

![У каждого героя свой опыт, а порог уровня — один на класс](/materials/guild-of-heroes/img/lab10/schema-01-object-vs-class.webp)

Члены класса, которые не принадлежат объекту, называются **статическими** — `static`. Константа `const` всегда статическая сама по себе, писать `static` рядом с ней не нужно (и нельзя).

Выключите пробу и очистите `Run`.

### 4. Мир — в один объект

Откройте `Program.cs`. Основной сценарий — это почти полсотни строк: пять героев, гильдия, история поручений, экспедиция, №105. И только две последние строки — работа программы: создать окно и запустить.

Подготовка мира — отдельная задача. Вынесем её.

Такое изменение называется **рефакторингом**: меняется устройство кода, а поведение программы должно остаться прежним. «Должно» — значит, надо проверить. Перед переносом сохраните текущий вывод в файл. В Git Bash, в папке проекта:

```bash
printf '2\n5\n' | dotnet run > before.txt
```

Программа получит пункты `2` и `5`, закроется по концу ввода, а всё, что она напечатала, окажется в файле `before.txt`. После переноса мы сравним с ним новый вывод. Но сначала: что должна **вернуть** подготовка? Окну нужны гильдия и доска. Соберём их в один объект `GuildWorld` — он и будет возвращаемым значением метода.

Создайте `GuildWorld.cs`:

```csharp
public class GuildWorld {
    public Guild Guild { get; }
    public QuestBoard Board { get; }

    public GuildWorld(Guild guild, QuestBoard board) {
        Guild = guild;
        Board = board;
    }
}
```

Свойство с одним `get` и без `set` — свойство **только для чтения**. Присвоить ему значение можно только в конструкторе, дальше — никогда, даже изнутри класса. Это то же обещание, что `readonly` у поля из №6, но для свойства: мир собран один раз и подменить в нём гильдию или доску нельзя.

Свойство `Guild` типа `Guild` — нормальная запись в C#: имя свойства совпадает с именем класса. Компилятор различает их по месту.

### 5. Статический класс WorldSetup

Кто будет готовить мир? Нужен метод `Create`, который создаёт героев, гильдию, доску, историю — и возвращает `GuildWorld`. Нужен ли для этого объект «подготовщика»? Нет: у подготовки нет своего состояния, ей нечего хранить между вызовами. Ей нужен только код.

Для этого в C# есть **статический класс**. Создайте `WorldSetup.cs`:

```csharp
public static class WorldSetup {
    public static GuildWorld Create() {
        // сюда переедет подготовка мира
    }
}
```

**`static class`** — класс, у которого не бывает объектов. Написать `new WorldSetup()` нельзя — ошибка компиляции. Все его члены тоже должны быть `static`. Вызывают их через имя класса: `WorldSetup.Create()`.

Вы уже пользовались статическими классами: `Console` (`Console.WriteLine`) и наш `Probe` (`Probe.Run`). В №9 появился статический **метод** в обычном классе — `TryParseQuestId`: он не трогал поля окна.

Теперь перенос. Из `Program.cs` **вырежьте** всё от строки `Hero yaroslav = ...` до строки с `new Quest(105, ...)` включительно и вставьте в тело `Create` вместо комментария. В конце метода добавьте:

```csharp
return new GuildWorld(guild, board);
```

Начало и конец метода после переноса:

```csharp
public static GuildWorld Create() {
    Hero yaroslav = new Hero("Ярослав", 100);
    Hero anastasia = new Hero("Анастасия", 90);
    Hero artem = new Hero("Артём", 120);
    Hero alexander = new Hero("   Александр   ", 150);
    Hero sergey = new Hero("Сергей", 110);

    // ... гильдия, доска, история №101–104, экспедиция №201 ...

    board.AddQuest(new Quest(105, "Сверить адрес доставки", 100, 10));

    return new GuildWorld(guild, board);
}
```

Переменные `yaroslav`, `guild`, `board` теперь **локальные** переменные метода `Create`. Они существуют, пока метод работает. А объекты, на которые они ссылаются, живут дальше — потому что метод отдаёт ссылки на них наружу через `GuildWorld`.

### 7. Когда static, а когда нет

Посмотрите на весь проект целиком.

| Член | static? | Почему |
| --- | --- | --- |
| `Hero.ExperiencePerLevel` | да (`const`) | одно правило для всех героев |
| `Hero.GainExperience` | нет | меняет опыт **этого** героя |
| `GuildConsole.TryParseQuestId` | да | работает только с параметрами, полей не трогает |
| `GuildConsole.AssignQuest` | нет | использует `_board` и `_isRunning` этого окна |
| `WorldSetup.Create` | да | готовит новый мир, хранить между вызовами нечего |
| `QuestBoard.TryAssign` | нет | работает со списками **этой** доски |

Правило: член делают статическим, если ему **не нужно** состояние конкретного объекта. Если метод читает или меняет поля конкретного экземпляра — он принадлежит объекту. Статический метод может обращаться к статическим членам класса.

Проверьте ограничение статического класса сами: напишите в `Probe.Run` строку

```csharp
WorldSetup setup = new WorldSetup();
```

Прочитайте ошибку компиляции — у статического класса не может быть экземпляров. Удалите строку.

В нашей реализации каждый вызов `WorldSetup.Create()` строит **новый** мир — новых героев, новую доску. В этой версии `WorldSetup` нет статического состояния: все созданные объекты отдаются наружу через `GuildWorld`. Новый мир появляется благодаря вызовам `new` внутри метода, а не самому слову `static`.

### 8. Обещания «не менять»: const и readonly

В проекте теперь три способа сказать «это не меняется».

| Запись | Где | Когда задаётся | Одинаково для всех объектов? |
| --- | --- | --- | --- |
| `const int ExperiencePerLevel = 50;` | `Hero` | в объявлении, при компиляции | да |
| `private readonly Guild _guild;` | `QuestBoard`, `GuildConsole` | в объявлении или конструкторе | нет: у каждой доски своя гильдия |
| `public Guild Guild { get; }` | `GuildWorld` | в конструкторе | нет: у каждого мира свои |

`const` — для чисел и строк, известных заранее: порог уровня, предел здоровья. `readonly` и свойства только для чтения — для ссылок на объекты, которые объект получает при рождении и хранит до конца.

![GuildWorld хранит неизменные ссылки на гильдию и доску, а их методы продолжают менять состояние модели](/materials/guild-of-heroes/img/lab10/schema-04-readonly-reference.webp)

<summary>Самопроверка — после своей попытки</summary>

1. `static` сделал опыт одним на **класс**: 30 (№101) + 20 (№103) + 15 (№104) = 65 — общая сумма. А `Level` остался у каждого свой и пересчитывался только у того, кто получал награду, в момент получения: у Сергея после №103 общий опыт был 50 → уровень 2; у Ярослава после №104 — 65 → уровень 2. Остальные награды не получали — уровень 1 из конструктора. Исправление: убрать `static` и вернуть `hero.Experience`.
2. Нет `1 +`: 50 / 50 = 1, 15 / 50 = 0. Анастасия опыта не получала — `GainExperience` у неё не вызывался, и остался уровень 1 из конструктора. Исправление: `Level = 1 + Experience / ExperiencePerLevel;`.

public class Hero {
    public const int ExperiencePerLevel = 50;
    public const int MaxHealthLimit = 200;
    public const int DefaultMaxHealth = 100;

    private string _name = "Безымянный герой";

    public string Name {
        get {
            return _name;
        }

        private set {
            if (string.IsNullOrWhiteSpace(value)) {
                _name = "Безымянный герой";
                return;
            }

            _name = value.Trim();
        }
    }

    public int Health { get; private set; }
    public int MaxHealth { get; private set; }
    public int Level { get; private set; }
    public int Experience { get; private set; }

    public int ExperienceToNextLevel {
        get {
            return ExperiencePerLevel - Experience % ExperiencePerLevel;
        }
    }

    public Hero(string name, int health) {
        Name = name;

        MaxHealth = health;

        if (MaxHealth <= 0) {
            MaxHealth = DefaultMaxHealth;
        }

        if (MaxHealth > MaxHealthLimit) {
            MaxHealth = MaxHealthLimit;
        }

        Health = health;

        if (Health < 0) {
            Health = 0;
        }

        if (Health > MaxHealth) {
            Health = MaxHealth;
        }

        Level = 1;
        Experience = 0;
    }

    // TakeDamage, Heal, CanGainExperience, IsAlive, GetInfo — без изменений

    public void GainExperience(int amount) {
        if (!CanGainExperience(amount)) {
            return;
        }

        Experience += amount;
        Level = 1 + Experience / ExperiencePerLevel;
    }
}
