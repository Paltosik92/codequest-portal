## Обязательная часть

### 1. Программа знает только героев

У Александра, Анастасии и Артёма разная работа. Воин сдвигает завалы, маг читает печати, лучник достаёт до высоты. Как сказать это программе?

| Способ | Как выглядит | Что плохо |
| --- | --- | --- |
| Строка-профессия | `public string Role` в `Hero` и `if (hero.Role == "Воин")` | Опечатка «воин» молча ломает проверку; все умения всех профессий лежат в одном классе |
| Скопировать класс | `Warrior` — копия `Hero` на 130 строк плюс одно умение | Исправили ошибку в `Hero` — забыли в трёх копиях |
| **Наследование** | `class Warrior : Hero` — воин **является** героем и добавляет своё | — |

Воин — это герой: у него есть имя, здоровье, уровень, опыт, он получает урон и награды. Всё это уже написано в `Hero`. Наследование позволяет сказать: «`Warrior` — это `Hero`, плюс вот это». Общий код остаётся в одном месте.

Но наследование уместно не всегда. Проверка простая — фраза «X **является** Y» должна быть правдой всегда, а не «иногда похож»:

| Утверждение | Правда? | Наследовать? |
| --- | --- | --- |
| Воин является героем | да | `Warrior : Hero` |
| Маг является героем | да | `Mage : Hero` |
| Маг является воином | нет | нет — это разные профессии одного уровня |
| Экспедиция является гильдией | нет | нет — у экспедиции **есть** участники (№8), это другая связь |
| Насос является героем | нет | нет — у насоса нет здоровья и опыта, хоть он и помогает |

Если фраза звучит как «у X **есть** Y» — это не наследование, а агрегация или композиция из №8.

### 2. Выучка — общее для всех

Сначала то, что есть у **любого** героя: выучка — насколько хорошо он знает своё дело, от 1 до 10. Это не профессия, а мера мастерства, поэтому её место — в `Hero`.

Откройте `Hero.cs`. Рядом с другими константами добавьте:

```csharp
public const int MaxTraining = 10;
```

Рядом с `Level` и `Experience` — свойство:

```csharp
public int Training { get; private set; }
```

Теперь конструктор. Сейчас он принимает имя и здоровье. Добавьте третий параметр — **замените** заголовок конструктора и допишите в конец тела три проверки:

```csharp
public Hero(string name, int health, int training) {
    // ... всё, что было: Name, MaxHealth, Health, Level, Experience ...

    Training = training;
    if (Training < 1) {
        Training = 1;
    }
    if (Training > MaxTraining) {
        Training = MaxTraining;
    }
}
```

Сохраните — и проект перестанет собираться. Во `WorldSetup`, в `Probe` и в личном проекте осталось `new Hero("Сергей", 110)` с **двумя** аргументами, а такого конструктора больше нет.

Можно исправить каждый вызов. Но правильнее вернуть старый конструктор — и пусть он просто **передаёт работу** новому. Добавьте в `Hero` ещё один конструктор:

```csharp
public Hero(string name, int health) : this(name, health, 1) {
}
```

**`: this(...)`** после заголовка конструктора — вызов **другого конструктора того же класса**. Сначала выполнится `Hero(name, health, 1)` со всеми проверками, потом — тело этого конструктора (у нас оно пустое). Правила создания героя по-прежнему написаны один раз.

Теперь у `Hero` два конструктора — это **перегрузка**: одно имя, разные списки параметров. Компилятор выбирает нужный по аргументам: `new Hero("Сергей", 110)` — двухпараметровый, выучка 1.

Соберите и запустите: всё как в №10.

### 3. Первый наследник: воин

Создайте файл `Warrior.cs`:

```csharp
public class Warrior : Hero {
    public Warrior(string name, int health, int training) : base(name, health, training) {
    }

    public int PushObstacle() {
        return Training * 2;
    }
}
```

Разберём по частям.

**`class Warrior : Hero`** — `Warrior` **наследует** `Hero`. `Hero` — базовый класс (родитель), `Warrior` — производный (наследник). Наследник получает все открытые свойства и методы родителя: `Name`, `Health`, `Level`, `Experience`, `Training`, `TakeDamage`, `Heal`, `GainExperience`, `GetInfo`…

**Конструкторы не наследуются.** У `Warrior` должен быть свой. Но создавать героя — работа `Hero`: проверки имени, здоровья, выучки уже написаны там. Поэтому конструктор воина сразу передаёт данные родителю.

**`: base(name, health, training)`** — вызов конструктора **базового** класса. Похоже на `this(...)`, но `this` зовёт соседний конструктор этого же класса, а `base` — конструктор родителя. Сначала отработает `Hero(name, health, training)`, потом — тело конструктора `Warrior` (пока пустое).

**`PushObstacle`** — умение, которого у обычного героя нет: с какой силой воин сдвигает завал. Внутри метод читает `Training` — свойство, объявленное в `Hero`. Наследнику оно доступно, как своё.

![Цепочка конструкторов: new Warrior → base(...) → Hero; new Hero(имя, здоровье) → this(..., 1)](/materials/guild-of-heroes/img/lab11/schema-01-constructor-chain.webp)

Короткий словарь этой работы:

| Термин | Что значит | В нашем коде |
| --- | --- | --- |
| Базовый класс (родитель) | класс, от которого наследуют | `Hero` |
| Производный класс (наследник) | класс, который получает всё открытое от базового и добавляет своё | `Warrior`, `Mage` |
| `: Hero` после имени класса | «наследует от» | `class Warrior : Hero` |
| `: base(...)` после конструктора | вызвать конструктор родителя | `: base(name, health, training)` |
| `: this(...)` после конструктора | вызвать другой конструктор этого же класса | `: this(name, health, 1)` |
| Перегрузка | несколько методов или конструкторов с одним именем и разными параметрами | два конструктора `Hero` |

### 4. Что получил наследник

Проверим. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Warrior trainee = new Warrior("Учебный воин", 150, 6);
    trainee.TakeDamage(30);
    trainee.GainExperience(60);

    Console.WriteLine(trainee.GetInfo());
    Console.WriteLine($"Выучка: {trainee.Training}");
    Console.WriteLine($"Сила толчка: {trainee.PushObstacle()}");

    Hero asHero = trainee;
    Console.WriteLine($"Через переменную Hero: {asHero.Name}, здоровье {asHero.Health}");
}
```

Включите пробу и запустите:

```text
>>> Проба <<<
>>> Учебный воин <<<
Здоровье: 120
Уровень: 2
Опыт: 60
Выучка: 6
Сила толчка: 12
Через переменную Hero: Учебный воин, здоровье 120
```

В `Warrior.cs` нет ни `TakeDamage`, ни `GainExperience`, ни `GetInfo` — а они работают. Правило уровня из №10 тоже: 60 опыта — второй уровень.

Последние две строки важны. **`Hero asHero = trainee;`** — воина можно положить в переменную типа `Hero`. Воин **является** героем, поэтому такое присваивание разрешено без всяких преобразований. Это значит: в `List<Hero>` гильдии, в `AddMember(Hero)` экспедиции, в `AssignedHero` поручения можно класть воинов.

Теперь допишите в пробу строку и посмотрите на ошибку компиляции:

```csharp
Console.WriteLine(asHero.PushObstacle());
```

Компилятор скажет: у `Hero` нет метода `PushObstacle`. Объект в переменной — воин, но **тип переменной** — `Hero`, и через неё видно только то, что есть у любого героя. Удалите строку.

Выключите пробу и очистите `Run`.

### 7. Три препятствия — три разных вызова

У прохода три препятствия: завал, печать, высокая площадка. Посчитаем, хватит ли сил, на учебных объектах. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Warrior warrior = new Warrior("Учебный воин", 150, 6);
    Mage mage = new Mage("Учебный маг", 90, 6);

    Console.WriteLine($"Завал: {warrior.PushObstacle()}");
    Console.WriteLine($"Печать: {mage.ReadSeal()}");

    List<Hero> team = new List<Hero>();
    team.Add(warrior);
    team.Add(mage);
    Console.WriteLine($"В отряде: {team.Count}");
}
```

Запустите:

```text
>>> Проба <<<
Завал: 12
Печать: 12
В отряде: 2
```

Работает. Но посмотрите, **как**:

- для завала мы должны знать, что `warrior` — воин, и вызвать именно `PushObstacle`;
- для печати — что `mage` — маг, и вызвать `ReadSeal`;
- в списке `team` оба лежат как `Hero`. Пройти по нему циклом и спросить «что ты можешь сделать с завалом?» нельзя: у `Hero` таких методов нет.

Попробуйте дописать:

```csharp
foreach (Hero member in team) {
    Console.WriteLine(member.PushObstacle());
}
```

Ошибка компиляции — та же, что в шаге 4. Удалите цикл.

Выходит, для каждого препятствия — свой вызов для каждой профессии. Придёт четвёртая профессия — придётся найти и поправить каждое место расчёта. Запомните эту проблему: её решение — тема следующей работы.

![Тип переменной решает, что видно: через Hero умения профессий не видны](/materials/guild-of-heroes/img/lab11/schema-03-variable-type.webp)

### 8. Что наследник может, а что — нет

Наследник получает всё открытое, но правила инкапсуляции родителя продолжают действовать.

| Член `Hero` | Доступен в `Warrior`? | Почему |
| --- | --- | --- |
| `public string Name { get; private set; }` — чтение | да | `get` открыт |
| `Name = ...` — запись | **нет** | `private set` — только внутри `Hero` |
| `private string _name` | **нет** | `private` — только внутри `Hero`, даже наследнику не видно |
| `Training`, `Health` — чтение | да | `get` открыт |
| `TakeDamage`, `GainExperience` | да | открытые методы |
| конструкторы `Hero` | **не наследуются** | у наследника свои; родительский вызывается через `base(...)` |

Попробуйте в `Warrior.PushObstacle` написать `Health = 1000;` — компилятор не даст. Здоровье меняется только через `TakeDamage` и `Heal`, даже у воина. Удалите строку.

Это хорошо: правила `Hero` защищены не только от `Program`, но и от наследников. Воин не может обойти проверку здоровья «изнутри».

![Один объект Warrior хранит унаследованное здоровье; TakeDamage меняет его по правилам Hero, а прямое присваивание в наследнике запрещено](/materials/guild-of-heroes/img/lab11/schema-04-inherited-state.webp)

Проверьте себя — верно или нет? Ответьте в уме, потом откройте.

1. `Mage` может вызвать `GainExperience`, хотя в `Mage.cs` его нет.
2. `Warrior` может прочитать поле `_name`.
3. В `List<Hero>` можно положить и `Warrior`, и `Mage`.
4. Если у `Warrior` нет своего конструктора, он получит конструктор `Hero(name, health, training)`.
5. `new Hero("Сергей", 110)` создаёт героя с выучкой 1.

<details>
<summary>Ответы</summary>

1 — верно: открытые методы наследуются. 2 — неверно: `private` не видно даже наследнику; читать можно свойство `Name`. 3 — верно: воин и маг являются героями. 4 — неверно: конструкторы не наследуются; без своего конструктора компилятор попробует вызвать `Hero()` без параметров — и не найдёт его. 5 — верно: двухпараметровый конструктор передаёт 1 через `this(...)`.

</details>

### 10. Найдите две ошибки

#### Ошибка 1. Второе здоровье

Кто-то решил, что у воина «своё здоровье», и написал:

```csharp

    // конструктор и PushObstacle — как раньше
```

Проект собирается, только с предупреждением. Проба:

```csharp

Hero h = w;

Console.WriteLine(h.Health);
```

Печатает `0` и `150`. Один объект — два разных здоровья? Прочитайте предупреждение компилятора и объясните.

#### Ошибка 2. Безымянный воин

Другой студент забыл `: base(...)`:

```csharp
}
```

Получил ошибку компиляции и «исправил» её — добавил в `Hero` пустой конструктор `public Hero() { }`. Проект собрался. Но `new Warrior("Ярослав", 100, 5).GetInfo()` печатает:

<details>
<summary>Самопроверка — после своей попытки</summary>

1. В `Warrior` объявлено **новое** свойство `Health`, которое скрывает родительское (об этом и предупреждение: «скрывает унаследованный член»). Конструктор `Hero` заполнил родительское `Health` = 150, а новое никто не заполнял — 0. Через переменную `Warrior` видно новое, через `Hero` — родительское. Исправление: удалить свойство из `Warrior` — здоровье уже есть у любого героя.
2. Без `: base(...)` компилятор вызывает конструктор родителя **без параметров**. Его не было — отсюда исходная ошибка. Пустой `Hero()` ничего не присваивает: имя осталось начальным значением поля, числа — нулями, а `Level = 1` стоит в **другом** конструкторе. Исправление: удалить `Hero()` и вернуть `: base(name, health, training)`.
