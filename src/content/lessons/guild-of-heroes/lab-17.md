### 1. Одно правило — один цикл?

Посчитаем порядок канцелярии вручную. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    GuildWorld world = WorldSetup.Create();
    foreach (Hero hero in world.Guild.GetMembers()) {
        if (hero.Health >= 100 && hero.Experience >= 20) {
            Console.WriteLine(hero.Name);
        }
    }
}
```

Включите пробу и запустите:

```text
>>> Проба <<<
Сергей
```

Пропущен один человек. Тот самый, которого вчера отстранили от работ.

Совет тут же попросит: «А если только по здоровью?», «А только по опыту?». Каждый раз — копия того же цикла, в которой меняется **одна** строка — условие в `if`. Всё остальное — обход состава, сбор результата — одинаковое.

Хочется написать отбор **один раз**, а условие передавать в него снаружи — как параметр. Но условие — это не число и не строка. Это **кусок кода**: «возьми героя и ответь да или нет».

Выключите пробу и очистите `Run`.

### 2. Метод в переменной: делегат

В C# метод можно положить в переменную и передать в другой метод. Тип такой переменной называется **делегатом**: он описывает, **какой** метод туда подходит — какие параметры и какой результат.

Сначала — свой делегат, чтобы увидеть, как это устроено. В конец файла `Probe.cs`, **после** класса `Probe`, добавьте одну строку:

```csharp
public delegate bool HeroRule(Hero hero);
```

Это объявление **типа**: «`HeroRule` — любой метод, который принимает `Hero` и возвращает `bool`».

Теперь внутри класса `Probe`, рядом с `Run`, добавьте обычный метод, который подходит под это описание:

```csharp
private static bool IsHealthy(Hero hero) {
    return hero.Health >= 100;
}
```

И проверим. Замените тело `Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    HeroRule rule = IsHealthy;

    GuildWorld world = WorldSetup.Create();
    foreach (Hero hero in world.Guild.GetMembers()) {
        if (rule(hero)) {
            Console.WriteLine(hero.Name);
        }
    }
}
```

Две новые вещи:

- `HeroRule rule = IsHealthy;` — в переменную кладётся **сам метод**, без скобок. Скобки означали бы «вызови сейчас», а нам нужно «запомни, кого вызывать».
- `rule(hero)` — вызов метода, который лежит в переменной. Выглядит как обычный вызов.

Запустите:

```text
>>> Проба <<<
Ярослав
Артём
Александр
Сергей
```

Цикл не знает, **какое** правило внутри `rule`. Положите в `rule` другой подходящий метод — цикл не изменится.

### 3. Готовые делегаты: Func и Action

Объявлять свой делегат для каждой подписи утомительно. В .NET есть готовые:

| Делегат | Что за метод | Пример |
| --- | --- | --- |
| `Func<Hero, bool>` | принимает `Hero`, возвращает `bool` | правило отбора |
| `Func<int, int>` | принимает `int`, возвращает `int` | «удвоить» |
| `Action<Hero>` | принимает `Hero`, ничего не возвращает | «выдать пропуск» |
| `Action<string>` | принимает `string`, ничего не возвращает | «напечатать» |

`Func<…>` — последний тип в угловых скобках всегда **результат**, остальные — параметры. `Action<…>` — только параметры, результата нет (`void`).

Проверьте себя — какой делегат подходит? Ответьте в уме, потом откройте.

1. Метод `int Square(int n)`.
2. Метод `void Greet(Hero hero)`.
3. Метод `bool IsLong(string text)`.
4. Метод `string Describe(Hero hero)`.

<details>
<summary>Ответы</summary>

1 — `Func<int, int>`. 2 — `Action<Hero>`: результата нет. 3 — `Func<string, bool>`. 4 — `Func<Hero, string>`: параметр `Hero`, результат — последний тип.

</details>

`Func<Hero, bool>` описывает ровно то же, что наш `HeroRule`. Замените в пробе:

```csharp
Func<Hero, bool> rule = IsHealthy;
```

Запустите — тот же результат. Теперь **удалите** строку `public delegate bool HeroRule(Hero hero);` из конца `Probe.cs`: свой делегат больше не нужен. Дальше в курсе — только `Func` и `Action`.

### 4. Лямбда-выражение: правило в одну строку

Метод `IsHealthy` — четыре строки ради одного условия. Для таких коротких правил есть запись короче — **лямбда-выражение**:

```csharp
Func<Hero, bool> rule = hero => hero.Health >= 100;
```

Читается: «взять `hero` — вернуть `hero.Health >= 100`».

- слева от `=>` — параметр (имя придумываем сами);
- справа — выражение, значение которого и будет результатом;
- тип параметра компилятор знает из `Func<Hero, bool>`: `hero` — это `Hero`.

Удалите из `Probe` метод `IsHealthy` и замените строку правила на лямбду. Запустите — результат тот же.

Если правило не помещается в одно выражение, у лямбды может быть **тело** в фигурных скобках — как у обычного метода, с `return`:

```csharp
Func<Hero, bool> careful = hero => {
    if (!hero.IsAlive()) {
        return false;
    }
    return hero.Health >= 100;
};
```

Обратите внимание на точку с запятой после закрывающей скобки: вся лямбда — это значение, которое присваивается переменной.

Несколько правил — несколько лямбд:

```csharp
Func<Hero, bool> healthy = hero => hero.Health >= 100;
Func<Hero, bool> experienced = hero => hero.Experience >= 20;
Func<Hero, bool> chancellery = hero => hero.Health >= 100 && hero.Experience >= 20;
```

Выключите пробу и очистите `Run`.

### 5. SelectionService: отбор по любому правилу

Теперь сам отбор — один раз, для всех правил. Создайте `SelectionService.cs`:

```csharp
public static class SelectionService {
    public static List<Hero> Select(List<Hero> heroes, Func<Hero, bool> rule) {
        List<Hero> result = new List<Hero>();
        foreach (Hero hero in heroes) {
            if (rule(hero)) {
                result.Add(hero);
            }
        }
        return result;
    }

    public static void ApplyToSelected(List<Hero> heroes, Func<Hero, bool> rule, Action<Hero> action) {
        foreach (Hero hero in heroes) {
            if (rule(hero)) {
                action(hero);
            }
        }
    }
}
```

`Select` получает список и **правило** — и возвращает тех, кого правило пропустило. Какое правило — `Select` не знает и знать не должен.

`ApplyToSelected` получает ещё и **действие** `Action<Hero>` — и выполняет его для каждого отобранного. Что за действие — решает вызывающий: напечатать, выдать пропуск, записать в журнал.

Класс статический (№10): у отбора нет своего состояния, только работа над тем, что передали.

![Select получает список и правило — и не знает, какое оно](/materials/guild-of-heroes/img/lab17/schema-02-select-with-any-rule.webp)

Проверим сервис на **граничных** героях — тех, кто стоит ровно на пороге. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    List<Hero> edge = new List<Hero>();
    edge.Add(new Warrior("Ровно сто, мало опыта", 100, 5));
    edge.Add(new Mage("Мало здоровья, много опыта", 99, 5));
    edge.Add(new Ranger("Ровно сто, ровно двадцать", 100, 5));
    edge[1].GainExperience(30);
    edge[2].GainExperience(20);

    Func<Hero, bool> chancellery = hero => hero.Health >= 100 && hero.Experience >= 20;
    foreach (Hero hero in SelectionService.Select(edge, chancellery)) {
        Console.WriteLine(hero.Name);
    }
}
```

**До запуска** решите, кто пройдёт. Запустите:

```text
>>> Проба <<<
Ровно сто, ровно двадцать
```

Проходит только тот, у кого **оба** условия выполнены, и `>=` пропускает ровно пороговые значения. Такие граничные примеры — лучший способ проверить правило: на «явно хороших» и «явно плохих» героях почти любое правило выглядит верным.

Выключите пробу и очистите `Run`.

```csharp
private void PrintSelection(string title, Func<Hero, bool> rule) {
    List<Hero> selected = SelectionService.Select(_guild.GetMembers(), rule);

    List<string> names = new List<string>();
    foreach (Hero hero in selected) {
        names.Add(hero.Name);
    }

    string text = "никого";
    if (names.Count > 0) {
        text = string.Join(", ", names);
    }
    Console.WriteLine($"{title}: {text}");

private void ShowAccess() {
    PrintSelection("Порядок канцелярии (здоровье ≥ 100 и опыт ≥ 20)",
                   hero => hero.Health >= 100 && hero.Experience >= 20);
    PrintSelection("Только здоровье ≥ 100", hero => hero.Health >= 100);
    PrintSelection("Только опыт ≥ 20", hero => hero.Experience >= 20);
}
```

`string.Join(", ", names)` склеивает строки списка через запятую с пробелом.

Метод `PrintSelection` получает её как обычный параметр типа `Func<Hero, bool>` и передаёт дальше в `Select`. Окно описывает **правило**, сервис **отбирает**, герои **отвечают** своими свойствами.

### 7. Правило по умению

Порядок канцелярии спрашивает, **сколько у человека здоровья**. А работе у седьмой тяги нужно другое: **может ли он помочь с печатью**. Это мы уже умеем спрашивать у любого героя — `GetContribution` из №12.

Допишите в конец `ShowAccess`:


### 8. Лямбда помнит, где родилась

Вернёмся к захвату. Лямбда `hero => hero.GetContribution(seal) > 0` создана внутри `ShowAccess`, где есть переменная `seal`. Лямбда **запоминает не значение, а саму переменную**. Если до вызова лямбды переменную изменить — лямбда увидит новое значение.

```csharp
int limit = 100;
Func<Hero, bool> strong = hero => hero.Health >= limit;
// ... позже:
limit = 80;
// теперь strong пропускает всех со здоровьем от 80
```

Это удобно — правило можно «настроить» переменной-порогом. И опасно — если забыть, что лямбда смотрит на переменную, а не на число, которое было в момент её создания. Вы увидите это в трассировке.

Где в проекте теперь живут делегаты:

| Место | Делегат | Кто решает, что внутри |
| --- | --- | --- |
| `SelectionService.Select(heroes, rule)` | `Func<Hero, bool>` | окно: правило допуска |
| `SelectionService.ApplyToSelected(..., action)` | `Action<Hero>` | окно: «выдать пропуск» |
| `PrintSelection(title, rule)` | `Func<Hero, bool>` | `ShowAccess`: каждое правило |
| лямбда `bySkill` | `Func<Hero, bool>` | захватила `seal` |

#### Почему правила — снаружи, а не в Hero?

Можно было бы добавить в `Hero` метод `IsAdmittedByChancellery()`. Но порядок допуска — не свойство героя, а **решение совета**, и оно меняется: сегодня по здоровью, завтра по умению, послезавтра — по чему-то ещё. Если каждое такое решение вписывать в `Hero`, класс героя будет переписываться после каждого заседания.

Делегат разводит две вещи:

- **герой** отвечает на вопросы о себе: `Health`, `Experience`, `GetContribution(...)`;
- **правило** — это вопрос, который задают снаружи и передают как значение.

Герой не меняется, когда меняются правила. Так же как в №12 экспедиция не менялась, когда появлялись новые роли.

### 9. Трассировка: предскажите вывод

**Не запускайте сразу.**

```csharp
List<Hero> team = new List<Hero>();

```

2. Объясните, почему последние две строки разные, хотя правило `strong` не переписывалось.
3. Вставьте фрагмент в `Probe.Run`, запустите, сравните.

#### Д.1. Правило из правил

Напишите в `SelectionService` метод `public static Func<Hero, bool> Both(Func<Hero, bool> first, Func<Hero, bool> second)`, который **возвращает** новое правило: «пропустить, если пропускают оба». #### Д.2. Готовые методы с делегатами

У `List<T>` есть методы, которые принимают правило: `FindAll(...)` — все подходящие, `Find(...)` — первый подходящий, `Exists(...)` — есть ли хоть один. Их параметр — делегат `Predicate<T>`: принимает `T`, возвращает `bool`. Лямбду можно передать прямо. Если правило уже лежит в `Func<Hero, bool> rule`, передайте обёртку `hero => rule(hero)`: это разные типы делегатов. Перепишите в пробе отбор канцелярии через `world.Guild.GetMembers().FindAll(...)`. Чем `FindAll` похож на ваш `Select`? (В №19 таких методов станет гораздо больше.)

#### Д.3. Действие с последствиями

`Action<Hero>` может не только печатать. Напишите в пробе на **учебных** героях:

```csharp
public static class SelectionService {
    public static List<Hero> Select(List<Hero> heroes, Func<Hero, bool> rule) {
        List<Hero> result = new List<Hero>();
        foreach (Hero hero in heroes) {
            if (rule(hero)) {
                result.Add(hero);
            }
        }
        return result;
    }

    public static void ApplyToSelected(List<Hero> heroes, Func<Hero, bool> rule, Action<Hero> action) {
        foreach (Hero hero in heroes) {
            if (rule(hero)) {
                action(hero);
            }
        }
    }

    public static int Count(List<Hero> heroes, Func<Hero, bool> rule) {
        int count = 0;
        foreach (Hero hero in heroes) {
            if (rule(hero)) {
                count++;
            }
        }
        return count;
    }
}
```
