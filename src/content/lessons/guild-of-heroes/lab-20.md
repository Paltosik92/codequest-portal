## Идентичность: ключ Id, ссылка, позиция и сравнение объектов

> До совета Нижнего Брода — **4 дня**.

Совет собрали раньше срока — среди дня, под проливной дождь. В зале пахло мокрыми плащами и свечным воском.

Антон говорил негромко и уверенно.

— Мы нашли причину нехватки, — он положил на стол пачку распоряжений, ту самую, с порога канцелярии. — Сокращение поставок, перенаправление грузов, недопоставки уплотнений. И на каждом — одна подпись. — Он поднял глаза. — «Сергей».

Все повернулись к Сергею. Александр, стоявший рядом, сделал полшага вперёд.

— Мастер гильдии уже отстранён, — продолжил Антон. — Предлагаю совету передать ведение всех заявок моей канцелярии. Пока не разберёмся.

— Я этого не подписывал, — сказал Сергей. Голос был ровный, только руки сжаты.

— Подпись — ваша, — мягко ответил Антон. — Имя — ваше.

И тут скрипнула дверь.

На пороге стоял светловолосый парень в серой рабочей куртке, с кожаной сумкой курьера через плечо. Мокрый, запыхавшийся.

— Это мои подписи, — сказал он. — Меня тоже зовут Сергей. Сергей Лесной, курьер канцелярии. Я возил то, что мне выдавали. И расписывался — как велели.

В зале стало очень тихо. Два Сергея стояли друг напротив друга — один у стола, другой у двери.

## Цель и результат

После этой работы вы:

- поймёте разницу между **ключом**, **ссылкой** и **позицией** объекта;
- дадите каждому герою **ключ** `Id` — номер, который отличает людей с одинаковыми именами;
- научите гильдию искать по ключу (`FindHeroById`) и по имени — **списком** (`FindHeroesByName`);
- переведёте доску и окно на назначение по `Id`;
- напишете **сравниватель** `IComparer<Hero>` и отсортируете **копию** состава;
- увидите в пробе: два героя «Сергей» — два разных человека.

**Результат:** в гильдии каждый герой имеет номер: #1 Ярослав … #5 Сергей. Окно показывает состав по опыту, а назначение по имени, которое носят несколько героев, уточняет номер.

### 1. Второй Сергей не проходит в гильдию

Проверим, что будет, если в программе окажутся два человека с одним именем. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Guild trialGuild = new Guild("Учебная гильдия");
    Hero master = new SupportHero("Сергей", 110, 5);
    Hero courier = new SupportHero("Сергей", 100, 3);

    Console.WriteLine($"Мастер принят: {trialGuild.AddHero(master)}");
    Console.WriteLine($"Курьер принят: {trialGuild.AddHero(courier)}");

    Hero? found = trialGuild.FindHeroByName("Сергей");
    Console.WriteLine($"Найден тот, кто с выучкой: {found?.Training}");
}
```

Включите пробу и запустите:

```text
>>> Проба <<<
Мастер принят: True
Курьер принят: False
Найден тот, кто с выучкой: 5
```

(`found?.Training` — «если `found` не `null`, взять `Training`». Тот же оператор `?.`, что у событий в №18.)

С №5 гильдия считает: одно имя — один человек. Для перепроверки «не вписали ли дважды» это было удобно. Но теперь это **неправда**: Сергей Лесной — другой человек, и гильдия его не пускает. А поиск по имени молча возвращает **первого** подходящего — и никогда не узнает о втором.

Имя — не то, что отличает людей. Подпись «Сергей» — тоже.

Выключите пробу и очистите `Run`.

### 2. Три способа указать на объект

Как вообще можно указать на конкретного героя?

| Способ | Пример | Где работает | Где ломается |
| --- | --- | --- | --- |
| **Ссылка** | `Hero sergey` — переменная | внутри одного запуска программы | на бумаге, в файле, после перезапуска — ссылки там нет |
| **Позиция** | `members[4]` | пока список не меняли | после сортировки, удаления, вставки — на месте 4 уже другой |
| **Имя** | «Сергей» | пока имена уникальны | два Сергея — и уже не ясно, кто |
| **Ключ** | `Id = 5` | всегда: номер выдают один раз и больше не меняют | — |

**Ключ** — значение, которое у каждого объекта **своё** и **не меняется**. В жизни это номер паспорта, табельный номер, номер поручения. Наши поручения с №6 так и устроены: №101, №102 — номера, а не названия. Пора дать номера и героям.

### 3. Id у героя

Откройте `Hero.cs`. Добавьте свойство:

```csharp
public int Id { get; private set; }
```

Конструктор `Hero(name, health, training)` получает номер **первым** параметром:

```csharp
protected Hero(int id, string name, int health, int training) {
    if (id < 1) {
        throw new InvalidRecordException($"Номер героя должен быть положительным, а не {id}.");
    }
    Id = id;

    // ... всё прежнее тело: Name, MaxHealth, Health, Level, Experience, Training ...
}
```

Неположительный номер — неверные данные, как в №16.

Двухпараметровый конструктор `Hero(string name, int health) : this(name, health, 1)` **удалите**: с №13 им никто не пользуется, а без номера героя создать больше нельзя.

Теперь наследники. В каждом из четырёх — `Warrior`, `Mage`, `Ranger`, `SupportHero` — добавьте номер первым параметром и передайте в `base`:

```csharp
public Warrior(int id, string name, int health, int training) : base(id, name, health, training) {
}
```

Это **миграция**: изменился конструктор — компилятор покажет все места, где героев создают. Таких места два: `WorldSetup` и ваши пробы.

В `WorldSetup.Create`:

```csharp
Hero yaroslav = new Warrior(1, "Ярослав", 100, 5);
Hero anastasia = new Mage(2, "Анастасия", 90, 6);
Hero artem = new Ranger(3, "Артём", 120, 4);
Hero alexander = new Warrior(4, "   Александр   ", 150, 6);
Hero sergey = new SupportHero(5, "Сергей", 110, 5);
```

Номера команды — 1–5, в порядке, в котором герои пришли в гильдию.

### 4. Гильдия: ключ уникален, имя — нет

Откройте `Guild.cs`. Три изменения.

**Поиск по ключу** — новый метод:

```csharp
public Hero? FindHeroById(int id) {
    foreach (Hero hero in _heroes) {
        if (hero.Id == id) {
            return hero;
        }
    }
    return null;
}
```

**Поиск по имени** возвращает теперь **список** — всех, кто носит это имя. Замените `FindHeroByName` на:

```csharp
public List<Hero> FindHeroesByName(string name) {
    List<Hero> result = new List<Hero>();
    if (string.IsNullOrWhiteSpace(name)) {
        return result;
    }

    string wanted = name.Trim();
    foreach (Hero hero in _heroes) {
        if (string.Equals(hero.Name, wanted, StringComparison.OrdinalIgnoreCase)) {
            result.Add(hero);
        }
    }
    return result;
}
```

Правило сравнения имён — то же, что с №5: пробелы по краям и регистр не важны. Изменилось только то, что ответ может содержать **несколько** героев. Или ни одного — пустой список вместо `null`.

**Добавление** отклоняет повтор **номера**, а не имени. В `AddHero` замените проверку:

```csharp
if (FindHeroById(hero.Id) != null) {
    return false;
}
```

**Удаление** — по номеру: `RemoveHero(int id)`, внутри — `FindHeroById(id)`.

Компилятор подскажет, кто ещё пользовался старыми методами, — это доска. Исправим её в следующем шаге.

### 5. Доска назначает по номеру

Откройте `QuestBoard.cs`. Везде, где герой искался по имени, — теперь по номеру.

```csharp
public bool TryAssign(int questId, int heroId) {
    Quest? quest = FindQuest(questId);
    if (quest == null) {
        return false;
    }

    Hero? hero = _guild.FindHeroById(heroId);
    if (hero == null) {
        return false;
    }

    if (IsAssigned(hero)) {
        return false;
    }

    return quest.TryAssign(hero);
}
```

Точно так же — `TryRemoveMember(int heroId)` и `FindActiveQuest(int heroId)` (из №7): параметр `int heroId`, поиск — `_guild.FindHeroById(heroId)`, в конце `TryRemoveMember` — `_guild.RemoveHero(hero.Id)`.

Доска больше не разбирается с именами вообще. Она получает **ключ** и находит **ссылку**. А как человек назвал героя — забота окна.

Осталась история в `WorldSetup`. Замените имена номерами:

```csharp
board.TryAssign(101, 5);
// ...
board.TryAssign(102, 5);
board.TryCancel(102);
board.TryAssign(103, 5);
board.TryComplete(103);
board.TryAssign(104, 1);
// ...
board.TryAssign(106, 5);
```

Сергей — №5, Ярослав — №1. Читать стало менее «человечно», но теперь история однозначна: даже если завтра в гильдию придёт ещё один Сергей, поручения №101–106 останутся за **этим**.

### 6. Окно: человек называет имя, программа уточняет номер

Человек у окна не помнит номеров — он говорит «Сергей». Окно должно найти **всех** с таким именем и, если их несколько, спросить, кого именно.

Сначала маленькая уборка. Помощник `TryParseQuestId` из №9 давно разбирает не только номера поручений, но и номера экспедиций, а теперь будет разбирать номера героев. Переименуйте его в `TryParseNumber` — во всех местах (в VS Code: курсор на имени, `F2`, новое имя). Тело не меняется.

Теперь `AssignQuest`. Замените его часть после ввода номера поручения:

```csharp
string? heroName = ReadInput("Имя исполнителя: ");
if (heroName == null) {
    _isRunning = false;
    return;
}

List<Hero> found = _guild.FindHeroesByName(heroName);
if (found.Count == 0) {
    Console.WriteLine("Героя с таким именем нет.");
    return;
}

int heroId = found[0].Id;
if (found.Count > 1) {
    Console.WriteLine("Несколько героев с этим именем:");
    foreach (Hero hero in found) {
        Console.WriteLine($"#{hero.Id} {hero.Name} ({hero.RoleName}), здоровье {hero.Health}");
    }

    string? heroIdText = ReadInput("Номер героя: ");
    if (heroIdText == null) {
        _isRunning = false;
        return;
    }
    if (!TryParseNumber(heroIdText, out heroId)) {
        Console.WriteLine("Номер — это число, например 5.");
        return;
    }
}

if (_board.TryAssign(questId, heroId)) {
    Console.WriteLine("Назначено.");
} else {
    Console.WriteLine("Отказ: проверьте номер, состояние поручения и занятость героя.");
}
```

Если человек с таким именем один — окно берёт его номер молча. Если несколько — показывает их с номерами и спрашивает. В доску уходит **только номер**.

`out heroId` здесь передаёт **уже объявленную** переменную: `TryParseNumber` перезапишет её, если человек ввёл число.

### 7. Сравниватель: состав по опыту

В окне пункт `1` показывает героев в порядке добавления. Совету удобнее видеть самых опытных первыми. В №19 мы сортировали LINQ-запросом. Есть и другой способ — **объект-сравниватель**, который можно отдать любой сортировке.

Создайте `HeroExperienceComparer.cs`:

```csharp
public class HeroExperienceComparer : IComparer<Hero> {
    public int Compare(Hero? x, Hero? y) {
        if (x == null || y == null) {
            return 0;
        }

        int byExperience = y.Experience.CompareTo(x.Experience);
        if (byExperience != 0) {
            return byExperience;
        }

        return x.Id.CompareTo(y.Id);
    }
}
```

**`IComparer<Hero>`** — интерфейс из .NET (вспомните №14): «я умею сравнивать двух героев». Его единственный метод `Compare(x, y)` отвечает числом:

| Ответ | Значит |
| --- | --- |
| меньше 0 | `x` должен стоять **раньше** `y` |
| 0 | равны — порядок не важен |
| больше 0 | `x` должен стоять **позже** `y` |

**`CompareTo`** — готовое сравнение у чисел и строк, отвечает так же: `3.CompareTo(5)` — отрицательное, `5.CompareTo(5)` — 0.

- `y.Experience.CompareTo(x.Experience)` — **наоборот** (`y` с `x`), чтобы больший опыт шёл первым;
- при равном опыте — по **ключу** `Id`: порядок всегда однозначный, и при каждом запуске одинаковый.

Параметры `Hero?` — так `IComparer` объявлен в .NET с учётом `null`. В нашем составе `null` не бывает, но проверка обязательна.

Теперь `ShowMembers`:

```csharp
private void ShowMembers() {
    List<Hero> members = _guild.GetMembers();
    members.Sort(new HeroExperienceComparer());

    foreach (Hero hero in members) {
        Console.WriteLine($"#{hero.Id} {hero.Name} ({hero.RoleName}): здоровье {hero.Health}, уровень {hero.Level}, " +
                          $"опыт {hero.Experience}, до уровня {hero.ExperienceToNextLevel}, выучка {hero.Training}");
    }
}
```

`List.Sort(сравниватель)` переставляет элементы **того же** списка. Поэтому сортируем **копию**, которую вернул `GetMembers()` (№5): порядок внутри гильдии не меняется — меняется только порядок показа.

Запустите, выберите `1`:

```text
#5 Сергей (Поддержка): здоровье 110, уровень 2, опыт 50, до уровня 50, выучка 5
#1 Ярослав (Воин): здоровье 100, уровень 1, опыт 15, до уровня 35, выучка 5
#2 Анастасия (Маг): здоровье 90, уровень 1, опыт 0, до уровня 50, выучка 6
#3 Артём (Лучник): здоровье 120, уровень 1, опыт 0, до уровня 50, выучка 4
#4 Александр (Воин): здоровье 150, уровень 1, опыт 0, до уровня 50, выучка 6
```

Сергей теперь первый — но позиция 0 в этом списке **не** делает его «героем номер 0». Его номер — 5, и это не изменится ни от какой сортировки.

![Сравниватель отвечает «раньше / равны / позже»; Sort переставляет копию](/materials/guild-of-heroes/img/lab20/schema-03-comparer-and-copy.webp)

Копия списка хранит ссылки на тех же героев. Перестановка, добавление или удаление элемента в копии не меняют состав гильдии; изменение самого объекта `Hero` видно через оба списка.

![Два списка содержат ссылки на одни и те же объекты Hero](/materials/guild-of-heroes/img/lab20/schema-04-copy-shares-heroes.webp)

1. Что вернёт `Compare` для Ярослава (опыт 15, #1) и Сергея (опыт 50, #5) — именно в таком порядке аргументов?
2. Что изменится в выводе, если в последней строке `Compare` поменять `x.Id` и `y.Id` местами?
3. Почему нельзя написать `_heroes.Sort(...)` прямо внутри `Guild.GetMembers()`?

<details>
<summary>Ответы</summary>

1. Положительное число: `50.CompareTo(15)` > 0 — Ярослав должен стоять **позже** Сергея.
2. Среди героев с опытом 0 порядок станет обратным: #4, #3, #2. Порядок по опыту не изменится.
3. Тогда при каждом показе менялся бы порядок **внутри** гильдии — то, что видят все остальные методы. Копия нужна, чтобы показ ничего не ломал.

</details>

### 8. Проба: два Сергея — два человека

Вернёмся к пробе из шага 1 — теперь с номерами. Замените тело `Probe.Run`:

```csharp
public static void Run() {
    Console.WriteLine(">>> Проба <<<");

    Guild trialGuild = new Guild("Учебная гильдия");
    Hero master = new SupportHero(5, "Сергей", 110, 5);
```
