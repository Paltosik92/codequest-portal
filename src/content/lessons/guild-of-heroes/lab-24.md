## Интеграция: маршрут из трёх испытаний, выбор состава, сохранение посреди пути

> **День совета.** Ночь перед ним.

Проход в скале был узким и мокрым. Вода сочилась по стенам, капала с потолка, журчала под ногами. Где-то наверху, за толщей камня, гудел переполненный резервуар — так гудит натянутая до предела струна.

Шли цепочкой. Впереди Ярослав с ключом Антона на шее, за ним Александр, Анастасия с посохом, Сергей с ящиком инструментов, Артём с колчаном и мотком верёвки. Замыкала Вера — она тащила по камням шланг насоса: «Канальный» остался у входа и откачивал воду, чтобы проход не затопило совсем.

Елена шла посередине. Под клеёнчатым плащом она прижимала к себе ноутбук.

Проход кончился каменной камерой. В дальней стене, за грудой обломков, темнела седьмая тяга — огромный бронзовый рычаг, обвитый цепью с печатью.

— Три дела, — сказала Елена, раскрыв ноутбук на сухом выступе. — Разобрать завал. Прочитать печать. Подать сигнал вниз, чтобы в посёлке успели открыть каналы. По порядку: пока лежит завал, к печати не подойти. Пока не снята печать, сигналить рано.

— Кто на завал? — спросил Ярослав.

— Это решите вы, — Елена повернула экран. — Программа скажет, хватит ли.

Над скалой ударил колокол — глухо, сквозь камень. Четвёртый раз за сутки.

### 1. Почему печать читает только она

Вспомним №17. Правило допуска канцелярии — «здоровье ≥ 100 и опыт ≥ 20» — не пропустило Анастасию. Антон сказал тогда: «Седьмая тяга давно не используется». Проверим, что было бы, если бы правило осталось.

    Challenge seal = new Challenge(ChallengeKind.Seal, 15);

    Expedition withoutMage = new Expedition(900, "Без мага");
    Expedition everyone = new Expedition(901, "Все");
    foreach (Hero hero in world.Guild.GetMembers()) {
        everyone.AddMember(hero);
        if (hero.Id != 2) {
            withoutMage.AddMember(hero);
        }

    Console.WriteLine($"Печать без Анастасии: {withoutMage.TotalContribution(seal)} из 15");
    Console.WriteLine($"Печать всем составом: {everyone.TotalContribution(seal)} из 15");

### 3. Одна проверка вклада на два случая

Сравним, как завершается поручение с испытанием. Сейчас `TryCompleteWithChallenge` ищет экспедицию **на доске** по номеру. Но состав на этап человек выберет прямо у тяги, и регистрировать его на доске незачем — как в пробе шага 1.

Можно написать второй метод «завершить с составом» — и скопировать в него проверку вклада, вызов `TryComplete` и событие. Две копии — две возможности однажды исправить только одну. Сделаем иначе: выделим общую часть.

Откройте `QuestBoard.cs` и замените `TryCompleteWithChallenge` двумя методами:

```csharp
public bool TryCompleteWithChallenge(int questId, int expeditionId) {
    Expedition? expedition = FindExpedition(expeditionId);
    if (expedition == null) {
        return false;
    }
    if (!expedition.HasQuest(questId)) {
        return false;
    }
    return TryCompleteWithTeam(questId, expedition);
}

public bool TryCompleteWithTeam(int questId, Expedition team) {
    Quest? quest = FindQuest(questId);
    if (quest == null) {
        return false;
    }

    Challenge? challenge = quest.Challenge;
    if (challenge == null) {
        return false;
    }
    if (team.TotalContribution(challenge) < challenge.Difficulty) {
        return false;
    }

    bool completed = quest.TryComplete();
    if (completed) {
        RaiseCompleted(quest);
    }
    return completed;
}
```

`TryCompleteWithChallenge` теперь делает только своё — находит зарегистрированную экспедицию и проверяет, что поручение в её списке, — а всё остальное **поручает** `TryCompleteWithTeam`. Пункт `4` окна работает как раньше: проверьте `4`, `106`, `201`.

Колокол и журнал гильдии подписаны на `QuestCompleted` — значит, они услышат и завершение этапа маршрута. Ни строчки для этого писать не нужно: так работают события (№18).

### 4. Сервис маршрута

Маршрут — правило проекта: этапы идут по порядку, ведущий этапа должен быть в составе, состав собирается из номеров героев. Это работа сервиса. Создайте `Services/RouteService.cs`:

```csharp
using GuildOfHeroes.Models;

namespace GuildOfHeroes.Services;

public class RouteService {
    private readonly Guild _guild;
    private readonly QuestBoard _board;
    private readonly GuildLog _log;
    private readonly List<int> _stageIds = new List<int> { 301, 302, 303 };

    public RouteService(Guild guild, QuestBoard board, GuildLog log) {
        _guild = guild;
        _board = board;
        _log = log;
    }

    public List<Quest> GetStages() {
        List<Quest> stages = new List<Quest>();
        foreach (int stageId in _stageIds) {
            Quest? stage = _board.FindQuest(stageId);
            if (stage != null) {
                stages.Add(stage);
            }
        }
        return stages;
    }

    public Quest? FindNextStage() {
        foreach (Quest stage in GetStages()) {
            if (stage.Status != QuestStatus.Completed) {
                return stage;
            }
        }
        return null;
    }

    public Expedition BuildTeam(int stageId, List<int> heroIds) {
        Expedition team = new Expedition(stageId, "Состав этапа");
        foreach (int heroId in heroIds) {
            Hero? hero = _guild.FindHeroById(heroId);
            if (hero == null) {
                throw new InvalidRecordException($"Героя #{heroId} в гильдии нет.");
            }
            team.AddMember(hero);
        }
        return team;
    }

    public string Describe(Expedition team, Challenge challenge) {
        List<string> parts = team.GetMembers()
            .Select(m => $"{m.Name} {m.GetContribution(challenge)}")
            .ToList();
        return $"{string.Join(", ", parts)} — итого {team.TotalContribution(challenge)} из {challenge.Difficulty}";
    }
}
```

`new List<int> { 301, 302, 303 }` — список, заполненный сразу при создании: значения в фигурных скобках через запятую.

Что здесь от прошлых работ:

- **`GetStages`** — этапы **по номерам** (№20), в порядке маршрута, а не в порядке доски. Сервис хранит ключи, а объекты каждый раз находит на доске: так он увидит и загруженные из снимка поручения.
- **`FindNextStage`** — первый невыполненный этап. Порядок маршрута — в одном месте.
- **`BuildTeam`** — состав из номеров. Каждый вызов создаёт **новую** экспедицию — как в пробе шага 1: состав на завал не должен перетечь в состав на печать. Повтор номера `AddMember` отклонит сам (№8). Несуществующий номер — **неверные данные** (№16): исключение.
- **`Describe`** — строка для человека: LINQ-проекция (№19) каждого участника в «имя вклад» и итог. Участники — `IContributor` (№14): сервису всё равно, герой это или насос.

### 5. Пройти этап

Добавьте в `RouteService` главный метод:

```csharp
public bool TryPass(int stageId, Expedition team) {
    Quest? next = FindNextStage();
    if (next == null || next.Id != stageId) {
        return false;
    }

    Hero? lead = next.AssignedHero;
    Challenge? challenge = next.Challenge;
    if (lead == null || challenge == null || !team.HasMember(lead)) {
        return false;
    }

    bool passed = _board.TryCompleteWithTeam(stageId, team);

    string result = "не пройден";
    if (passed) {
        result = "пройден";
    }
    _log.RecordRoute($"Этап №{stageId}: {Describe(team, challenge)} — {result}");
    return passed;
}
```

Три **предметных** отказа — `false`, как у всех `Try`-методов с №6:

1. этап не тот, что следующий по маршруту;
2. ведущего этапа нет в составе — «Ярослав ведёт завал» значит, что Ярослав там;
3. вклада не хватает — это решает доска в `TryCompleteWithTeam`.

Каждая **настоящая** попытка — дошедшая до проверки вклада — записывается в журнал гильдии, удачная или нет. Добавьте в `GuildLog`:

```csharp
public void RecordRoute(string line) {
    _lines.Add(line);
}
```

Удачная попытка оставит в журнале две строки: эту — от сервиса маршрута, и строку о выполнении — от события доски. Первая говорит, **кто и сколько** вложил, вторая — **кто получил** награду.

### 6. Пункт «Маршрут»

Накладные больше не приходят: склады канцелярии опечатаны советом. Пункт `8 Накладная` уступает место маршруту. В `GuildConsole`:

1. Удалите метод `AcceptSupply`.
2. В строке меню — `8 Маршрут`, в `HandleChoice` — `case "8": RunRoute(); break;`.
3. Добавьте поле `private readonly RouteService _route;` и в конструкторе — `_route = new RouteService(world.Guild, world.Board, world.Log);`.

Сервис маршрута создаёт окно: ему нужен тот мир, с которым окно работает, — загруженный или исходный.

И сам метод:

```csharp
private void RunRoute() {
    List<Quest> stages = _route.GetStages();
    foreach (Quest stage in stages) {
        Console.WriteLine(stage.GetInfo());
    }

    Quest? next = _route.FindNextStage();
    if (next == null) {
        Console.WriteLine("Маршрут пройден.");
        return;
    }

    Challenge? challenge = next.Challenge;
    if (challenge == null) {
        return;
    }
    Console.WriteLine($"Следующий этап: №{next.Id}, испытание {challenge.GetKindText()}, сложность {challenge.Difficulty}");

    string? teamText = ReadInput("Состав (номера героев через пробел): ");
    if (teamText == null) {
        _isRunning = false;
        return;
    }

    List<int> heroIds = new List<int>();
    foreach (string part in teamText.Split(' ', StringSplitOptions.RemoveEmptyEntries)) {
        if (!TryParseNumber(part, out int heroId)) {
            Console.WriteLine($"«{part}» — не номер героя.");
            return;
        }
        heroIds.Add(heroId);
    }

    try {
        Expedition team = _route.BuildTeam(next.Id, heroIds);
        Console.WriteLine($"Вклад: {_route.Describe(team, challenge)}");

        if (_route.TryPass(next.Id, team)) {
            Console.WriteLine("Этап пройден.");
        } else {
            Console.WriteLine("Этап не пройден: вклада не хватает или исполнитель этапа не в составе.");
        }
    } catch (InvalidRecordException ex) {
        Console.WriteLine($"Состав отклонён: {ex.Message}");
    }
}
```

**`Split(' ', StringSplitOptions.RemoveEmptyEntries)`** — разрезать строку по пробелам и выбросить пустые куски: `"1  4 "` → `"1"`, `"4"`. Каждый кусок проходит через `TryParseNumber` (№9, №20) — форма ввода проверяется в окне. А существует ли такой герой — смысл — проверяет сервис и сообщает исключением. Граница из №9 и №16 на месте.

Окно не знает ни порядка этапов, ни правила ведущего, ни как считается вклад. Оно спрашивает, показывает и передаёт номера.

### 7. Итог маршрута

Когда этапов не осталось, человек у тяги должен увидеть итог, а не одно слово. Это отчёт — значит, `ReportService` и LINQ (№19). Добавьте в него:

```csharp
public static List<string> RouteLines(List<Quest> stages) {
    return stages
        .Where(s => s.Status == QuestStatus.Completed)
        .Select(s => s.GetInfo())
        .ToList();
}

public static int CountPassed(List<Quest> stages) {
    return stages.Count(s => s.Status == QuestStatus.Completed);
}
```

В `RunRoute` замените ветку `next == null`:

```csharp
if (next == null) {
    Console.WriteLine($"Маршрут пройден: {ReportService.CountPassed(stages)} из {stages.Count}.");
    foreach (string line in ReportService.RouteLines(stages)) {
        Console.WriteLine($"- {line}");
    }
    Console.WriteLine("Седьмая тяга открыта.");
    return;
}
```

### 8. Половина маршрута переживает перезапуск

Главная проверка работы: маршрут, пройденный наполовину, сохраняется и продолжается после загрузки. Ничего нового писать для этого не нужно — этапы маршрута обычные поручения, а их сохранение и загрузку мы сделали в №22–23. Убедимся. Замените тело `Probe.Run`:

### 10. Найдите две ошибки

#### Ошибка 1. Сигнал раньше воды

#### Ошибка 2. Состав, который помнит прошлое

Другой студент решил не создавать экспедицию на каждую попытку и завёл в `RouteService` поле:

```csharp
private readonly Expedition _team = new Expedition(300, "Состав маршрута");

public Expedition BuildTeam(int stageId, List<int> heroIds) {
    foreach (int heroId in heroIds) {
        Hero? hero = _guild.FindHeroById(heroId);
        if (hero == null) {
            throw new InvalidRecordException($"Героя #{heroId} в гильдии нет.");
        }
        _team.AddMember(hero);
    }
    return _team;
}
```

Завал он прошёл составом `1 4`. На печати ввёл `2 5` — и увидел: «Вклад: Ярослав 0, Александр 0, Анастасия 12, Сергей 5 — итого 17 из 15». Странно, но прошло. А на высоте ввёл просто `3` — и Артём **один** прошёл испытание, которое в одиночку не проходится. Какой вклад насчитала программа? Почему?

<details>
<summary>Самопроверка — после своей попытки</summary>

1. Без проверки `FindNextStage` сервис принимает любой этап с подходящим вкладом. Окно спросило номер — человек ввёл не тот. Правило порядка — правило **маршрута**: оно живёт в `RouteService`, в одном месте. Окно может подсказать следующий этап, но не обязано его охранять. Доска о маршруте не знает вовсе — для неё №301–303 обычные поручения.
2. `_team` — один объект на все попытки: участники копятся. На высоте в составе Ярослав, Александр, Анастасия, Сергей и Артём: 2 + 3 + 3 + 5 + 8 = 21 из 10. Исправление: новая экспедиция в каждом `BuildTeam`. Тот же урок, что в №4 («мир внутри цикла») и №9, только наоборот: здесь объект должен быть **новым** каждый раз.

</details>

Совет собрался в полдень — в том же зале, где четыре дня назад Антон обвинял Сергея. Елена положила на стол ноутбук и распечатку отчёта гильдии — состав, поручения, журнал, накладные, маршрут. Рядом Борис положил свою связку.

— Здесь всё, — сказала Елена. — Кто, когда, что подписал и что из этого вышло. Теперь их прочтут все.

Совет читал долго. Потом Нина встала.

— Предложение о тридцатилетнем праве на воду долины отклонено, — сказала она. — Распорядитель Ветров ответит за свои распоряжения перед окружным судом.

Антон не спорил. Он кивнул — коротко, почти вежливо — и вышел, не оглянувшись.

Вера осталась инженером водосборника — под надзором совета и с запретом подписывать распоряжения в одиночку. «Справедливо», — сказала она и пошла проверять тягу. Эльдар уезжал вечером: совет посёлка подписал с ним новый контракт — охранять не ящики канцелярии, а склад аварийных уплотнений Нижнего Брода. Сергей Лесной стал курьером посёлка.

![Седьмой колокол](/materials/guild-of-heroes/img/lab24/epic-vi-b-seventh-bell.webp)

Вечером команда стояла у вывески гильдии. Над дверью, под знакомыми буквами, Сергей прибивал новую дощечку: «Принимаем поручения. По номеру».

Вода журчала в канаве у дороги — уже не разливаясь, а ровно, по желобу.

— Слушайте, — сказал Артём, — а теперь можно программу, которая сама вовремя приносит обед?

Елена закрыла ноутбук.

— Сначала нужен один пример, — сказала она.

Ярослав засмеялся первым.
