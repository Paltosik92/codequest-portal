## Шаг 1. Создай проект

Открой Git Bash в рабочей папке, которую назвал преподаватель, и создай папку проекта со своим кодом группы и фамилией:

```bash
mkdir pixelport-is31-ivanov
cd pixelport-is31-ivanov
git init -b main
code .
```

Последняя команда открывает текущую папку в VS Code. Если `code` не находится, открой VS Code вручную через **File → Open Folder**.

Скопируй в проект папку `img` из материалов курса. Структура должна стать такой:

```text
pixelport-is31-ivanov/
└── img/
    ├── logo-mark.svg
    ├── neon-circuit.png
    └── … остальные обложки
```

Теперь создай в корне проекта файл `index.html`. Имя важно: когда браузер открывает папку сайта, он по умолчанию ищет именно `index.html`. Позже это будет главная страница магазина. Сегодня главная — страница твоей игры, в №02 мы её переименуем.

> ✅ **Проверь себя:** в боковой панели VS Code видны папка `img` и файл `index.html`, а в терминале `pwd` показывает твою папку.

## Шаг 2. Скелет страницы

Любая HTML-страница начинается с одного и того же каркаса. Набери его руками (в VS Code можно напечатать `!` и нажать Tab, но первый раз лучше руками, чтобы запомнить):

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Neon Circuit — PixelPort</title>
  <link rel="icon" href="img/logo-mark.svg">
</head>
<body>

</body>
</html>
```

Разберём, что здесь что:

| Строка | Что делает |
| --- | --- |
| `<!DOCTYPE html>` | Говорит браузеру: это современный HTML. Без неё браузер включает «режим совместимости» с сайтами 90-х |
| `<html lang="ru">` | Корень документа. `lang` подсказывает язык программам экранного доступа и переводчику |
| `<head>` | Служебная часть: на самой странице её не видно |
| `<meta charset="UTF-8">` | Кодировка. Без неё русские буквы могут превратиться в «кракозябры» |
| `<meta name="viewport" …>` | Без этой строки телефон покажет страницу уменьшенной, как на мониторе |
| `<title>` | Текст на вкладке браузера и в закладках |
| `<link rel="icon">` | Значок на вкладке — логотип PixelPort |
| `<body>` | Всё, что видит пользователь |

HTML — это **теги**. Почти все они парные: `<title>` открывает элемент, `</title>` закрывает, а между ними содержимое. Некоторые теги, например `<meta>` и `<link>`, одиночные: содержимого у них нет, вся информация в **атрибутах** вида `имя="значение"`.

Теперь запусти страницу: правый клик по `index.html` → **Open with Live Server**. Откроется браузер с адресом вроде `http://127.0.0.1:5500/index.html`. Страница пока белая, но на вкладке уже есть название и значок.

> ✅ **Проверь себя:** на вкладке браузера видны «Neon Circuit — PixelPort» и пиксельный значок «P».

Live Server — это маленький веб-сервер на твоём компьютере. Он отдаёт файлы браузеру так же, как это делает настоящий сайт в интернете, и сам обновляет страницу при каждом сохранении файла. Поэтому дальше просто сохраняй файл (Ctrl+S) и смотри в браузер.

## Шаг 3. Шапка, название и обложка

Внутри `<body>` добавь шапку и начало основного содержимого:

```html
<body>
  <header>
    <p><strong>PixelPort</strong> — магазин инди-игр</p>
  </header>

  <main>
    <h1>Neon Circuit</h1>
    <p><em>Побеждайте на ночных трассах футуристического города.</em></p>

    <img src="img/neon-circuit.png"
         alt="Неоновый спорткар мчится по ночной трассе среди небоскрёбов"
         width="300">

    <p><a href="#requirements">Системные требования</a></p>
  </main>
</body>
```

Что нового:

- `<header>` и `<main>` — **смысловые** контейнеры: «шапка» и «основное содержимое». Внешне они ничего не меняют, но браузер, поисковики и программы для незрячих понимают по ним структуру страницы.
- `<h1>` — главный заголовок. На странице он один, как название у книги.
- `<strong>` — важный текст (жирный), `<em>` — смысловое выделение (курсив).
- `<img>` — картинка. `src` — путь к файлу **относительно этой страницы**: «зайди в папку `img`, возьми `neon-circuit.png`». `width="300"` задаёт ширину в пикселях, высота подстроится сама.
- `alt` — текстовое описание картинки. Его читает вслух программа экранного доступа, и его же браузер покажет, если картинка не загрузилась. Описывай то, что на картинке **видно**, а не «картинка игры».
- `<a href="#requirements">` — ссылка. Решётка означает «на этой же странице, к элементу с `id="requirements"`». Такого элемента пока нет, мы добавим его в шаге 6.

> ✅ **Проверь себя:** обложка видна, под названием курсивом идёт слоган. Если вместо картинки значок «сломанного изображения», проверь путь и имя файла буква в букву.

## Шаг 4. Об игре и особенности

Продолжи внутри `<main>`, после ссылки:

```html
    <h2>Об игре</h2>
    <p>
      2089 год. Ночной город превратился в гоночную трассу, а победа в лиге
      Neon Circuit — единственный способ попасть в верхний город. Собери
      машину своей мечты, изучи каждый тоннель и обгони тех, кто уже
      считает себя чемпионом.
    </p>
    <p>Разработчик: <strong>Prism Drive</strong>. Год выхода: 2025. Жанр: гонки.</p>

    <h2>Особенности</h2>
    <ul>
      <li>24 трассы в трёх районах города</li>
      <li>Сетевые заезды до 8 игроков</li>
      <li>Тюнинг машины: от двигателя до цвета неоновой подсветки</li>
      <li>Режим «Призрак»: соревнуйся с собственным лучшим заездом</li>
    </ul>

    <h2>Как начать</h2>
    <ol>
      <li>Выбери стартовую машину в гараже.</li>
      <li>Пройди обучающий заезд по набережной.</li>
      <li>Получи пропуск в первую лигу и сразись с соперниками.</li>
    </ol>
```

`<h2>` — заголовок раздела, следующий уровень после `<h1>`. Всего уровней шесть, до `<h6>`. Уровни не пропускают: после `<h1>` идёт `<h2>`, а не `<h4>`, даже если `<h4>` «по размеру больше нравится». Размер потом изменим через CSS.

`<ul>` — маркированный список (unordered), порядок неважен. `<ol>` — нумерованный (ordered), порядок важен. Каждый пункт внутри — `<li>`. Обрати внимание: номера в `<ol>` браузер ставит сам.

Перенос строки и лишние пробелы внутри `<p>` браузер игнорирует. Абзац в коде можно разбить на несколько строк для удобства, на странице он всё равно останется одним абзацем.

**Твоя часть:** замени описание, особенности и шаги на свои для выбранной игры. Минимум три особенности и три шага. Пиши так, чтобы игру захотелось купить.

> ✅ **Проверь себя:** на странице три раздела с заголовками; у «Особенностей» точки, у «Как начать» номера 1, 2, 3.

## Шаг 5. Цена и кнопка

```html
    <h2>Цена</h2>
    <p>
      <del>1499 ₽</del>
      <strong>599 ₽</strong>
      <mark>−60%</mark>
    </p>
    <button type="button">Купить</button>
```

- `<del>` — удалённый, то есть устаревший, текст. Браузер зачёркивает его, и это значит «старая цена».
- `<mark>` — пометка, по умолчанию с жёлтым фоном. Пока некрасиво, в №05 из неё получится яркий бейдж скидки.
- `<button>` — кнопка. Пока она ничего не делает: «оживлять» страницу будем на TypeScript, начиная с №07. А по-настоящему купить игру через неё станет можно в №22, когда за кнопкой появятся сервер и база данных.

Если у твоей игры нет скидки, оставь только `<strong>` с ценой, без `<del>` и `<mark>`.

> ✅ **Проверь себя:** старая цена зачёркнута, новая жирная, есть кнопка «Купить».

## Шаг 6. Системные требования — таблица

Таблица нужна, когда данные действительно табличные: строки и столбцы с общим смыслом. Системные требования — как раз такой случай.

```html
    <h2 id="requirements">Системные требования</h2>
    <table>
      <thead>
        <tr>
          <th>Параметр</th>
          <th>Минимальные</th>
          <th>Рекомендуемые</th>
        </tr>
      </thead>
      <tbody>
        <tr>
          <th>ОС</th>
          <td>Windows 10 64-bit</td>
          <td>Windows 11 64-bit</td>
        </tr>
        <tr>
          <th>Процессор</th>
          <td>4 ядра, 3.0 ГГц</td>
          <td>8 ядер, 3.6 ГГц</td>
        </tr>
        <tr>
          <th>Оперативная память</th>
          <td>8 ГБ</td>
          <td>16 ГБ</td>
        </tr>
        <tr>
          <th>Видеокарта</th>
          <td>4 ГБ видеопамяти</td>
          <td>8 ГБ видеопамяти</td>
        </tr>
        <tr>
          <th>Место на диске</th>
          <td colspan="2">35 ГБ</td>
        </tr>
      </tbody>
    </table>
```

Как читать таблицу:

- `<table>` — сама таблица, `<tr>` — строка (table row).
- `<th>` — ячейка-заголовок (жирная, по центру), `<td>` — обычная ячейка с данными.
- `<thead>` и `<tbody>` делят таблицу на шапку и тело, как `<head>` и `<body>` делят страницу.
- `colspan="2"` растягивает ячейку на два столбца: место на диске одинаковое для обоих вариантов.
- `id="requirements"` у заголовка — уникальное имя элемента на странице. Именно к нему ведёт ссылка из шага 3.

Таблица будет без рамок. Это нормально: оформление появится в №03.

> ✅ **Проверь себя:** нажми на ссылку «Системные требования» вверху — страница прокрутится к таблице, а в адресе появится `#requirements`. Если окно большое и прокручивать некуда, сузь окно браузера.

## Шаг 8. Заглянем под капот: DevTools

В браузере нажми **F12**. Откроются инструменты разработчика (DevTools) — главный инструмент веб-разработчика, дальше он понадобится на каждой паре.

**Вкладка Elements.** Здесь видно дерево элементов, которое браузер построил из твоего HTML. Наведи мышь на `<img>` в дереве: картинка подсветится на странице. И наоборот: правый клик по любому месту страницы → **Просмотреть код** (Inspect) — и DevTools покажет нужный элемент.

**Попробуй «взломать» магазин.** В Elements найди `<strong>599 ₽</strong>`, дважды щёлкни по тексту и замени цену на `0 ₽`. На странице игра стала бесплатной! Теперь обнови страницу (F5) — цена вернулась.

Почему так: DevTools меняет только копию страницы у тебя в браузере, а не файл на диске и не сайт у других людей. Отсюда важный вывод на весь курс: **всё, что пришло в браузер, пользователь может изменить**. Поэтому настоящую цену при покупке будет проверять сервер, а не страница. Это мы и сделаем в №22.

**Вкладка Console.** Здесь браузер пишет об ошибках. Сейчас там должно быть пусто или почти пусто. Запомни, где она, — пригодится через минуту.

> ✅ **Проверь себя:** ты нашёл в Elements свою таблицу и понял, почему изменённая в DevTools цена исчезла после F5.

## 🔧 Сломай нарочно

Специально ломать полезно: когда ошибка случится сама, ты её сразу узнаешь. После каждого опыта верни всё как было.

**Опыт 1. Неверный путь к картинке.** Замени `img/neon-circuit.png` на `img/neon-circut.png` (пропущена буква) и сохрани. Что видно на странице? Открой Console: там сообщение `404 (Not Found)`. Код 404 — ответ сервера «такого файла нет». Ты будешь встречать его весь курс: и для картинок, и для страниц, и для данных с сервера.

**Опыт 2. Забытый закрывающий тег.** Удали `</strong>` после `Prism Drive` и сохрани. Сколько текста стало жирным? Посмотри в Elements, где браузер сам закрыл тег. Браузер очень снисходителен и старается «угадать», что ты имел в виду, но угадывает не всегда так, как хотелось бы. Поэтому ошибки в HTML часто не видны сразу.

**Опыт 3. Пустой alt.** Удали атрибут `alt` целиком и снова сломай путь к картинке, как в опыте 1. Что теперь показывает браузер на месте обложки? А с `alt`? Вот зачем он нужен даже зрячим пользователям.

## Шаг 9. Публикуем на GitHub Pages

Сначала зафиксируй работу в Git:

```bash
git add .
git commit -m "Add Neon Circuit game page"
```

Сообщения коммитов в курсе пишем **на английском**, как в большинстве реальных команд. Формат простой: глагол в повелительном наклонении с большой буквы и что сделано, до 50 символов, без точки в конце. Например: `Add cart page`, `Fix cover image path`, `Update price table`. Читать это нужно как продолжение фразы «Если применить этот коммит, он… *add cart page*».

Теперь создай репозиторий на GitHub: **New repository** → имя `pixelport` → видимость **Public** → без README и `.gitignore` (они у нас будут свои) → **Create repository**. GitHub покажет команды для существующего репозитория. Нам нужны две из них:

```bash
git remote add origin https://github.com/ЛОГИН/pixelport.git
git push -u origin main
```

Обнови страницу репозитория на GitHub: там должны появиться `index.html` и папка `img`.

Включи публикацию: в репозитории **Settings → Pages**. В разделе **Build and deployment** выбери **Source: Deploy from a branch**, ветку **main** и папку **/ (root)** → **Save**.

Подожди одну-две минуты. Ход публикации виден на вкладке **Actions**: там появится задача *pages build and deployment*. Когда она станет зелёной, открой:

```text
https://ЛОГИН.github.io/pixelport/
```

Это твой сайт в интернете. Отправь ссылку себе в мессенджер и открой с телефона. Можно и так: в Chrome на компьютере нажми значок «Поделиться» в адресной строке → **Создать QR-код** и наведи на него камеру телефона.

GitHub Pages — бесплатный хостинг статических сайтов: он просто раздаёт файлы из репозитория так же, как Live Server раздаёт их с твоего компьютера. После каждого `git push` сайт обновляется сам через минуту-другую.

**Если через 3–4 минуты сайт не открывается**, а на вкладке **Actions** пусто, значит публикация не запустилась. Так бывает, когда Pages включили уже после push. В **Settings → Pages** выбери ветку **None** → **Save**, затем снова **main** и **/ (root)** → **Save**. Задача на вкладке Actions появится через несколько секунд.

> ✅ **Проверь себя:** страница открывается по ссылке `github.io` на компьютере и на телефоне, обложка видна, ссылка «Системные требования» работает.

На телефоне страница выглядит мелковато и картинка не тянется по ширине — это нормально. Адаптивную вёрстку для телефонов сделаем в №06.

## Дополнительные квесты

Квесты не обязательны и не понадобятся в следующих работах. Делай их, если основная часть готова.

### ★★ Отзывы прессы

Добавь перед подвалом раздел «Что пишут критики» с двумя-тремя вымышленными цитатами. Для цитаты есть специальный тег:

```html
<blockquote>
  <p>Лучшая ночная гонка этого года. Неон ещё никогда не был таким быстрым.</p>
  <footer>— <cite>Журнал «Игровой Пульс»</cite>, 9/10</footer>
</blockquote>
```

Подсказка: внутри `<blockquote>` может быть свой `<footer>`, и это не конфликтует с подвалом страницы, ведь у каждого блока свой «подвал».

### ★★ Частые вопросы

Добавь раздел «Вопросы и ответы» из трёх раскрывающихся пунктов. Для этого не нужен JavaScript:

```html
<details>
  <summary>Есть ли в игре русский язык?</summary>
  <p>Да, интерфейс и субтитры полностью на русском.</p>
</details>
```

Нажми на вопрос в браузере. Что делает атрибут `open`, если добавить его к `<details>`?

### ★★★ Своя игра

Придумай собственную игру: название, жанр, разработчика, цену и описание. Сделай для неё вторую страницу `my-game.html` с той же структурой. Вместо обложки используй `img/no-cover.png` или свою картинку 3:4 (если берёшь её из интернета, она должна быть свободной для использования). Добавь на страницу своей основной игры ссылку на новую страницу:

```html
<a href="my-game.html">Ещё игра от меня</a>
```

Проверь, что ссылка работает и на `github.io`.

## Шпаргалка

| Тег | Что значит |
| --- | --- |
| `<h1>`…`<h6>` | Заголовки разных уровней |
| `<p>` | Абзац |
| `<strong>`, `<em>` | Важный текст, смысловое выделение |
| `<del>`, `<mark>` | Удалённый (зачёркнутый) текст, пометка |
| `<img src alt width>` | Картинка |
| `<a href>` | Ссылка (`#id` — на элемент этой страницы) |
| `<ul>`, `<ol>`, `<li>` | Маркированный и нумерованный списки, пункт |
| `<table>`, `<tr>`, `<th>`, `<td>` | Таблица, строка, заголовок ячейки, ячейка |
| `<thead>`, `<tbody>` | Шапка и тело таблицы |
| `<header>`, `<main>`, `<footer>` | Шапка, основное содержимое, подвал |
| `<button type="button">` | Кнопка |
