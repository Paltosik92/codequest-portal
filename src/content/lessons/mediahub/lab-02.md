## Шаг 1. Переименуй страницу игры

Главной страницей сайта станет витрина, а страница игры переедет в `game.html`. Переименуй файл через Git, а не через проводник:

```bash
git mv index.html game.html
git status
```

`git status` покажет `renamed: index.html -> game.html`. Если переименовать файл в проводнике, Git сначала увидит «один файл удалён, другой появился» и только потом, при коммите, догадается, что это переименование. `git mv` сразу говорит Git, что происходит, и история файла не теряется.

Если Live Server был открыт на `index.html`, браузер сейчас покажет список файлов или ошибку: главной страницы больше нет. Открой `game.html` и проверь, что игра на месте.

> ✅ **Проверь себя:** в VS Code больше нет `index.html`, есть `game.html`, и он открывается в браузере.

## Шаг 2. Шапка с меню

У каждого магазина есть шапка, которая одинакова на всех страницах: логотип и меню разделов. Открой `game.html` и замени старый `<header>` на новый:

```html
  <header>
    <a href="index.html">
      <img src="img/logo.svg" alt="PixelPort — на главную" width="160">
    </a>
    <nav>
      <ul>
        <li><a href="index.html">Магазин</a></li>
        <li><a href="library.html">Библиотека</a></li>
        <li><a href="cart.html">Корзина (2)</a></li>
        <li><a href="admin.html">Админка</a></li>
      </ul>
    </nav>
  </header>
```

Что здесь важно:

- **Логотип — это ссылка на главную.** Пользователи привыкли к этому на любом сайте. Картинка внутри ссылки описывает, *куда ведёт ссылка*, поэтому `alt` здесь «PixelPort — на главную», а не «Логотип с буквой P».
- **`<nav>`** — смысловой контейнер «главная навигация». Программы экранного доступа позволяют сразу перепрыгнуть к нему.
- **Меню — это список.** Пункты меню и есть список ссылок, поэтому их кладут в `<ul>`. Сейчас видны точки, а в №04 мы превратим этот список в горизонтальное меню.
- **Пути относительные.** `href="library.html"` значит «файл `library.html` в той же папке, где лежит текущая страница». Поэтому сайт работает и на Live Server, и на GitHub Pages, где адрес начинается с `/pixelport/`.

Страницы игры в меню нет, и это правильно: игру открывают из карточки на витрине, отдельным разделом она не является. Но ссылку «назад» дадим. Добавь сразу после `<main>` в `game.html`:

```html
    <p><a href="index.html">← Все игры</a></p>
```

Сейчас ссылки в меню ведут на несуществующие страницы. Нажми, например, «Библиотека» — Live Server ответит ошибкой. Сейчас исправим.

> ✅ **Проверь себя:** в шапке `game.html` логотип PixelPort и список из четырёх ссылок.

## Шаг 3. Витрина

Создай новый `index.html`. Скопируй из `game.html` всё от `<!DOCTYPE html>` до `</header>` включительно и `<footer>` в конце. Поменяй `<title>` на `PixelPort — магазин инди-игр`. Между шапкой и подвалом напиши витрину:

```html
  <main>
    <section>
      <h1>Зимняя распродажа уже близко</h1>
      <p>Скидки до 60% на инди-хиты. Добавь игры в желаемое, чтобы не пропустить старт.</p>
      <img src="img/hero.png"
           alt="Путник в красном плаще смотрит на долину с замком и огромной планетой в небе"
           width="600">
      <p><a href="#catalog">Смотреть игры</a></p>
    </section>

    <section id="catalog">
      <h2>Хиты недели</h2>

      <article>
        <a href="game.html">
          <img src="img/neon-circuit.png" alt="Неоновый спорткар на ночной трассе" width="180">
          <h3>Neon Circuit</h3>
        </a>
        <p>Гонки · 2025</p>
        <p><del>1499 ₽</del> <strong>599 ₽</strong> <mark>−60%</mark></p>
      </article>

      <article>
        <a href="game.html">
          <img src="img/mossbound.png" alt="Каменные ворота среди покрытых мхом руин" width="180">
          <h3>Mossbound</h3>
        </a>
        <p>Приключения · 2023</p>
        <p><del>899 ₽</del> <strong>629 ₽</strong> <mark>−30%</mark></p>
      </article>

      <!-- Ещё минимум две карточки по тому же образцу -->
    </section>
  </main>
```

Допиши ещё минимум две карточки по образцу. Данные игр — в таблице из №01. Твоя игра должна быть среди карточек. Если у игры нет скидки, в цене оставь только `<strong>`.

Новые теги:

- **`<section>`** — раздел страницы со своим заголовком. На витрине два раздела: баннер и каталог.
- **`<article>`** — самостоятельный кусок, который имеет смысл и сам по себе: карточку игры можно вырезать и вставить на другую страницу или в рассылку, и она останется понятной. Поэтому карточка — `article`, а не просто блок.
- **`<!-- … -->`** — комментарий. Браузер его не показывает.
- **`<h3>` внутри ссылки.** В HTML5 ссылка может содержать целый блок: и картинку, и заголовок. Тогда кликабельна вся верхняя часть карточки.

Обрати внимание на иерархию заголовков: `h1` — главное на странице (распродажа), `h2` — раздел каталога, `h3` — каждая игра внутри раздела.

**Честное ограничение.** Пока все карточки ведут на одну и ту же `game.html`, ведь страница игры у нас одна. Сделать 12 одинаковых файлов `game-1.html`, `game-2.html` можно, но это тупиковый путь: представь, что у магазина 50 000 игр. В №10 одна страница `game.html` научится показывать любую игру — для этого нам понадобится TypeScript.

> ✅ **Проверь себя:** открой `index.html` в Live Server. Нажми «Смотреть игры» — страница прокрутится к каталогу. Нажми на карточку — откроется страница игры. Логотип возвращает назад.

## Шаг 4. Корзина

Создай `cart.html` с той же шапкой и подвалом. Содержимое `<main>`:

```html
  <main>
    <h1>Корзина</h1>

    <table>
      <thead>
        <tr>
          <th>Игра</th>
          <th>Цена</th>
          <th>Действие</th>
        </tr>
      </thead>
      <tbody>
        <tr>
          <td>
            <img src="img/neon-circuit.png" alt="" width="60">
            <a href="game.html">Neon Circuit</a>
          </td>
          <td>599 ₽</td>
          <td><button type="button">Удалить</button></td>
        </tr>
        <tr>
          <td>
            <img src="img/mossbound.png" alt="" width="60">
            <a href="game.html">Mossbound</a>
          </td>
          <td>629 ₽</td>
          <td><button type="button">Удалить</button></td>
        </tr>
      </tbody>
      <tfoot>
        <tr>
          <th>Итого</th>
          <td colspan="2"><strong>1228 ₽</strong></td>
        </tr>
      </tfoot>
    </table>

    <form>
      <label for="promo">Промокод</label>
      <input id="promo" name="promo" type="text" placeholder="Например, PIXEL10">
      <button type="submit">Применить</button>
    </form>

    <p><button type="button">Оформить заказ</button></p>
  </main>
```

Два новых момента:

- **`<tfoot>`** — подвал таблицы. В нём живёт итог. Вместе с `thead` и `tbody` получается полная структура таблицы.
- **`alt=""` у миниатюр.** Пустой `alt` — не ошибка, а осознанное решение: рядом уже написано название игры, и программе экранного доступа не нужно читать его дважды. Пустой `alt` говорит «картинка декоративная, пропусти её». А вот *отсутствие* атрибута `alt` — ошибка.

Не забудь отметить в шапке текущий раздел. Об этом подробнее в шаге 7, а пока просто сделай корзину.

> ✅ **Проверь себя:** в таблице корзины три части: шапка, две игры, итог.

## Шаг 6. Админка: форма новой игры

Создай `admin.html`. Это страница Ани: здесь она будет добавлять игры в каталог. Главное на ней — **форма**.

```html
  <main>
    <h1>Управление каталогом</h1>

    <form>
      <fieldset>
        <legend>Новая игра</legend>

        <p>
          <label for="title">Название</label><br>
          <input id="title" name="title" type="text" required maxlength="80">
        </p>

        <p>
          <label for="developer">Разработчик</label><br>
          <input id="developer" name="developer" type="text" required>
        </p>

        <p>
          <label for="genre">Жанр</label><br>
          <select id="genre" name="genre" required>
            <option value="">— выберите жанр —</option>
            <option value="1">Приключения</option>
            <option value="2">Гонки</option>
            <option value="3">Стратегии</option>
            <option value="4">Головоломки</option>
          </select>
        </p>

        <p>
          <label for="year">Год выхода</label><br>
          <input id="year" name="year" type="number" min="1980" max="2030" required>
        </p>

        <p>
          <label for="price">Цена, ₽</label><br>
          <input id="price" name="price" type="number" min="0" step="1" required>
        </p>

        <p>
          <label for="discount">Скидка, %</label><br>
          <input id="discount" name="discount" type="number" min="0" max="90" value="0">
        </p>

        <p>
          <label for="description">Описание</label><br>
          <textarea id="description" name="description" rows="4" cols="50"></textarea>
        </p>
      </fieldset>

      <fieldset>
        <legend>Теги</legend>
        <label><input type="checkbox" name="tags" value="cyberpunk"> киберпанк</label>
        <label><input type="checkbox" name="tags" value="cozy"> уют</label>
        <label><input type="checkbox" name="tags" value="multiplayer"> мультиплеер</label>
        <label><input type="checkbox" name="tags" value="story"> сюжет</label>
      </fieldset>

      <p><button type="submit">Сохранить игру</button></p>
    </form>
  </main>
```

Разберём форму, потому что формы — это главный способ, которым пользователь отправляет данные на сервер. Весь блок 4 курса будет про это.

- **`<label for="title">` и `id="title"`** связывают подпись с полем. Щёлкни по слову «Название» — курсор прыгнет в поле. Программа экранного доступа прочитает подпись, когда пользователь попадёт в поле. Поле без подписи — частая и неприятная ошибка.
- **`name="title"`** — имя, под которым значение поля уйдёт на сервер. `id` нужен странице, `name` — серверу.
- **`type`** меняет поведение поля: `number` не даст ввести буквы и покажет стрелки, на телефоне откроется цифровая клавиатура.
- **`required`, `min`, `max`, `maxlength`** — встроенные проверки браузера.
- **`<select>` с `<option>`** — выпадающий список. Пользователь видит «Гонки», а на сервер уйдёт `value="2"`. Пустое `value=""` у первого пункта вместе с `required` заставляет действительно выбрать жанр.
- **`<fieldset>` и `<legend>`** группируют поля и подписывают группу.
- **Чекбокс внутри `<label>`** — второй способ связать подпись с полем: не нужны `for` и `id`, щёлкать можно по слову.

**Посмотри, куда уходят данные.** Нажми «Сохранить игру» с пустыми полями: браузер не даст отправить форму и подсветит первое незаполненное поле. Теперь заполни все поля, отметь пару тегов и отправь. Страница перезагрузится, а в адресной строке появится что-то такое:

```text
admin.html?title=Ember+Leap&developer=Hot+Rock&genre=2&year=2023&price=499&discount=0&description=…&tags=cozy&tags=story
```

Это и есть данные формы: пары `name=значение`, соединённые `&`. Пробелы превратились в `+`, а русские буквы — в коды вида `%D0%B8`. Сейчас эти данные никому не нужны: принимать их некому. В №20 их примет сервер на C# и сохранит игру в базе данных.

> ✅ **Проверь себя:** щелчок по подписи ставит курсор в поле; пустую форму отправить нельзя; после отправки заполненной формы в адресе видны значения полей.

## Шаг 7. Отметь текущий раздел

В меню каждой страницы пользователь должен видеть, где он находится. Для этого у ссылки на текущую страницу ставят атрибут `aria-current="page"`. Например, в `cart.html`:

```html
        <li><a href="cart.html" aria-current="page">Корзина (2)</a></li>
```

Расставь `aria-current="page"` на всех страницах:

| Страница | Какой пункт отмечен |
| --- | --- |
| `index.html` | Магазин |
| `game.html` | Магазин (игра — часть магазина) |
| `cart.html` | Корзина |
| `library.html` | Библиотека |
| `admin.html` | Админка |

Сейчас атрибут внешне ничего не меняет. Программа экранного доступа прочитает «текущая страница», а в №04 мы подсветим этот пункт через CSS: селектор найдёт его именно по этому атрибуту.

Наверное, ты уже заметил неудобство: шапка скопирована в пять файлов. Если Аня попросит переименовать «Админку» в «Управление», придётся исправлять пять мест и не ошибиться ни в одном. Запомни это ощущение: у программистов на него аллергия. Хорошее решение появится, когда страницы начнут строиться из данных и общих модулей.

> ✅ **Проверь себя:** пройди по сайту как покупатель: витрина → игра → «Все игры» → корзина → библиотека → админка → логотип. Ни одного 404, и на каждой странице отмечен свой пункт меню.

## Шаг 8. Публикуем и проверяем валидатором

```bash
git add .
git commit -m "Add storefront, cart, library and admin pages"
git push
```

Через минуту-две открой `https://ЛОГИН.github.io/pixelport/`. Теперь по этому адресу витрина, а не страница игры. Пройди тот же маршрут, что в шаге 7, но уже на `github.io`.

Теперь проверим HTML автоматически. Открой валидатор W3C: [validator.w3.org/nu](https://validator.w3.org/nu/). Выбери **Check by address**, вставь адрес своей витрины и нажми **Check**. Валидатор найдёт то, что браузер молча «простил»: незакрытые теги, повторяющиеся `id`, картинки без `alt`. Проверь так все пять страниц: адреса вида `https://ЛОГИН.github.io/pixelport/cart.html`.

Предупреждения (*Warning*) можно прочитать и подумать над ними. Ошибки (*Error*) нужно исправить, затем сделать коммит и push.

> ✅ **Проверь себя:** на всех пяти страницах на `github.io` валидатор показывает *No errors*, а все ссылки работают.

## 🔧 Сломай нарочно

**Опыт 1. Большая буква в адресе.** В шапке `index.html` замени `cart.html` на `Cart.html` и сохрани. Нажми «Корзина» в Live Server — работает! Теперь сделай коммит, push и подожди публикации. Нажми «Корзина» на `github.io` — 404.

Почему: Windows не различает большие и маленькие буквы в именах файлов, поэтому `Cart.html` и `cart.html` для неё одно и то же. А серверы в интернете почти всегда работают на Linux, где это два разных файла. Ошибка «у меня работает, на сервере нет» — одна из самых частых у начинающих веб-разработчиков. Правило на весь курс: **имена файлов и папок — только строчные латинские буквы, цифры и дефисы**. Верни `cart.html` и отправь исправление коммитом `Fix cart link case`.

**Опыт 2. Подпись без связи.** В админке у поля «Цена» замени `for="price"` на `for="prise"`. Щёлкни по подписи «Цена»: курсор больше не прыгает в поле. Внешне форма та же, а пользоваться ею стало хуже — особенно тем, кто работает с клавиатуры или с экранным диктором. Валидатор такую ошибку тоже найдёт. Верни как было.

**Опыт 3. Поле без name.** Убери `name="developer"` у поля разработчика, заполни и отправь форму. Посмотри в адресную строку: разработчика там нет. Поле без `name` браузер на сервер не отправляет. Это пригодится в №20, когда «сервер не видит поле» — первым делом проверяй `name`. Верни атрибут.

## Дополнительные квесты

### ★★ Полный каталог

Выведи на витрине все восемь игр. Обрати внимание, сколько однотипного HTML пришлось написать. В №08 восемь карточек будет рисовать цикл из нескольких строк TypeScript.

### ★★ Своя страница 404

GitHub Pages умеет показывать твою страницу вместо стандартной ошибки 404. Создай `404.html` с той же шапкой, заголовком «Такой игры нет на нашей полке», картинкой `img/no-cover.png` и ссылкой на витрину. Опубликуй и открой несуществующий адрес, например `https://ЛОГИН.github.io/pixelport/minecraft`.

### ★★ Хлебные крошки

На странице игры добавь перед `<h1>` «хлебные крошки» — путь от главной до текущей страницы:

```html
<nav aria-label="Хлебные крошки">
  <ol>
    <li><a href="index.html">Магазин</a></li>
    <li><a href="index.html#catalog">Гонки</a></li>
    <li aria-current="page">Neon Circuit</li>
  </ol>
</nav>
```

Почему здесь `ol`, а не `ul`? Зачем `aria-label`, если на странице уже есть один `<nav>`?

### ★★★ Панель поиска

Над карточками на витрине добавь разметку панели поиска: поле поиска по названию (`type="search"`), выпадающие списки «Жанр» и «Сортировка» (по популярности, сначала дешёвые, сначала дорогие, по размеру скидки) и кнопку «Сбросить». Все поля с подписями, панель внутри `<form>`. Работать панель начнёт в №09, а сейчас нужно продумать, какие поля нужны покупателю, и аккуратно их разметить. Проверь страницу валидатором.

## Шпаргалка

| Тег / атрибут | Что значит |
| --- | --- |
| `<nav>` | Блок навигации |
| `<section>` | Раздел страницы со своим заголовком |
| `<article>` | Самостоятельный фрагмент (карточка, пост, отзыв) |
| `<tfoot>` | Подвал таблицы (итоги) |
| `<form>` | Форма: собирает данные полей и отправляет их |
| `<label for>` + `id` | Подпись, связанная с полем |
| `<input type="text / number / search / checkbox">` | Поле ввода разных видов |
| `<select>`, `<option value>` | Выпадающий список |
| `<textarea>` | Многострочное поле |
| `<fieldset>`, `<legend>` | Группа полей и её подпись |
| `name` | Имя поля в отправленных данных |
| `required`, `min`, `max`, `maxlength` | Встроенные проверки браузера |
| `aria-current="page"` | Отметка текущей страницы в навигации |
| `alt=""` | Декоративная картинка, диктор её пропускает |
