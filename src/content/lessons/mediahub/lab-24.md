## Шаг 1. Запускаем версию с жалобами

1. **Скопируй** папку `lab24-pixelport-bugs` к себе, рядом со своим проектом, а не внутрь него. Назови `pixelport-bugs`. Открой её в VS Code и сделай первый коммит — это «релиз», от которого ты будешь считать исправления:

   ```bash
   git init
   git add .
   git commit -m "Import PixelPort 1.0 release"
   ```

2. В `server/appsettings.json` поставь имя **своей** базы приложения, как в №18. В `src/storage.ts` замени `is31-ivanov` в `STUDENT_CODE` на свой код — приставку `bughunt-` оставь: так корзина и желаемое этого проекта не смешаются с твоими.

3. Собери и запусти:

   ```bash
   npm install
   npm run build
   dotnet tool restore
   cd server
   export PGPASSWORD='твой пароль'
   dotnet ef database update
   dotnet run
   ```

4. Открой `http://localhost:5080` — витрина из 12 игр. В psql в своей базе: `\dn` — появилась схема `bugs` рядом с `public`. Таблицы проекта видны так:

   ```sql
   SET search_path TO bugs;
   \dt
   ```

   `SET search_path` действует до выхода из psql. Без него `SELECT * FROM games` покажет игры **твоего** магазина из `public`.

Начать с чистой базы, если что-то пошло не так: `DROP SCHEMA bugs CASCADE;` в psql и снова `dotnet ef database update`.

> Одна известная особенность, не из списка жалоб: второй отзыв того же игрока на ту же игру — 500. Это ограничение из №19 (квест ★★★). Для отзывов выбирай игрока, который ещё не писал об этой игре.

## Шаг 2. Как ловить баг

Баг — это разница между **ожидаемым** и **фактическим**. Охота — пять шагов, и пропускать нельзя ни одного:

| Этап | Вопрос | Результат |
| --- | --- | --- |
| 1. Воспроизвести | Как увидеть баг своими глазами? | Точные шаги, после которых баг есть всегда |
| 2. Локализовать | В каком слое? Браузер, запрос, сервер, база? | Слой, где данные впервые стали неправильными |
| 3. Доказать | Чем подтвердить причину? | Запрос, строка лога, результат SQL, скриншот |
| 4. Исправить | Что изменить в причине? | Минимальная правка + коммит |
| 5. Проверить | Баг ушёл? Не сломал ли я соседнее? | Повтор шагов воспроизведения |

**Главный приём локализации — идти по пути данных и смотреть, где они испортились.** Цепочка у нас всегда одна: база → C# → JSON → TypeScript → страница. Проверь середину — запрос в Network. Если в ответе сервера уже неправильно — ищи в сервере или базе. Если в ответе правильно, а на странице нет — ищи во фронтенде. Каждая проверка отсекает половину кода.

Инструменты по слоям:

| Где смотреть | Что видно |
| --- | --- |
| DevTools → **Elements** | Какой элемент на самом деле под курсором, какие стили к нему применены |
| DevTools → **Console** | Ошибки JavaScript и `console.log` |
| DevTools → **Network** | Что браузер отправил (Payload) и что сервер ответил (Response), статус |
| DevTools → **Application** → Local Storage | Что сохранено в браузере |
| Консоль сервера | Ошибки C#, SQL, который выполнил EF Core |
| `.http` | Запрос к серверу без фронтенда |
| psql | Что на самом деле лежит в базе |

## Шаг 3. Разбираем вместе: жалоба 1

**Воспроизводим.** На главной поставь фильтр цены «до 1000 ₽». Neon Circuit (на карточке 599 ₽) пропала. Сними фильтр — появилась. Баг есть всегда — значит, его можно ловить.

**Локализуем.** DevTools → Network, снова поставь фильтр. Найди запрос `games?maxPrice=1000…` и открой Response: Neon Circuit в ответе **нет**. Значит, фронтенд ни при чём — он показал то, что прислал сервер. Проверим сервер без браузера, в `.http`:

```http
GET {{host}}/api/games?maxPrice=1000
```

Её нет и здесь. Смотрим в базу:

```sql
SET search_path TO bugs;
SELECT title, price, discount_percent, final_price FROM games WHERE title = 'Neon Circuit';
```

```text
    title     | price | discount_percent | final_price
--------------+-------+------------------+-------------
 Neon Circuit |  1499 |               60 |         599
```

**Гипотеза:** фильтр сравнивает с полной ценой 1499, а не с ценой со скидкой 599.

**Доказываем.** В консоли сервера найди SQL этого запроса. В нём `WHERE g.price <= @maxPrice` — не `final_price`. А в `GameEndpoints.cs`:

```csharp
found = found.Where(game => game.Price <= maxPrice);
```

Доказательство полное: база хранит 599, SQL сравнивает с 1499, строка кода найдена.

**Исправляем** — одно слово: `game.Price` → `game.FinalPrice`. Покупатель видит и платит цену со скидкой — по ней и фильтруем.

**Проверяем.** Перезапусти сервер. Фильтр «до 1000 ₽» — Neon Circuit на месте; в SQL `final_price`. Заодно проверь соседнее: без фильтра — 12 игр, фильтр «до 500 ₽» — Ember Leap (499) и Cloud Bakery (349).

**Коммит и отчёт.** Скопируй `bugs/TEMPLATE.md` в `bugs/BUG-01.md` и заполни:


## Шаг 4. Жалобы 2–5 — сам

Для каждой — тот же цикл, отдельный коммит и отчёт `bugs/BUG-0N.md`. Под каждой жалобой — с чего начать. Подсказку открывай, только если застрял минут на пять.

### Жалоба 2. Не нажимается «В корзину» у игр со скидкой

**С чего начать:** Elements. Щёлкни правой кнопкой по «В корзину» у Neon Circuit → «Просмотреть код». Какой элемент выделился? Сравни с игрой без скидки. Почему сердечко при этом нажимается?

<details>
<summary>Подсказка</summary>

Поверх карточки лежит невидимый слой — псевдоэлемент. В Elements он виден внутри `<article class="card">` как `::after`. Найди его правило в `styles.css` (поиск по `data-discount`). Слой занимает всю карточку (`inset: 0`) и перехватывает клики. У сердечка `z-index: 1` — оно выше слоя. Слою нужно не «уйти вниз», а **пропускать клики сквозь себя**: свойство `pointer-events`.

</details>

**Проверь после исправления:** у игры со скидкой нажимаются «В корзину», ♡, обложка и название; блик на карточке остался.

### Жалоба 3. 👍 превращается в 👎

**С чего начать:** воспроизведи (игрок Nova, Dune Runner — она ещё не писала о ней отзыв) с открытым Network. Что браузер **отправил** — вкладка Payload у запроса `reviews`? Что сервер **ответил**? Сравни имена полей с записью `NewReview` в `GameDtos.cs`.

<details>
<summary>Подсказка</summary>

Браузер отправил `isRecomended` — с одной «m». Сервер ждёт `isRecommended`, незнакомое поле молча пропускает (помнишь `"total": 1` из №22?), а `bool`, которого нет в JSON, — это `false`. Опечатка во фронтенде, в интерфейсе `NewReview` в `models.ts`. Исправь имя в интерфейсе и запусти `npm run build`: TypeScript сам покажет, где ещё осталась опечатка.

</details>

Баг уже испортил данные: отзыв Nova в базе лежит с `is_recommended = false`. Найди его в psql и исправь `UPDATE`. В отчёте напиши, как поддержке найти и исправить другие такие отзывы. Можно ли вообще отличить «испорченный» 👎 от настоящего?

**Проверь после исправления:** отзыв с 👍 (другой игрок или другая игра) публикуется с 👍, рейтинг растёт; с 👎 — с 👎.

### Жалоба 4. «Желаемое» не сохраняется

**С чего начать:** Application → Local Storage → `http://localhost:5080`. Нажми ♡ и посмотри, какой ключ изменился. Обнови страницу. Какой ключ код **читает** при загрузке?

<details>
<summary>Подсказка</summary>

Ключей два: `…:wishlist` и `…:wishList`. Пишется один, читается другой. Найди в `main.ts` все `saveIds` и `loadIds` — где-то имя отличается одной буквой. TypeScript здесь не поможет: для него это просто две разные строки.

</details>

**Проверь после исправления:** ♡ на главной → обнови → сердечко закрашено, игра в «Желаемом» на странице библиотеки. Лишний ключ из Local Storage можно удалить (Delete).

### Жалоба 5. Скидка 75% «ничего не делает»

**С чего начать:** нажми «Применить» с 75% и посмотри на три места: Console браузера, Network (статус ответа) и **консоль сервера**. Где написана настоящая причина?

<details>
<summary>Подсказка</summary>

Сервер ответил 500. В его консоли — `23514: new row for relation "games" violates check constraint "ck_games_discount"`. Это база отказалась сохранять строку. В psql `\d games`: ограничение `discount_percent <= 70`, хотя проверка в `GameValidation.cs` разрешает до 90. Две проверки одного правила разошлись. Ограничение задано в `PixelPortDb.cs` (`HasCheckConstraint`). Исправь там и создай **новую** миграцию: `dotnet ef migrations add FixDiscountCheck`, затем `dotnet ef database update`. Загляни в созданный файл: EF Core удаляет старое ограничение и создаёт новое.

</details>

Заодно подумай: почему админка **промолчала**, хотя сервер ответил ошибкой? Найди в Console, что случилось с этой ошибкой, и в отчёте отметь, что ещё стоит исправить в `admin.ts`.

**Проверь после исправления:** 75% → цена Mossbound 224 ₽, на витрине тоже. 95% → по-прежнему понятная ошибка 400 у поля. В psql `\d games` — `<= 90`.

> ✅ **Проверь себя:** пять жалоб — пять коммитов (`git log --oneline` — шесть строк вместе с импортом) и пять отчётов в `bugs/`. Пройди все пять сценариев ещё раз подряд: исправление одного бага не должно было вернуть другой.

```text

```
