## Шаг 2. Слой за слоем

Иди по плану. Для каждого шага:

1. Напиши код **одного** шага.
2. Собери: `dotnet build` и/или `npm run build`.
3. Проверь именно этот шаг: запрос в `.http`, `\d` в psql, страница в браузере.

Где что проверять:

| Слой | Чем проверить |
| --- | --- |
| База | `dotnet ef database update`, в psql `\d таблица`, `SELECT` |
| Сервер | Запросы в `.http` — сначала «хорошие», потом «плохие» из контракта |
| Фронтенд с сервером | `localhost:5080`, Network: что ушло, что пришло |
| Фронтенд без сервера | Live Server: работает или честно говорит «нужен сервер» |
| Вёрстка | Узкое окно (DevTools → телефон), длинные названия |

Если застрял больше чем на 10 минут — включай режим охоты из №24: воспроизвести, локализовать по пути данных, доказать. Не помогло — спроси соседа, потом преподавателя. С собой приноси **доказательство**: запрос и ответ, строку лога, а не «у меня не работает».

## Шаг 3. Приёмы из примера

Пример PIX-100 «Выбор редакции» из №27 сделан до конца. Вот приёмы из него, которые встречаются почти в каждой функции меню.

**Отличить «нет поля» от `false`.** В `PUT` с телом `{ "isEditorsChoice": true }` поле объявлено как `bool?`. Если клиент прислал `{ }`, будет `null`, а не тихий `false`:

```csharp
// Отметка «Выбор редакции»: bool? — чтобы отличить «нет поля» от false
public record EditorsChoiceInput(bool? IsEditorsChoice);
```

```csharp
        api.MapPut("/{id:int}/editors-choice", async (PixelPortDb db, int id, EditorsChoiceInput input) =>
        {
            Game? game = await db.Games.FindAsync(id);
            if (game is null)
            {
                return GameNotFound(id);
            }
            if (input.IsEditorsChoice is null)
            {
                return Results.ValidationProblem(new Dictionary<string, string[]>
                {
                    ["isEditorsChoice"] = ["Укажи true или false"],
                });
```

**Новый параметр фильтра — в обоих режимах.** Параметр появляется в четырёх местах:

- в `CatalogFilters` (`filters.ts`);
- в `toQuery` (`api.ts`) — для сервера;
- в `selectGames` (`filters.ts`) — для режима без сервера;
- в `readFilters` (`main.ts`) — из формы.

TypeScript сам укажет на `ALL_GAMES`, где поле забыли. Новое поле в `catalog.json` называется не так, как в API, — его переводят при загрузке файла:

```ts
    // В файле отметка называется editorsChoice и есть только у игр подборки
    type CatalogItem = Omit<GameDetails, "finalPrice" | "isEditorsChoice"> & { editorsChoice?: boolean };
    const raw = await getJson<CatalogItem[]>(CATALOG_URL);
    staticGames = raw.map(({ editorsChoice, ...game }) => ({
      ...game,
      finalPrice: calculateFinalPrice(game.price, game.discountPercent),
      isEditorsChoice: editorsChoice ?? false,
    }));
```

**Переключатель с откатом.** Флажок сохраняется сразу. Если сервер ответил ошибкой или не ответил — флажок возвращается в прежнее положение, и пользователь видит, что не сохранилось:

```ts
// Флажок «Выбор редакции»: сохраняем сразу, при ошибке возвращаем как было
async function onChoiceChange(event: Event): Promise<void> {
  const input = event.target;
  if (!(input instanceof HTMLInputElement) || !input.classList.contains("choice-input")) {
    return;
  }
  const row = input.closest("tr");
  const id = Number(row?.dataset.gameId);
  const title = row?.querySelector("a")?.textContent ?? "";
  const wanted = input.checked;

  input.disabled = true;
  try {
    const result = await putEditorsChoice(id, wanted);
    if (!result.ok) {
      throw new Error(result.message);
    }
    setText("#admin-catalog-message", wanted ? `«${title}» — в выборе редакции.` : `«${title}» убрана из выбора редакции.`);
  } catch (error) {
    input.checked = !wanted;
    setText("#admin-catalog-message", `«${title}»: не сохранилось — ${error instanceof Error ? error.message : "ошибка"}`);
  } finally {
    input.disabled = false;
  }
}
```

Тот же приём — для «👍 Полезно», «Сравнить», ♡: интерфейс не должен показывать то, чего на сервере нет.

**Бейдж поверх картинки.** Обложку оборачивают в элемент с `position: relative`, бейдж внутри — `position: absolute`:

```ts
  // Обложка в обёртке: на неё ложится бейдж «Выбор редакции»

    badge.textContent = "★ Выбор редакции";
    coverBox.append(badge);
  }
```

## Проверка критериев

| № | Как проверил | Итог |
| --- | --- | --- |
| 1 | Витрина: бейдж у Lantern Valley, Iron Harbor, Hollow Bell; … | ✅ |
| 3 | … Остановил сервер и щёлкнул флажок — он вернулся обратно, сообщение «не сохранилось» | ✅ |

Нашёл ❌ — чини и проверяй снова. Не успеваешь — честно оставь ❌ и напиши почему. Скрытый ❌ всё равно найдут на защите, а честный — это решение.

## Шаг 5. Ревью и слияние

1. Поставь в тикете **Статус** «сделано». Закоммить и отправь.
2. В PR нажми **Ready for review** — черновик станет обычным PR. В описание скопируй таблицу проверки критериев.
3. **Reviewers** — сосед. Он проверяет код по списку:

   - [ ] Функция работает у **него** — он скачал ветку (`git fetch`, `git switch feature/…`), собрал и прошёл два-три критерия сам.
   - [ ] В коде нет отладочного `console.log`, закомментированного кода, паролей.
   - [ ] Миграции в коммите есть; `js/` собран.
   - [ ] Имена понятны; повторяющийся код вынесен в функцию.
   - [ ] «Плохие» случаи обрабатываются и в коде сервера, и на странице.

   Хотя бы один комментарий к строке кода — по делу.

4. Исправь по ревью (новые коммиты в ту же ветку), ответь на комментарии.
5. Approve от соседа → **Merge pull request** → Delete branch.
6. Локально:

   ```bash
   git switch main
   git pull
   git branch -d feature/<имя>
   ```

7. Через пару минут проверь `github.io`: в режиме без сервера функция работает или честно молчит, а витрина не сломана.

> ✅ **Проверь себя:**
> - PR влит; в нём — ревью соседа с комментарием, таблица проверки критериев.
> - `git log --oneline main` — коммиты твоих шагов и «Merge pull request #… from feature/…».
> - `docs/feature.md` со статусом «сделано» и таблицей проверки.
> - Все три опыта ниже пройдены, найденное исправлено.

## 🔧 Сломай нарочно

Эти опыты — для твоей функции. Сделай их **до** ревью: всё, что найдёшь, ты успеешь исправить.

**Опыт 1. Сервер упал посреди дела.** Открой страницу со своей функцией, **останови сервер** (`Ctrl+C`) и воспользуйся функцией: нажми кнопку, отправь форму, переключи флажок. Что видит пользователь? Хорошо — понятное сообщение, и интерфейс вернулся в правдивое состояние. Плохо — тишина, «вечная загрузка», флажок, который врёт, или ошибка только в Console. Вспомни жалобу 5 из №24: админка молчала ровно так.

**Опыт 2. Новая база.** Представь, что проект скачал новый человек:

```bash
dotnet ef database update 0
dotnet ef database update
dotnet run
```

Работает ли функция на чистой базе? Есть ли нужные начальные данные — сидер их создал? А если не откатывать, а просто применить миграцию к заполненной базе — тоже работает? Это генеральная репетиция №29, где проект будут поднимать с нуля.

**Опыт 3. Без сервера.** Открой магазин через Live Server. Функция работает по `catalog.json` или честно сообщает, что нужен сервер? В Console нет красных ошибок? Сломанный `github.io` увидят все, кто откроет ссылку из твоего резюме.

## Дополнительные квесты

### ★ Покажи, а не расскажи

Добавь в описание PR скриншот или короткую анимацию (GIF) функции в работе — перетащи файл в поле описания на GitHub, он загрузится сам. Ревьюер увидит результат до того, как откроет код. Эту же анимацию покажешь на демо-дне.

Если всё готово раньше — возьми один пункт из «Не входит» своего тикета. Новая ветка от свежего `main`, **новый** PR с тем же порядком: критерий, код, проверка, ревью. Старый тикет не переписывай — допиши в него раздел «Доработка».

### ★★★ Строгий ревьюер

Сделай ревью PR ещё одного одногруппника (кроме соседа) по списку из шага 5. Засчитывается, если хотя бы один твой комментарий **изменил код**: автор исправил что-то по твоему замечанию. Попроси добавить тебя в соавторы.
