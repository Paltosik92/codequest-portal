**Дисциплина:** «Разработка мобильных приложений».
**Начало:** ваш GameBox после полностью выполненной ПР1.

Бит открывает GameBox и выбирает крестики-нолики. Вчера за карточкой была только заглушка; сегодня на её месте появится настоящее поле. Два человека смогут по очереди оставлять на нём X и O.

«Первая игра начинается с первого хода», — замечает Бит. Но просто нарисовать символ мало: нужно помнить выбранную клетку, передать очередь другому игроку и не позволить затереть чужой ход.

Сегодня поле научится принимать допустимые действия. Определять, кто победил и когда партия закончилась, оно будет в следующей работе.

![Бит открывает из существующей полки GameBox первое пустое поле крестиков-ноликов](/materials/mobile-lab/img/lab2/comic-01-bit-first-board.webp)

_Продолжаем тот же GameBox: меняется содержимое уже существующего игрового экрана._

## Результат занятия

После обязательной части два человека на одном устройстве смогут:

- открыть крестики-нолики из главной полки;
- увидеть девять клеток, расположенных квадратом 3×3;
- начать с X и затем чередовать X и O;
- видеть подпись текущего игрока;
- ставить символ только в свободную клетку;
- нажать занятую клетку без изменения символа и очереди;
- очистить поле и снова начать с X;
- вернуться к существующему главному экрану GameBox.

**Это промежуточная версия игры. Проверку победы и ничьей добавим в ПР3.**

Три одинаковых символа в линию пока не останавливают игру. Полное поле не вызывает сообщение о ничьей. Эти ограничения будут честно указаны на игровом экране.

Компьютерного соперника, статистики и сохранения здесь ещё нет. Игроки сами по очереди используют одно устройство.

![После ходов в клетки 0, 4 и 8 на поле стоят X, O и X, а очередь принадлежит O](/materials/mobile-lab/img/lab2/ui-01-first-moves.webp)

_В приложении будет полная подпись: «Проверку победы и ничьей добавим в ПР3». Макет сокращает её, но не обещает уже работающий подсчёт результата._

## 2. Создаём модель девяти клеток

### 2.1. Экран показывает, модель хранит правила

Чтобы поставить X, приложению нужно ответить на два разных вопроса:

- что хранится в выбранной клетке и разрешено ли её менять;
- как показать текущее состояние на экране.

Первый вопрос решает `TicTacToeGame`. Второй — `TicTacToeScreen`.

Экран получает нажатие и передаёт индекс модели. Внутри девяти клеток не будет девяти отдельных переменных с независимыми X/O.

| Модель `TicTacToeGame`             | Экран `TicTacToeScreen`             |
| ---------------------------------- | ----------------------------------- |
| Хранит список поля                 | Читает элементы списка              |
| Хранит текущий символ              | Показывает подпись «Ход: …»         |
| Решает, допустим ли ход            | Передаёт индекс нажатой клетки      |
| Записывает символ и меняет очередь | Просит Flutter обновить отображение |
| Очищает поле методом `reset`       | Предоставляет кнопку очистки        |

Для этой работы достаточно такого разделения. Отдельные слои, сервисы и дополнительные библиотеки не нужны.

### 2.2. Три состояния одной клетки

В модели используем `enum Mark`:

```dart
enum Mark {
  empty,
  x,
  o,
}
```

Это небольшой набор допустимых значений. Клетка может быть пустой, содержать X или содержать O.

`Mark.empty` — состояние данных, а пустая строка `''` — способ показать это состояние. Мы не храним в модели случайные текстовые подписи вроде `'крестик'` или `'нолик'`.

| Значение модели | Что видит человек |
| --------------- | ----------------- |
| `Mark.empty`    | Пустая клетка     |
| `Mark.x`        | `X`               |
| `Mark.o`        | `O`               |

Первый игрок — `Mark.x`. Значение `Mark.empty` текущим игроком не назначается.

### 2.3. Девять элементов одного списка

Поле будет создано один раз при создании модели:

```dart
  final List<Mark> board = List<Mark>.filled(
    9,
    Mark.empty,
    growable: false,
  );
```

Длина списка — девять. `growable: false` запрещает добавлять и удалять элементы, но позволяет менять значение по существующему индексу.

`final` закрепляет ссылку `board` за этим списком. Содержимое клеток при этом остаётся изменяемым: иначе нельзя было бы сделать ход.

В начале данные можно представить так:

```text
индекс:  0      1      2      3      4      5      6      7      8
поле:   empty  empty  empty  empty  empty  empty  empty  empty  empty
игрок:  X
```

В интерфейсе тот же порядок раскладывается по строкам:

```text
0 | 1 | 2
---------
3 | 4 | 5
---------
6 | 7 | 8
```

Индекс начинается с нуля. Верхняя левая клетка — `0`, центральная — `4`, нижняя правая — `8`.

Девять состояний поля здесь означают девять хранимых значений клеток. Это не девять возможных позиций всей игры: комбинаций значений намного больше.

![Девять клеток сетки показывают элементы одного списка Mark с индексами от 0 до 8](/materials/mobile-lab/img/lab2/schema-02-list-to-grid.webp)

_Список и поле показывают одну позицию. `GridView` получает индекс и читает `board[index]`; собственной копии поля у клетки нет._

### 2.4. Создаём файл модели целиком

В существующей папке `lib/games/tic_tac_toe` создайте файл **`tic_tac_toe_game.dart` и полностью вставьте следующий код**:

```dart
enum Mark {
  empty,
  x,
  o,
}

class TicTacToeGame {
  final List<Mark> board = List<Mark>.filled(
    9,
    Mark.empty,
    growable: false,
  );

  Mark currentPlayer = Mark.x;

  bool makeMove(int index) {
    if (index < 0 || index >= board.length) {
      return false;
    }

    // Проверку занятой клетки добавим на этапе 5.
    board[index] = currentPlayer;
    currentPlayer = currentPlayer == Mark.x ? Mark.o : Mark.x;
    return true;
  }

  void reset() {
    board.fillRange(0, board.length, Mark.empty);
    currentPlayer = Mark.x;
  }
}
```

Отдельный фрагмент `enum` из объяснения выше повторно не вставляйте: он уже включён в полный листинг.

Это стартовая модель для сборки поля. Проверка границ уже дана готовой, а обязательную проверку занятой клетки вы добавите на этапе 5.

До этапа 5 проверяйте только нажатия **разных свободных** клеток. Промежуточная модель ещё допускает перезапись: это известная граница текущего шага, которую мы обязательно закроем.

### 2.5. Контракт `makeMove`

Метод принимает индекс и возвращает `bool`:

```dart
bool makeMove(int index)
```

Это сигнатура для чтения, а не ещё один метод, который нужно вставить в файл.

| Возвращаемое значение | Значение для экрана                               |
| --------------------- | ------------------------------------------------- |
| `true`                | Модель приняла ход и изменила позицию             |
| `false`               | Модель отклонила действие; поле и очередь прежние |

Готовая проверка границ отсекает, например, `-1` и `9`. У нашего поля есть индексы только `0`–`8`.

Запись `board[index] = currentPlayer` сохраняет **текущий** символ. Следующая строка переключает очередь для следующего допустимого действия.

Условное выражение читается так:

```text
если сейчас X → следующим будет O
иначе сейчас O → следующим будет X
```

Сначала записываем символ, затем переключаем игрока. Если поменять порядок, первый ход неожиданно окажется O.

После добавления защиты окончательный порядок будет таким:

```text
проверить индекс
→ проверить занятость
→ записать символ
→ переключить игрока
→ вернуть true
```

### 2.6. Почему файл не импортирует Flutter

В модели нет кнопок, цветов, `BuildContext` и `setState`. Она хранит данные и выполняет правила независимо от того, как нарисован экран.

Сейчас не нужно добавлять фазу победы, свойство победителя и выигрышные линии. В ПР3 расширим эту же модель, сохранив знакомые поле, `makeMove` и `reset`.

Сохраните файл. В терминале выполните:

```bash
flutter analyze
```

На экране приложения пока ничего не изменится: заглушка ещё не читает новую модель. Следующий этап свяжет их.

## 3. Вместо заглушки показываем игровое поле

### 3.1. Что изменится в устройстве экрана

Бывший `TicTacToeScreen` почти не менялся во время работы, поэтому был `StatelessWidget`.

Теперь пользователь делает ход, данные модели меняются, и экран должен снова показать поле. Для этого используем `StatefulWidget` с объектом состояния `State`.

Создадим модель как поле этого `State`:

```dart
  final TicTacToeGame _game = TicTacToeGame();
```

Эта строка будет расположена **в классе `_TicTacToeScreenState`, вне метода `build`**.

Пока открыт этот игровой маршрут, экран использует один объект `_game`. Перестроение интерфейса не должно создавать новую пустую модель.

`State` хранит ссылку на модель, а сами девять значений и очередь находятся внутри модели. Второй список клеток в `State` не нужен.

### 3.2. Полная замена экранного файла

Откройте **`lib/games/tic_tac_toe/tic_tac_toe_screen.dart` и замените его содержимое целиком** следующим кодом:

```dart
import 'package:flutter/material.dart';

import 'tic_tac_toe_game.dart';

class TicTacToeScreen extends StatefulWidget {
  const TicTacToeScreen({super.key});

  @override
  State<TicTacToeScreen> createState() => _TicTacToeScreenState();
}

class _TicTacToeScreenState extends State<TicTacToeScreen> {
  final TicTacToeGame _game = TicTacToeGame();

  String _markText(Mark mark) {
    switch (mark) {
      case Mark.empty:
        return '';
      case Mark.x:
        return 'X';
      case Mark.o:
        return 'O';
    }
  }

  void _onCellTap(int index) {
    final moved = _game.makeMove(index);
    if (!moved) {
      return;
    }

    setState(() {
      // Модель уже изменилась: показываем её новое состояние.
    });
  }

  void _resetGame() {
    _game.reset();
    setState(() {
      // Поле и очередь сброшены в модели.
    });
  }

  Widget _buildCell(int index) {
    final colors = Theme.of(context).colorScheme;
    final mark = _game.board[index];

    return Material(
      color: colors.surfaceContainerHighest,
      shape: RoundedRectangleBorder(
        borderRadius: BorderRadius.circular(16),
        side: BorderSide(color: colors.outlineVariant),
      ),
      clipBehavior: Clip.antiAlias,
      child: InkWell(
        onTap: () => _onCellTap(index),
        child: Center(
          child: Padding(
            padding: const EdgeInsets.all(12),
            child: FittedBox(
              fit: BoxFit.scaleDown,
              child: Text(
                _markText(mark),
                style: TextStyle(
                  fontSize: 48,
                  fontWeight: FontWeight.w700,
                  color: mark == Mark.o ? colors.tertiary : colors.primary,
                ),
              ),
            ),
          ),
        ),
      ),
    );
  }

  @override
  Widget build(BuildContext context) {
    final textTheme = Theme.of(context).textTheme;

    return Scaffold(
      appBar: AppBar(
        title: const Text('Крестики-нолики'),
      ),
      body: SafeArea(
        child: Center(
          child: ConstrainedBox(
            constraints: const BoxConstraints(maxWidth: 480),
            child: ListView(
              padding: const EdgeInsets.all(20),
              children: [
                Text(
                  'Два игрока на одном устройстве',
                  style: textTheme.titleMedium,
                  textAlign: TextAlign.center,
                ),
                const SizedBox(height: 12),
                Text(
                  'Поле готово к первым ходам',
                  style: textTheme.titleLarge,
                  textAlign: TextAlign.center,
                ),
                const SizedBox(height: 20),
                AspectRatio(
                  aspectRatio: 1,
                  child: GridView.builder(
                    padding: EdgeInsets.zero,
                    physics: const NeverScrollableScrollPhysics(),
                    gridDelegate:
                        const SliverGridDelegateWithFixedCrossAxisCount(
                      crossAxisCount: 3,
                      crossAxisSpacing: 10,
                      mainAxisSpacing: 10,
                    ),
                    itemCount: _game.board.length,
                    itemBuilder: (context, index) => _buildCell(index),
                  ),
                ),
                const SizedBox(height: 20),
                FilledButton.icon(
                  onPressed: _resetGame,
                  icon: const Icon(Icons.refresh),
                  label: const Text('Очистить поле'),
                ),
                const SizedBox(height: 16),
                const Text(
                  'Проверку победы и ничьей добавим в ПР3.',
                  textAlign: TextAlign.center,
                ),
                const SizedBox(height: 12),
                OutlinedButton.icon(
                  onPressed: () => Navigator.pop(context),
                  icon: const Icon(Icons.arrow_back),
                  label: const Text('В GameBox'),
```

### 3.4. Почему сетка попадает в нужную клетку

`GridView.builder` вызывает `itemBuilder` с индексом. Мы передаём его без изменений в `_buildCell(index)`.

Внутри `_buildCell` эта же величина используется дважды:

```dart
    final mark = _game.board[index];
```

```dart
        onTap: () => _onCellTap(index),
```

Первая строка читает нужный элемент. Вторая сообщает модели, какую клетку нажали.

Не подменяйте `index` постоянным `0`. Иначе нажатия разных клеток будут попадать в одно место списка.

`itemCount: _game.board.length` связывает число клеток с размером поля. При длине девять и трёх столбцах получаются три строки.

## 4. Прослеживаем ход и показываем текущего игрока

### 4.1. От нажатия до нового отображения

Нажатие не рисует X напрямую. Сначала оно передаёт действие модели:

```text
нажатие на клетку
        ↓
индекс GridView
        ↓
_onCellTap(index)
        ↓
_game.makeMove(index)
        ↓
модель проверяет правило и меняет данные
        ↓
true → setState → новое отображение
false → поле и очередь остаются прежними
```

На этом этапе готова проверка индекса. После этапа 5 той же цепочкой будет отклоняться занятая клетка.

![Модель принимает индекс клетки, меняет данные при допустимом ходе и сообщает экрану результат для обновления](/materials/mobile-lab/img/lab2/schema-01-tap-to-state.webp)

_Правило проверяет модель. Экран получает `true` или `false`; после принятого хода он просит Flutter снова показать изменённые данные._

### 4.2. Разбираем обработчик из готового экрана

Откройте метод `_onCellTap` в `tic_tac_toe_screen.dart`. Менять его сейчас не нужно.

Первая строка вызывает правило и запоминает ответ:

```dart
    final moved = _game.makeMove(index);
```

`moved` — не новый символ клетки и не номер игрока. Это только результат операции: принят ход или нет.

Следующий блок завершает обработчик при отказе:

```dart
    if (!moved) {
      return;
    }
```

`!moved` читается как «ход не принят». Тогда нам нечего заново отображать: данные модели не должны были измениться.

При успехе выполняется `setState`. Обратите внимание на две разные роли:

- `_game.makeMove(index)` уже изменил поле и очередь;
- `setState` сообщает Flutter, что нужно повторно выполнить отображение этого экрана.

Внутри `setState` оставлен короткий комментарий, объясняющий, какое состояние изменилось. Самостоятельно второй раз записывать символ или переключать игрока в этом блоке не нужно.

Если изменить модель без уведомления Flutter, данные могут стать новыми, а экран некоторое время будет показывать старую картинку.

Если вызывать `setState`, но каждый раз создавать пустую модель в `build`, экран будет честно показывать заново созданное пустое поле. Поэтому важны и место создания модели, и обновление интерфейса.

## 5. Запрещаем ход в занятую клетку

### 5.1. Какое правило отсутствует

Предположим, X уже стоит в клетке 0. Следующий игрок O нажимает ту же клетку.

Мы хотим получить такой результат:

```text
до:     клетка 0 = X, очередь O
нажали: клетку 0
после:  клетка 0 = X, очередь O
ответ:  false
```

Клетка остаётся прежней, потому что действие запрещено. Очередь тоже остаётся прежней: игрок ещё не сделал допустимый ход.

Неверно было бы сохранить X, но всё равно переключить очередь. Тогда игрок терял бы ход из-за нажатия занятой клетки.

Это правило принадлежит модели. Мы не будем обходить его отдельными условиями в каждой из девяти кнопок.

### 5.2. Две ветви одного метода

![Допустимый ход меняет клетку и очередь, а запрещённый сохраняет оба значения и возвращает false](/materials/mobile-lab/img/lab2/schema-03-valid-invalid-move.webp)

_На занятую клетку можно нажать, но это не означает допустимый ход. `false` сохраняет и поле, и текущего игрока._

### 5.3. Самостоятельно добавляем условие

Откройте `lib/games/tic_tac_toe/tic_tac_toe_game.dart`.

В методе `makeMove` найдите комментарий:

```dart
    // Проверку занятой клетки добавим на этапе 5.
```

Замените **только этот комментарий** проверкой. Она должна находиться после проверки границ и **до** строки `board[index] = currentPlayer;`.

Условие словами:

```text
если выбранная клетка не empty:
    вернуть false
иначе:
    продолжить уже написанный метод
```

Не переносите переключение игрока выше проверки. Ранний `return false` должен завершить метод до любых изменений.

**Подсказка 1:** выбранное значение читается как `board[index]`.

**Подсказка 2:** сравнение «не равно» в Dart записывается через `!=`.

**Подсказка 3:** сравниваем значение перечисления с `Mark.empty`, а не со строкой `'empty'`.

Попробуйте написать условие самостоятельно. Затем сохраните файл и выполните короткий сценарий из раздела 5.5.

### 5.4. Рабочий метод для восстановления

Если условие не получилось или появились несогласованные правки, замените **метод `makeMove` целиком** следующим вариантом:

```dart
  bool makeMove(int index) {
    if (index < 0 || index >= board.length) {
      return false;
    }

    if (board[index] != Mark.empty) {
      return false;
    }

    board[index] = currentPlayer;
    currentPlayer = currentPlayer == Mark.x ? Mark.o : Mark.x;
    return true;
  }
```

Остальные части модели — `enum`, поле, текущий игрок и `reset` — оставьте на месте. Не вставляйте второй `makeMove` рядом с первым.

Оператор `return` завершает выполнение метода. Поэтому при занятой клетке программа не доходит ни до записи символа, ни до переключения игрока.

Проверка границ стоит первой: прежде чем читать `board[index]`, нужно убедиться, что такой элемент существует.

### 5.5. Проверяем состояние руками

Перед сценарием нажмите «Очистить поле». Не начинайте с неизвестной позиции, оставшейся после прошлой проверки.

Выполняйте действия по одному и после каждого смотрите **одновременно** на поле и подпись.

| Шаг | Действие       | Содержимое важных клеток    | Текущий игрок |

| 0   | Очистить       | 0, 4, 8 пусты               | X             |
| 1   | Нажать 0       | 0 = X                       | O             |

| 4   | Нажать 8       | 0 = X, 4 = O, 8 = X         | O             |

Состояние перед запрещённым действием:

X нажимает клетку 0, где уже стоит X. После нажатия должна остаться **та же позиция** и подпись `Ход: X`.

### 5.6. Нажатие занятой клетки другим игроком

Повторите более заметный случай:

1. Очистите поле.
2. X нажимает 0: в клетке появляется X, очередь O.
3. O нажимает 0: там остаётся X, очередь остаётся O.
4. O нажимает 1: в клетке 1 появляется O, очередь X.

### 5.7. Почему мы не отключаем занятую кнопку

В `_buildCell` остаётся обычный `onTap: () => _onCellTap(index)`. Нажатие доходит до модели, и именно модель его отклоняет.

Если спрятать правило только в условие виджета, другая кнопка или будущий компьютерный соперник смогут обойти такую защиту. Основное правило должно выполняться при каждом вызове `makeMove`.

Обработчик экрана не переключает игрока самостоятельно. Ему достаточно проверить ответ модели и обновить изображение при `true`.

## Проверяем

1. После `0 → 4` показана очередь X.
2. Повторное нажатие 0 сохраняет X в клетке и очередь X.
3. Следующее нажатие 8 ставит X и передаёт очередь O.
4. После отдельной проверки `0 → 0 → 1` поле содержит X и O в разных клетках.
5. В `makeMove` проверка занятости стоит до записи символа и смены очереди.
6. В экране нет второй реализации этого правила и второй копии поля.

**Контрольная точка:** запрещённый ход не меняет никаких игровых данных. Главный контракт ПР2 выполнен.

## 6. Проверяем очистку и начало с X

### 6.1. Что должен сбросить `reset`

Откройте `reset` в модели. Он уже дан готовым, заново писать его не нужно.

```dart
  void reset() {
    board.fillRange(0, board.length, Mark.empty);
    currentPlayer = Mark.x;
  }
```

У этого действия две обязательные части:

- очистить все девять элементов;
- вернуть очередь X.

`fillRange(0, board.length, ...)` заполняет диапазон от нуля до длины списка, не включая правую границу. При длине девять меняются элементы `0`–`8`.

Если очистить клетки и забыть текущего игрока, интерфейс может показать пустое поле с очередью O. Это неправильный сброс.

Список сохраняет прежнюю длину. Мы не вызываем `clear`, потому что после этого у поля вообще не осталось бы девяти элементов, а фиксированный список не поддерживает изменение длины.

### 6.2. Как кнопка обновляет экран

В `tic_tac_toe_screen.dart` кнопка «Очистить поле» вызывает `_resetGame`.

Этот обработчик сначала обращается к `_game.reset()`, затем вызывает `setState`, чтобы очистка и новая очередь стали видны.

Очистка не открывает ещё один `TicTacToeScreen` и не создаёт новый маршрут. Вы остаётесь на том же игровом экране.

### 6.3. Проверка с неудобной исходной очередью

Важно проверить сброс именно тогда, когда перед ним ход O:

1. Нажмите «Очистить поле».
2. Нажмите клетку 0: появится X, очередь станет O.
3. Снова нажмите «Очистить поле».
4. Проверьте, что символ исчез и надпись стала `Ход: X`.
5. Нажмите клетку 8: там должен появиться X.

Если проверять только после чётного числа ходов, очередь уже будет X и забытый сброс `currentPlayer` останется незамеченным.

### 6.4. Несколько очисток подряд

Нажмите очистку ещё два раза на уже пустом поле. Ошибки быть не должно: все клетки остаются пустыми, текущий игрок X.

После этого нажмите 4, 0, 8. Появятся X, O, X, как при обычном старте.

Не используйте hot restart как замену кнопке очистки при проверке. Перезапуск приложения уничтожает текущий `State`, а нам нужно убедиться в работе метода `reset` существующей модели.

### 6.5. Когда позиция сохраняется, а когда исчезает

| Действие                         | Ожидаемое поведение                                         |
| -------------------------------- | ----------------------------------------------------------- |
| Допустимый ход                   | Добавлен символ, очередь изменена, прошлые символы остаются |
| Запрещённый ход                  | Позиция и очередь прежние                                   |
| Перестроение после `setState`    | Экран читает ту же модель                                   |
| «Очистить поле»                  | Все клетки пусты, очередь X                                 |
| Выход в GameBox и новое открытие | Новый игровой маршрут начинает с пустого поля и X           |
| Полный перезапуск приложения     | Начатая позиция не восстанавливается                        |

Позиция живёт в модели открытого игрового экрана. В этой работе мы не сохраняем её на диск и не переносим в главный экран.

## Проверяем

1. Сделайте один ход X и очистите поле, пока очередь O.
2. Убедитесь, что исчезли все символы и снова показан X.
3. Сделайте первый ход после очистки в клетку 8: должен появиться X.
4. Несколько очисток подряд не вызывают ошибку и не меняют длину поля.
5. Возврат в GameBox и новое открытие дают пустую позицию с X.

**Контрольная точка:** очистка восстанавливает всё начальное состояние, а не только картинку клеток.

### 7.2. Получаем невозможную перезапись

```text
---------
  |   |
```

## Если что-то пошло не так

Сначала определите, где нарушена цепочка: индекс → модель → ответ → обновление экрана. Не меняйте одновременно модель, навигацию и тему в надежде случайно попасть в причину.

### Диагностика по симптомам

| Симптом                                              | Возможная причина                                                       | Что проверить                                                                                            |
| ---------------------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| X/O исчезают после нажатия                           | Создаётся новая модель при каждом перестроении                          | Строка `_game = TicTacToeGame()` должна быть полем `_TicTacToeScreenState`, вне `build`.                 |
| Поле очищается при каждом `setState`                 | В `build` вызывается `reset` или создаётся список                       | Уберите сброс из отображения; `reset` вызывается только обработчиком очистки.                            |
| Всегда ставится только X                             | Нет переключения либо каждый раз создаётся модель                       | Проверьте смену `currentPlayer` в `makeMove` и единственный экземпляр `_game`.                           |
| Первый и последующие символы всегда O                | В клетке жёстко написано `'O'` или очередь присваивается константой     | Сверьте `_markText`, чтение `board[index]` и условие переключения.                                       |
| Первый ход O, потом чередование                      | Игрок переключается до записи в поле                                    | В `makeMove` сначала `board[index] = currentPlayer`, затем смена очереди.                                |
| Игрок меняется после запрещённого действия           | Проверка стоит после переключения или оно дублируется в экране          | Все изменения выполняются после ранних отказов только в модели.                                          |
| Занятая клетка перезаписывается                      | Проверка не добавлена, удалена в эксперименте или сравнивает со строкой | В модели нужен `if (board[index] != Mark.empty) return false;` до записи.                                |
| Нажатие свободной клетки ничего не делает            | Условие занятости написано наоборот                                     | Отклонять нужно значение, которое **не равно** `Mark.empty`.                                             |
| Все девять клеток меняются одновременно              | Виджеты читают одно общее значение либо модель заполняет весь список    | В клетке читается `board[index]`, при ходе меняется только `board[index]`.                               |
| Нажимаем одну клетку, меняется другая                | Индекс подменён или переставлен                                         | Передавайте один `index` из `itemBuilder` в `_buildCell`, затем в `_onCellTap`.                          |
| Нажатие всегда меняет верхнюю левую клетку           | Вместо `index` передаётся постоянный `0`                                | Сверьте `onTap: () => _onCellTap(index)` и вызов `_buildCell(index)`.                                    |
| Данные меняются, но символа сразу не видно           | После `true` не вызывается `setState`                                   | Восстановите `_onCellTap` из полного листинга; не добавляйте второй список для обхода проблемы.          |
| Подпись всегда «Ход: X»                              | В `Text` постоянная строка                                              | Используйте `_markText(_game.currentPlayer)` в интерполяции; уберите `const` у этого изменяемого `Text`. |
| После очистки очередь O                              | В `reset` очищено только поле                                           | Последняя строка метода должна возвращать `currentPlayer = Mark.x`.                                      |
| После очистки клетки исчезли или возник `RangeError` | Вместо заполнения списка изменена длина                                 | Поле содержит девять элементов; используйте `fillRange`, а не удаление клеток.                           |
| Клеток меньше девяти или появилась четвёртая строка  | Неверная длина списка или `itemCount`                                   | В `List.filled` — 9, в `itemCount` — длина поля, в `crossAxisCount` — 3.                                 |
| `GridView` вызывает ошибку неограниченной высоты     | Убрана квадратная область                                               | Восстановите `AspectRatio` вокруг сетки и внешний `ListView`.                                            |
| Нижние кнопки не помещаются                          | Страница перестала прокручиваться                                       | Верните внешний `ListView`; не уменьшайте клетки до неудобного размера.                                  |
| `tic_tac_toe_game.dart` не найден                    | Файл создан не рядом с экраном или с другим расширением                 | Должен быть путь `lib/games/tic_tac_toe/tic_tac_toe_game.dart` и локальный импорт без `../`.             |
| Пропал Back или появилась другая тема                | В игре создан второй `MaterialApp`                                      | Игровой экран возвращает `Scaffold`; общий `MaterialApp` остаётся в `app.dart`.                          |
| Возврат ведёт через несколько одинаковых меню        | Вместо `pop` открывается новый `HomeScreen`                             | Кнопка «В GameBox» вызывает `Navigator.pop(context)`.                                                    |
| После правки всё ещё видна заглушка                  | Старый процесс, другой проект или не выполнен restart                   | Сохраните файл, проверьте путь запуска, выполните hot restart или один новый запуск после `q`.           |
| Три X в строке не завершают игру                     | Это граница ПР2                                                         | Ничего не исправляйте сейчас: проверка исхода появится в ПР3.                                            |

### Как отличить ошибку данных от ошибки отображения

Возьмите один короткий сценарий вместо случайных нажатий по всему полю:

```text
Очистить → 0 → 4 → 0 → 8
```

Сравните его с таблицей раздела 5.5.

Если символ появляется в другой клетке, сначала проверьте индекс.

Если клетка перезаписалась или очередь изменилась после отказа, проверьте `makeMove`.

Если новая позиция появляется только после другого действия, проверьте уведомление через `setState`.

Если после каждого обновления всё пусто, проверьте место создания модели и отсутствие сброса в `build`.

Не выполняйте `flutter clean` первым действием. Очистка сборки не восстановит проверку занятости и не исправит неверный индекс.

### Минимальный набор для обращения за помощью

Покажите преподавателю:

- первую содержательную ошибку анализа, если она есть;

## Как восстановиться, если отстали

Сначала сохраните свои текущие файлы и выясните, какой результат уже работает. Не удаляйте весь GameBox и не начинайте новый проект.

### Выберите ближайшее состояние

| Что уже получается                             | Откуда продолжить                                           |
| ---------------------------------------------- | ----------------------------------------------------------- |
| Работает только полка и заглушки ПР1           | Создать модель по 2.4, заменить экран по 3.2                |
| Модель создана, но заглушка не изменилась      | Проверить сохранение и полную замену экранного файла по 3.2 |
| Поле показывает X/O, но нет подписи хода       | Заменить один `Text` по 4.3                                 |
| Ходы идут, но занятые клетки перезаписываются  | Восстановить `makeMove` по 5.4                              |
| Защита работает, но очистка оставляет O        | Восстановить `reset` по 6.1                                 |
| После эксперимента осталось неверное состояние | Вернуть защиту и нажать очистку по 7.3                      |

### Если модель сильно разошлась с листингом

Откройте **`lib/games/tic_tac_toe/tic_tac_toe_game.dart`**. Для восстановления итоговой модели замените файл **целиком** следующим кодом:

```dart
enum Mark {
  empty,
  x,
  o,
}

class TicTacToeGame {
  final List<Mark> board = List<Mark>.filled(
    9,
    Mark.empty,
    growable: false,
  );

  Mark currentPlayer = Mark.x;

  bool makeMove(int index) {
    if (index < 0 || index >= board.length) {
      return false;
    }

    if (board[index] != Mark.empty) {
      return false;
    }

    board[index] = currentPlayer;
    currentPlayer = currentPlayer == Mark.x ? Mark.o : Mark.x;
    return true;
  }

  void reset() {
    board.fillRange(0, board.length, Mark.empty);
    currentPlayer = Mark.x;
  }
}
```

Этот справочный листинг уже содержит защиту. Он нужен только при восстановлении; повторно переписывать исправную модель не требуется.

### Если нужно восстановить экран

1. Сохраните копию своего `tic_tac_toe_screen.dart` вне рабочей `lib`.
2. Восстановите файл целиком по полному листингу 3.2.
3. Повторите замену подписи из 4.3: стартовый листинг содержит временную фразу.
4. Убедитесь, что модель восстановлена с проверкой из 5.4 или итогового листинга выше.
5. Сохраните файлы, выполните hot restart и откройте игру с полки.
6. Проверьте `0 → 4 → 0 → 8`, затем очистку.

Не вставляйте исходную заглушку из ПР1 поверх нового игрового файла: она не читает модель и не содержит поле.

### Если преподаватель выдаёт checkpoint

Сохраните текущую работу в резервной копии или согласованной ветке. Используйте checkpoint продолжения вашего проекта, не теряя индивидуальное имя и Android ID.

Уточните его стадию: первый checkpoint ПР2 ещё может не содержать защиту занятой клетки. После него обязательно выполните этап 5 и проверьте очистку.

Персонализированный `app_theme.dart` из ПР1 не заменяйте стандартным без необходимости. Если выданы только два игровых файла, используйте их в существующем проекте.

После восстановления:

```bash
flutter analyze
```

Затем вручную повторите короткий сценарий и возврат в GameBox. Только после этого продолжайте оставшиеся шаги.

## Дополнительное задание: собственные X/O

Выполняйте после обязательной части и сохранения исправленного checkpoint. Для ПР3 это оформление не требуется.

Можно заменить буквенные X/O стандартными значками `Icons.close` и `Icons.circle_outlined`, сохранив данные модели `Mark`.

### Один готовый вариант оформления

В `tic_tac_toe_screen.dart` найдите метод `_buildCell`. В нём внутри `FittedBox` найдите **весь виджет `Text`**:

```dart
              child: Text(
                _markText(mark),
                style: TextStyle(
                  fontSize: 48,
                  fontWeight: FontWeight.w700,
                  color: mark == Mark.o ? colors.tertiary : colors.primary,
                ),
              ),
```

Замените только этот фрагмент следующим:

```dart
              child: mark == Mark.empty
                  ? const SizedBox.shrink()
                  : Icon(
                      mark == Mark.x ? Icons.close : Icons.circle_outlined,
                      size: 48,
                      color: mark == Mark.o ? colors.tertiary : colors.primary,
                    ),
```

Остальные части `Material`, `InkWell`, `Center`, `Padding` и `FittedBox` сохраните. Подпись очереди по-прежнему показывает текст X/O через `_markText`.

Можно подобрать небольшой другой размер значка, но область нажатия всей клетки должна сохраниться. Модель, индекс, `makeMove`, защита и `reset` не меняются.

Проверьте первый X, второй O, отказ при занятой клетке и очистку. На узком экране символы должны помещаться и отличаться формой.

Не добавляйте пакеты, PNG-ассеты, победу и отдельное состояние внутри значка. Если оформление мешает, верните исходный `Text` из полного листинга.

## Перед следующей работой

Посмотрите ещё раз на позицию из пяти ходов:

```text
X | X | X
---------
O | O |
---------
  |   |

Ход: O
```

Человек уже видит три X в строке. Программа пока знает только, что отдельная клетка занята или свободна, и продолжает чередование.

В ПР3 добавим определение победы, ничьей и запрет ходов после завершения. Продолжим ту же модель и тот же экран; сейчас сохраните исправленную версию ПР2 без самостоятельного добавления исходов.
