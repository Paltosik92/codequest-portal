**Дисциплина:** «Разработка мобильных приложений».
**Начало:** ваш GameBox после полностью выполненной ПР2.

На поле уже три X в строке, но GameBox всё ещё предлагает следующий ход. Для версии ПР2 это было ожидаемо: она знала свободные и занятые клетки, но не понимала исход партии.

Бит смотрит на поле: «Кажется, пора остановиться». Сегодня научим игру замечать победу и ничью, сохранять результат на экране и начинать новую партию без следов предыдущей.

Продолжаем те же крестики-нолики. Полка, общая тема, девять клеток и передача нажатия в модель уже работают — теперь добавим правила завершения.

![Бит замечает три X в верхней строке, хотя версия ПР2 всё ещё показывает очередь O](/materials/mobile-lab/img/lab3/comic-01-bit-sees-a-winner.webp)

_Позиция знакома по ПР2. Теперь она станет завершённой партией, после которой новые ходы запрещены._

## Результат занятия

После обязательной части в GameBox будет завершённая локальная игра на двух человек:

- X и O по очереди ходят в свободные клетки;
- модель распознаёт три строки, три столбца и обе диагонали;
- после выигрышного хода появляется «Победил: X» или «Победил: O»;
- полное поле без победителя даёт статус «Ничья»;
- победа на девятом ходу остаётся победой;
- после победы или ничьей модель отклоняет новые ходы;
- «Новая партия» очищает клетки, возвращает X, активное состояние и отсутствие победителя;
- результат и поле остаются видны до рестарта или выхода;
- Back возвращает к существующей полке GameBox;
- готовый файл тестов проверяет правила без ручного разыгрывания каждой позиции.

**Играют два человека на одном устройстве.** Компьютерного соперника, сложности, статистики, профиля и сохранения пока нет.

Змейка и морской бой сохраняют свои заглушки. Название, автор и акцент вашего GameBox остаются прежними.

![Завершённая партия показывает победу X, исходное поле и кнопку новой партии](/materials/mobile-lab/img/lab3/ui-01-finished-game.webp)

_Результат заменяет подпись очереди. Поле остаётся на экране, чтобы игроки могли увидеть, чем закончилась партия._

Все пути `lib/...` и `test/...` считаются от корня вашего Flutter-проекта с `pubspec.yaml`. Имя `gamebox_ivanov` ниже — пример технического имени из ПР1.

## 2. Разбираем восемь линий и состояния партии

### 2.1. Не девять отдельных условий в кнопках

Нумерация клеток остаётся прежней:

```text
0 | 1 | 2
---------
3 | 4 | 5
---------
6 | 7 | 8
```

Три символа образуют линию только в одном из восьми наборов индексов:

| Вид               | Набор индексов |
| ----------------- | -------------- |
| Верхняя строка    | `0, 1, 2`      |
| Средняя строка    | `3, 4, 5`      |
| Нижняя строка     | `6, 7, 8`      |
| Левый столбец     | `0, 3, 6`      |
| Средний столбец   | `1, 4, 7`      |
| Правый столбец    | `2, 5, 8`      |
| Главная диагональ | `0, 4, 8`      |
| Вторая диагональ  | `2, 4, 6`      |

Запишем эти данные один раз в модели. Затем один и тот же цикл проверит каждую тройку.

![Восемь выигрышных комбинаций состоят из трёх строк, трёх столбцов и двух диагоналей одного поля](/materials/mobile-lab/img/lab3/schema-01-winning-lines.webp)

_Схема показывает наборы индексов, а не восемь одновременно сыгранных партий. Для каждой тройки будем сравнивать значения из одного `board`._

### 2.2. Когда тройка считается победой

Для линии `0, 1, 2` должны одновременно выполняться три условия:

1. `board[0]` не пуст.
2. `board[0]` совпадает с `board[1]`.
3. `board[0]` совпадает с `board[2]`.

Первое условие обязательно: три пустые клетки тоже равны между собой, но победой не являются.

| Значения в тройке   | Победа? | Причина                              |
| ------------------- | ------- | ------------------------------------ |
| X, X, X             | Да      | Одинаковый непустой символ           |
| O, O, O             | Да      | Одинаковый непустой символ           |
| X, O, X             | Нет     | Символы отличаются                   |
| X, X, empty         | Нет     | Третий символ не совпадает           |
| empty, empty, empty | Нет     | Не выполнено условие непустой клетки |

Экран не будет заново обходить линии. Он прочитает уже вычисленные моделью фазу и победителя.

### 2.3. Теперь у партии есть фаза

Одного списка клеток недостаточно для удобного ответа «можно ли продолжать». Вводим простой `enum GamePhase`:

- `playing` — партия активна;
- `won` — есть победитель;
- `draw` — поле заполнено без победителя.

Отдельное поле `winner` хранит `Mark.x`, `Mark.o` либо `Mark.empty`, когда победителя нет.

`Mark.empty` в `winner` означает отсутствие победителя. Это не третий игрок.

| Фаза      | `winner`              | Что показывает экран          |
| --------- | --------------------- | ----------------------------- |
| `playing` | `Mark.empty`          | `Ход: X` или `Ход: O`         |
| `won`     | `Mark.x` или `Mark.o` | `Победил: X` или `Победил: O` |
| `draw`    | `Mark.empty`          | `Ничья`                       |

![Активная партия переходит к победе или ничьей, а reset возвращает её к пустому полю и первому ходу X](/materials/mobile-lab/img/lab3/schema-02-game-phases.webp)

_`won` и `draw` — конечные состояния текущей партии. `reset` очищает поле и победителя, возвращает X и `playing`; он работает также во время незавершённой партии._

## Проверяем

1. Назовите три индекса главной и второй диагонали.
2. Объясните, почему три `Mark.empty` не дают победу.
3. Для победы O выберите фазу `won` и победителя `Mark.o`.
4. Для ничьей выберите фазу `draw` без победителя.

**Контрольная точка:** понятны данные, которые будем добавлять. Теперь реализуем их в существующей модели.

## 3. Добавляем определение исхода в модель

### 3.1. Полный файл с проверкой победы

Откройте **`lib/games/tic_tac_toe/tic_tac_toe_game.dart` и замените содержимое целиком** следующим кодом:

```dart
enum Mark {
  empty,
  x,
  o,
}

enum GamePhase {
  playing,
  won,
  draw,
}

class TicTacToeGame {
  static const List<List<int>> _winningLines = [
    [0, 1, 2],
    [3, 4, 5],
    [6, 7, 8],
    [0, 3, 6],
    [1, 4, 7],
    [2, 5, 8],
    [0, 4, 8],
    [2, 4, 6],
  ];

  final List<Mark> board = List<Mark>.filled(
    9,
    Mark.empty,
    growable: false,
  );

  Mark currentPlayer = Mark.x;
  GamePhase phase = GamePhase.playing;
  Mark winner = Mark.empty;

  bool makeMove(int index) {
    // Блокировку завершённой партии добавим на этапе 5.
    if (index < 0 || index >= board.length) {
      return false;
    }
    if (board[index] != Mark.empty) {
      return false;
    }

    board[index] = currentPlayer;
    winner = _findWinner();
    if (winner != Mark.empty) {
      phase = GamePhase.won;
      return true;
    }

    // Ветвь ничьей добавим в разделе 3.3.

    currentPlayer = currentPlayer == Mark.x ? Mark.o : Mark.x;
    return true;
  }

  Mark _findWinner() {
    for (final line in _winningLines) {
      final first = board[line[0]];
      if (first != Mark.empty &&
          first == board[line[1]] &&
          first == board[line[2]]) {
        return first;
      }
    }
    return Mark.empty;
  }

  void reset() {
    board.fillRange(0, board.length, Mark.empty);
    currentPlayer = Mark.x;
    phase = GamePhase.playing;
    winner = Mark.empty;
  }
}
```

Стартовый файл компилируется, сохраняет проверки ПР2 и определяет победу. Две отмеченные части — ничью и запрет хода после завершения — подключим в указанных этапах.

Пока не проверяйте продолжение после победы как готовое поведение. Это промежуточное состояние работы, которое будет закрыто до сдачи.

### 3.2. Как один цикл проверяет все линии

Рассмотрим первую тройку `[0, 1, 2]`.

- `line[0]` — индекс первой клетки этой тройки, то есть 0.
- `board[line[0]]` — символ из клетки 0.
- `board[line[1]]` и `board[line[2]]` — символы из клеток 1 и 2.

На следующем повторении `line` станет `[3, 4, 5]`, и тот же код сравнит среднюю строку. Сравнение не привязано к конкретной кнопке.

`_findWinner` возвращает найденный непустой символ. Если ни одна тройка не подошла, возвращается `Mark.empty`.

Метод только читает поле. Он не меняет очередь, не открывает диалог и не вызывает `setState`.

### 3.3. Самостоятельная часть: ничья

Ничья возникает, когда **победитель не найден и свободных клеток больше нет**.

Первая часть уже обеспечена порядком кода: при найденной победе метод завершается раньше через `return true`.

Осталось проверить отсутствие `Mark.empty` в `board`.

В `makeMove` замените комментарий `// Ветвь ничьей добавим в разделе 3.3.` условием, которое:

1. Проверяет, что поле не содержит пустой клетки.
2. Устанавливает `phase = GamePhase.draw`.
3. Возвращает `true`, потому что последний ход был принят.

**Подсказка:** `board.contains(Mark.empty)` отвечает, есть ли пустая клетка. Перед выражением можно поставить `!`, чтобы получить «пустых клеток нет».

Попробуйте написать ветвь самостоятельно. Если нужна помощь, замените указанный комментарий готовым блоком:

```dart
    if (!board.contains(Mark.empty)) {
      phase = GamePhase.draw;
      return true;
    }
```

Блок должен стоять **после проверки победы и до переключения игрока**.

Победный ход и последний ход ничьей возвращают `true`: они действительно изменили поле. `false` нужен для отклонённого действия, а не для сообщения «игра закончилась».

### 3.4. Почему порядок имеет значение

На девятом ходу может одновременно заполниться последняя клетка и появиться выигрышная линия. Если сначала проверить заполненность, программа ошибочно объявит ничью.

Нужный порядок после записи символа:

```text
победа есть? → won → закончить обработку
иначе поле полно? → draw → закончить обработку
иначе переключить игрока
```

![После допустимого хода сначала проверяется победа, затем ничья, а очередь меняется только при продолжении партии](/materials/mobile-lab/img/lab3/schema-03-move-result-order.webp)

_На схеме `draw?` означает «поле полно, а победа уже исключена». Девятый выигрышный ход заканчивается на ветви `won` и не доходит до ничьей._

При завершении `currentPlayer` остаётся символом последнего сделанного хода. В фазах `won` и `draw` это уже не приглашение следующему игроку — экран будет показывать результат вместо очереди.

## 4. Показываем результат и запускаем первые тесты

### 4.1. Добавляем одну подпись для трёх фаз

Откройте **`lib/games/tic_tac_toe/tic_tac_toe_screen.dart`**.

Внутри `_TicTacToeScreenState` найдите объявление `void _onCellTap(int index)`. **Непосредственно перед этим методом**, после закрывающей скобки `_markText`, вставьте следующий getter целиком:

```dart
  String get _statusText {
    switch (_game.phase) {
      case GamePhase.playing:
        return 'Ход: ${_markText(_game.currentPlayer)}';
      case GamePhase.won:
        return 'Победил: ${_markText(_game.winner)}';
      case GamePhase.draw:
        return 'Ничья';
    }
  }
```

Getter читается как свойство `_statusText`. Он выбирает текст по уже известной фазе, а не ищет выигрышные линии повторно.

В `build` найдите виджет подписи очереди из конца ПР2:

```dart
                Text(
                  'Ход: ${_markText(_game.currentPlayer)}',
                  style: textTheme.headlineMedium,
                  textAlign: TextAlign.center,
                ),
```

Замените **весь этот `Text`** следующим:

```dart
                Text(
                  _statusText,
                  style: textTheme.headlineMedium,
                  textAlign: TextAlign.center,
                ),
```

`_game`, `_markText`, `_onCellTap`, `_resetGame` и сетка остаются прежними. Не создавайте второго объекта модели для результата.

Теперь `reset` очищает и фазу, и победителя, поэтому название соответствует смыслу действия.

Найдите старое предупреждение:

Замените **этот виджет целиком**:

Нужны только `test` и `expect`; большого отдельного курса тестирования сейчас нет.

Создайте файл **`test/tic_tac_toe_game_test.dart` и полностью вставьте следующий код**:

```dart

import 'package:gamebox_ivanov/games/tic_tac_toe/tic_tac_toe_game.dart';

TicTacToeGame playMoves(List<int> moves) {
  final game = TicTacToeGame();
  for (final index in moves) {
    expect(game.makeMove(index), isTrue, reason: 'Ход в клетку $index');
  }

void main() {
  test('Пустое поле активно и не имеет победителя', () {
    final game = TicTacToeGame();

    'главная диагональ': [0, 1, 4, 2, 8],

      final game = playMoves(entry.value);
      expect(game.phase, GamePhase.won);
      expect(game.winner, Mark.x);

  }

  test('Победа O', () {

    expect(game.phase, GamePhase.won);
    expect(game.winner, Mark.o);
  });

  test('Полное поле без линии даёт ничью', () {
```

## 5. Закрываем ходы после финиша и проверяем reset

### 5.1. Самостоятельная часть: защита активной фазы

Возможность поставить символ зависит не только от свободной клетки. Партия должна оставаться активной.

Откройте `lib/games/tic_tac_toe/tic_tac_toe_game.dart`. В начале `makeMove` найдите комментарий:

```dart
    // Блокировку завершённой партии добавим на этапе 5.
```

Замените **только этот комментарий** условием, которое возвращает `false`, если `phase` не равна `GamePhase.playing`.

**Подсказка:** используйте тот же ранний отказ, что и для занятой клетки. Проверка стоит до чтения и изменения `board`.

Если нужна помощь, вставьте вместо комментария готовый блок:

```dart
    if (phase != GamePhase.playing) {
      return false;
    }
```

Теперь начало метода проверяет три ограничения:

```text
партия активна?
→ индекс существует?
→ клетка свободна?
→ только теперь записать символ
```

При отказе поле, очередь, фаза и победитель должны остаться прежними. Нельзя сначала поставить символ, а затем обнаружить, что ход запрещён.

### 5.2. Почему проверка находится в модели

В экранном `_buildCell` сохраните `onTap: () => _onCellTap(index)`. Не добавляйте туда единственную защиту через отключение клеток.

Нажатие доходит до `makeMove`, модель отвечает `false`, а обработчик не вызывает обновление для неизменившихся данных.

Так правило действует и при ошибке интерфейса, и при прямом вызове из теста. Внешний вид кнопки не должен определять, разрешено ли изменить игровое состояние.

Сохраните модель. Начните новую партию, выполните `0 → 3 → 1 → 4 → 2` и попробуйте нажать свободную клетку 8.

В клетке 8 ничего не появится, результат останется `Победил: X`.

### 5.3. Полный рестарт — четыре части состояния

В модели уже подготовлен расширенный `reset`. Сравните его со своим файлом:

```dart
  void reset() {
    board.fillRange(0, board.length, Mark.empty);
    currentPlayer = Mark.x;
    phase = GamePhase.playing;
    winner = Mark.empty;
  }
```

При необходимости замените **метод `reset` целиком** этим вариантом.

| Что сбрасывается | Значение после новой партии | Что случится, если забыть                   |
| ---------------- | --------------------------- | ------------------------------------------- |
| Девять клеток    | `Mark.empty`                | На новом поле останутся старые символы      |
| Текущий игрок    | `Mark.x`                    | Первым может неожиданно оказаться O         |
| Фаза             | `GamePhase.playing`         | Пустое поле не примет ход                   |
| Победитель       | `Mark.empty`                | В модели останется результат прошлой партии |

Не вызывайте `reset` из `build`: иначе партия будет очищаться при каждом перестроении.

Кнопка по-прежнему вызывает существующий `_resetGame`, а он — `_game.reset()` и затем `setState`. Новый экран и новый маршрут для рестарта не создаются.

### 5.4. Добавляем проверки защиты и полного сброса

Откройте **`test/tic_tac_toe_game_test.dart`**.

Найдите последний тест `'Запрет занятой клетки из ПР2 сохранён'`. **После его закрывающего `});`, но перед последней `}` функции `main`**, вставьте следующий блок целиком:

```dart
  test('После победы нельзя изменить свободную клетку', () {
    final game = playMoves([0, 3, 1, 4, 2]);
    final before = List<Mark>.of(game.board);
    final playerBefore = game.currentPlayer;

    expect(game.makeMove(8), isFalse);
    expect(game.board, before);
    expect(game.currentPlayer, playerBefore);
    expect(game.phase, GamePhase.won);
    expect(game.winner, Mark.x);
  });

  test('После ничьей состояние остаётся прежним', () {
    final game = playMoves([0, 1, 2, 4, 3, 5, 7, 6, 8]);
    final before = List<Mark>.of(game.board);
    final playerBefore = game.currentPlayer;

    expect(game.makeMove(0), isFalse);
    expect(game.board, before);
    expect(game.currentPlayer, playerBefore);
    expect(game.phase, GamePhase.draw);
    expect(game.winner, Mark.empty);
  });

  test('Reset полностью восстанавливает игру после обоих исходов', () {
    const finishedGames = [
      [0, 3, 1, 4, 2],
      [0, 1, 2, 4, 3, 5, 7, 6, 8],
    ];

    for (final moves in finishedGames) {
      final game = playMoves(moves);
      expect(game.phase, isNot(GamePhase.playing));
      game.reset();

      expect(game.board, List<Mark>.filled(9, Mark.empty));
      expect(game.currentPlayer, Mark.x);
      expect(game.phase, GamePhase.playing);
      expect(game.winner, Mark.empty);
      expect(game.makeMove(4), isTrue);
      expect(game.board[4], Mark.x);

      game.reset();
      expect(game.currentPlayer, Mark.x);
      expect(game.phase, GamePhase.playing);
      expect(game.winner, Mark.empty);
    }
  });
```

`List<Mark>.of(game.board)` сохраняет копию значений до запрещённого действия. Если написать только `final before = game.board`, обе переменные будут ссылаться на один изменяемый список и такая проверка не заметит его повреждение.

Выполните:

```bash

```

Все проверки должны пройти. Тест со свободной клеткой 8 особенно важен: простого запрета занятой клетки для него недостаточно.

После ничьей свободных клеток уже нет, но запрет активной фазы всё равно остаётся общим правилом для обоих конечных состояний.

## Проверяем

1. После победы X нажатие свободной клетки 8 отклоняется.
2. Поле, очередь, фаза и победитель не меняются после отказа.
3. «Новая партия» даёт девять пустых клеток и подпись `Ход: X`.
4. После рестарта можно сразу сделать ход в центр.
5. В тестах проверяется полный сброс и после победы, и после ничьей.

**Контрольная точка:** правила завершения защищены моделью, рестарт возвращает всё исходное состояние.

## 8. Дополняем тест и проверяем приложение целиком

### 8.1. Самостоятельный сценарий второй диагонали

## Если что-то пошло не так

Проверяйте сначала модель, затем соответствие текста её фазе. Исправление одной надписи не устраняет ошибку определения исхода.

| Симптом                                          | Возможная причина                                       | Что проверить                                                                   |
| ------------------------------------------------ | ------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Пустое поле объявлено победой                    | Проверяются только равные значения                      | В `_findWinner` нужно `first != Mark.empty`.                                    |
| Работает только одна строка                      | Неполная таблица или цикл завершён слишком рано         | Сверьте восемь троек; `return Mark.empty` должен стоять после цикла.            |
| Строки работают, диагональ нет                   | Неверные индексы                                        | Диагонали — `0,4,8` и `2,4,6`; проверьте обе тестами.                           |
| Побеждать умеет только X                         | В проверке жёстко указан `Mark.x`                       | Возвращайте общий непустой `first`; отдельно запустите тест O.                  |
| Победа девятым ходом превращается в ничью        | Заполненность проверяется раньше победы                 | Перенесите ветвь ничьей после победы с ранним выходом.                          |
| Полное поле остаётся активным                    | Не добавлена ветвь ничьей или условие написано наоборот | Ничья проверяется через `!board.contains(Mark.empty)` после исключения победы.  |

### Как читать конкретное расхождение теста

Например, тест девятого хода сообщает, что ожидал `GamePhase.won`, а получил `GamePhase.draw`.

Последовательность дошла до девятого хода, значит, проблема не в маршруте GameBox. Проверьте порядок двух ветвей после записи символа.

Если тест после победы ожидал `false`, а получил `true`, проверьте ранний отказ по фазе. Не исправляйте это добавлением условия только в `_onCellTap`.

Если тесты модели проходят, но текст результата неверен, проверьте `_statusText` и обновление через `setState`.

Не выполняйте очистку всей сборки первым действием: она не исправляет ошибочный порядок правил.

### Итоговый метод `makeMove` для восстановления

Если порядок ветвей потерян, замените **только метод `makeMove` целиком** следующим окончательным вариантом:

```dart
  bool makeMove(int index) {
    if (phase != GamePhase.playing) {
      return false;
    }
    if (index < 0 || index >= board.length) {
      return false;
    }
    if (board[index] != Mark.empty) {
      return false;
    }

    board[index] = currentPlayer;
    winner = _findWinner();
    if (winner != Mark.empty) {
      phase = GamePhase.won;
      return true;
    }

    if (!board.contains(Mark.empty)) {
      phase = GamePhase.draw;
      return true;
    }

    currentPlayer = currentPlayer == Mark.x ? Mark.o : Mark.x;
    return true;
  }
```

Остальные части модели берутся из полного листинга 3.1; `reset` сверяется с 5.3. Не оставляйте второй метод с тем же именем.

## Дополнительное задание: подсветка выигрышных клеток

Выполняйте только после обязательной части. Для ПР4 подсветка не требуется.

Добавим основание результата: модель запомнит индексы найденной линии, а экран выделит только эти клетки. Повторно вычислять победителя в UI нельзя.

В `tic_tac_toe_game.dart` **после** объявления `Mark winner = Mark.empty;` вставьте:

```dart
  List<int> winningLine = const [];
```

Замените **метод `_findWinner` целиком** следующим вариантом:

```dart
  Mark _findWinner() {
    for (final line in _winningLines) {
      final first = board[line[0]];
      if (first != Mark.empty &&
          first == board[line[1]] &&
          first == board[line[2]]) {
        winningLine = line;
        return first;
      }
    }
    return Mark.empty;
  }
```

В `reset`, **после** строки `winner = Mark.empty;`, вставьте:

```dart
    winningLine = const [];
```

В `tic_tac_toe_screen.dart`, в методе `_buildCell`, замените строку `color: colors.surfaceContainerHighest,` у `Material` следующим параметром:

```dart
      color: _game.winningLine.contains(index)
          ? colors.primaryContainer
          : colors.surfaceContainerHighest,
```

`makeMove`, размеры клеток, `onTap` и маршруты остаются прежними. Экран использует готовые индексы, а не обходит выигрышные комбинации.

Проверьте победу строкой и диагональю: выделены три нужные клетки. После новой партии выделение должно исчезнуть; при ничьей линия отсутствует.

Затем выполните анализ и тесты. Если времени не хватает, сохраните базовую версию без расширения — она полностью соответствует обязательному результату.

## Перед следующей работой

Теперь GameBox умеет провести локальную партию от первого X до победы или ничьей. После исхода правила защищают поле, а новая партия полностью возвращает начальное состояние.
